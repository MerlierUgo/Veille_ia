## Résumé

Deep search agents address complex information needs through iterative retrieval and reasoning, where the relevance of retrieved evidence influences downstream performance. Existing rerankers improve retrieval effectiveness but introduce substantial latency and cost when invoked throughout the search trajectory. We introduce SOARS, a training-free framework leveraging a System One model for fast, calibrated relevance estimation. At each search step, SOARS selects query-relevant passages from long documents and reranks candidates in a single call, jointly considering the original question and agent-generated sub-query. Across six LLM backbones on BrowseComp-Plus and WebShaper, SOARS consistently improves answer accuracy and evidence recall while reducing search calls, end-to-end latency, and inference cost. On BrowseComp-Plus, it improves GPT-5.4 Mini's accuracy from 73.9% to 84.7% while reducing search calls from 23 to 14, demonstrating the potential of System One reranking for more effective and efficient deep search.

## SOARS: System One Assisted Reranking for Agentic Search

Deep search agents address complex information needs through iterative retrieval and reasoning, where the relevance of retrieved evidence influences downstream performance. Existing rerankers improve retrieval effectiveness but introduce substantial latency and cost when invoked throughout the search trajectory. We introduce SOARS, a training-free framework leveraging a System One model for fast, calibrated relevance estimation. At each search step, SOARS selects query-relevant passages from long documents and reranks candidates in a single call, jointly considering the original question and agent-generated sub-query. On BrowseComp-Plus, it improves GPT-5.4 Mini’s accuracy from 73.9% to 84.7% while reducing search calls from 23 to 14, demonstrating the potential of System One reranking for more effective and efficient deep search.


### 1. Introduction

> Figure 1. Effect of SOARS on accuracy and search calls of deep search agents across various LLMs on BrowseComp-Plus ( Chen et al., 2026b ) .

Deep search agents leverage Large Language Models (LLMs) to address complex information needs through iterative rounds of searching, reading, and reasoning, deciding what to retrieve and read next based on the evidence collected throughout the search process ( Yao et al., 2023 ; Hsu et al., 2026 ; Huang et al., 2025 ; Zhang et al., 2024a ) . This paradigm supports reasoning-intensive tasks whose answers are not contained in any single document but must be assembled from evidence distributed across multiple documents ( Chen et al., 2026b ) . Given the limited interaction budgets of deep search agents, a central challenge in Web search is enabling these agents to surface the most relevant evidence effectively and efficiently.

To provide deep search agents with relevant corpus evidence, prior work has explored several directions. Some approaches improve first-stage retrieval by training dense retrievers for agent-generated sub-queries ( Chen et al., 2026a ) or adapting lexical retrieval to long documents ( Hsu et al., 2026 ) . Another approach warm-starts the agent by decomposing the question and reranking results from complementary searches to construct an initial evidence context to guide iterative search and reasoning ( Rad et al., 2026 ) . Retrieval-aware agent control has also been explored to mitigate reasoning stagnation and reduce redundant searches by monitoring information coverage and search novelty ( Soudani et al., 2026 ) . However, these approaches focus on retrieval, initialization, or trajectory control rather than reranking evidence throughout the search process.

Reranking first-stage retrieval candidates is a common approach to improving retrieval effectiveness, typically using cross-encoders ( Nogueira and Cho, 2019 ; Nogueira et al., 2020 ) or LLM-based rerankers that assess relevance through prompting or reasoning ( Sun et al., 2023 ; Pradeep et al., 2023b ; Zhuang et al., 2026 ; Pradeep et al., 2023a ) . Recent studies have extended reranking to deep search agents ( Meng et al., 2026 ; Sharifymoghaddam and Lin, 2026 ) , demonstrating improvements in retrieval effectiveness and answer accuracy. Within a deep search agent, however, reranking is not a one-time operation but is often invoked at every search call along the trajectory, adding latency without substantially reducing the number of searches. Moreover, existing approaches typically rank candidates solely based on agent-generated sub-queries, overlooking the original question’s global information need, and rely on initial document tokens that may omit relevant evidence. Consequently, they improve retrieval effectiveness at the expense of efficiency, without substantially reducing the agent’s search effort.

Emerging System One models offer a promising direction for jointly improving retrieval effectiveness and efficiency. Unlike generative LLMs, these models produce structured, calibrated decisions in a single forward pass, enabling fast and cost-efficient inference ( dos Santos Barbosa, 2026 ; Deußer et al., 2026 ) . Recent work by Li et al. (2026) demonstrates that Jev, a System One model, achieves relevance judgments comparable to frontier models at substantially lower latency and cost. These capabilities are particularly valuable for deep search agents, where retrieval and reranking occur repeatedly. By prioritizing relevant evidence at each search step, System One reranking can expose agents to more useful information, potentially reducing search calls, agent reasoning overhead, and cost. However, adapting these models to deep search requires addressing long documents and the interplay between the global information need of the original question and the local information need of agent-generated sub-queries.

To this end, the main objective of this paper is to investigate how lightweight, repeated System One reranking improves the effectiveness and efficiency of deep search agents. Specifically, we address three research questions (RQs). (RQ1) How can System One models be adapted as in-loop rerankers in the context of deep search agents to improve retrieval effectiveness? (RQ2) How does System One reranking affect the agent’s downstream answer accuracy and evidence recall? (RQ3) What is its impact on overall agent efficiency in terms of latency and cost?

To investigate these questions, we introduce SOARS ( S ystem O ne A ssisted R eranking for Agentic S earch), a training-free framework that integrates System One reranking into deep search agents. SOARS represents long documents using query-relevant passages and reranks candidates in a single call, considering both the original question and the agent-generated sub-query. We evaluate SOARS on two deep search benchmarks, BrowseComp-Plus ( Chen et al., 2026b ) and WebShaper ( Tao et al., 2026 ) , across six LLMs of varying families and sizes. Our results show that SOARS achieves retrieval effectiveness comparable to strong LLM-based rerankers while operating one to two orders of magnitude faster. At the agent level, SOARS prioritizes relevant evidence for subsequent reasoning, improving answer accuracy and reducing search calls across all backbones (Figure 1 ). Notably, GPT-5.4 Mini’s accuracy rises from 73.9% to 84.7% while search calls drop from 23 to 14. These improvements also translate into lower latency and cost, demonstrating how efficient, repeated reranking can improve the overall search trajectory.


### 2. Proposed Approach

Problem Formulation. Given a complex question $Q$ with supporting evidence distributed across corpus $\mathcal{D}$ , a deep search agent produces an answer by iteratively searching, reading, and reasoning over retrieved evidence. The agent is driven by a large language model $\mathcal{S}_{\theta}$ acting through a policy $\pi_{\theta}$ in a ReAct -style loop ( Yao et al., 2023 ) . At each turn $t$ , it emits a reasoning trace $\tau_{t}$ , selects an action $a_{t}$ , and receives an observation $o_{t}$ , forming the interaction trajectory as shown below:

[Tableau] (1) $$H_{T}=(\tau_{1},a_{1},o_{1},\dots,\tau_{T},a_{T},o_{T}),\qquad(\tau_{t},a_{t})\sim\pi_{\theta}(\cdot\mid H_{t-1}).$$

A search action issues a sub-query $q_{t}$ to a retriever, which returns the list $L_{q_{t}}$ of documents retrieved for $q_{t}$ . The agent operates under a limited interaction budget, so the order in which retrieved evidence is presented, and the form in which each document is exposed, determine what the agent ever reads and reasons over. Reranking $L_{q_{t}}$ can reshape this evidence, but since it is repeated at every search call along the trajectory, it must be not only effective but also efficient to be practical. This work introduces SOARS, a training-free reranker that reranks the candidates returned by every in-loop search before they reach the agent.

Deep Search Agent. The agent interacts with the corpus through issuing searches, previewing the returned results, and reading documents in full ( Hsu et al., 2026 ) . At each turn $t$ , when the agent selects a search action with sub-query $q_{t}$ , a first-stage retriever $\mathcal{R}$ surfaces documents from $\mathcal{D}$ and returns a ranked list as below:

[Tableau] (2) $$L_{q_{t}}=\mathcal{R}(q_{t},\mathcal{D}).$$

The agent then previews and reads from $L_{q_{t}}$ to gather evidence for $Q$ . Because the agent inspects only the top of this list, the documents placed near its top determine what evidence enters the trajectory. Our objective is to rerank $L_{q_{t}}$ at each search efficiently in a way that the agent is exposed to more relevant documents.

System One Reranking. SOARS reranks the top $k$ documents of $L_{q_{t}}$ by preparing a query and a compact representation for each document and scoring them with a System One model. This would let more candidates fit within the model’s context, so a large pool is reranked in a single call.

Since an agent-generated sub-query $q_{t}$ captures a local information need, matching it alone may overlook constraints in the original question $Q$ . We therefore score documents against the composed query $\tilde{q}_{t}=Q\oplus q_{t}$ , accounting for both local relevance and global constraints. To accommodate the System One model’s bounded input and enable deeper reranking, we represent each document $d$ using a query-relevant passage of $m$ tokens. Rather than selecting the leading tokens, which may miss evidence deeper in the document, we select the span $w$ of $m$ tokens starting at the earliest occurrence of a non-stopword term from the agent-generated sub-query $q_{t}$ . We use $q_{t}$ alone for passage selection to focus on the agent’s immediate information need, while retaining $Q$ during reranking to account for relevance to the global information need. We then prepend the document title, yielding $\hat{d}=\mathrm{title}(d)\oplus w$ . This compact representation prioritizes relevant evidence while allowing more candidates to fit within the model’s input budget.

Let $\mathcal{J}$ denote the System One reranker. We provide the top $k$ documents from $L_{q_{t}}$ in a single inference call to $\mathcal{J}$ , which scores each query-document pair pointwise. It grades each candidate on an ordinal relevance scale of four levels, $\mathit{rel}\in\{0,1,2,3\}$ , corresponding to off-topic , on a related topic , partly supplies , and fully supplies the information needed to answer the query. Rather than committing to a single level, $\mathcal{J}$ returns a calibrated distribution $\mathbf{p}^{d}$ over the four levels for each document $d$ , conditioned on the composed query $\tilde{q}_{t}$ and its passage $\hat{d}$ . The probability assigned to each relevance level is defined as:

[Tableau] (3) $$p^{d}(\mathit{rel})=\Pr\nolimits_{\mathcal{J}}\!\left(\mathit{rel}\mid\tilde{q}_{t},\hat{d}\right),$$

where $\Pr\nolimits_{\mathcal{J}}$ denotes $\mathcal{J}$ ’s calibrated probability and $\sum_{\mathit{rel}=0}^{3}p^{d}(\mathit{rel})=1$ . We score each document by the expected relevance level under this distribution:

[Tableau] (4) $$s(d)=\mathbb{E}_{\mathit{rel}\sim\mathbf{p}^{d}}\!\left[\mathit{rel}\right]=\sum_{\mathit{rel}=0}^{3}\mathit{rel}\cdot p^{d}(\mathit{rel}).$$

We then reorder the top $k$ documents in descending order of $s(d)$ . Using the full distribution rather than the most likely level provides a graded ranking signal, while single-call scoring keeps the per-search overhead low.


### 3. Experiments


#### 3.1. Setup


##### 3.1.1. Datasets

We evaluate SOARS on two benchmarks designed to assess deep search agents on complex, reasoning-intensive questions. BrowseComp-Plus ( Chen et al., 2026b ) contains 830 complex questions and approximately 100K documents, with human-verified judgments distinguishing evidence documents needed to answer a question from gold documents that also contain the answer. WebShaper ( Tao et al., 2026 ) provides only gold documents. We randomly sample 200 questions and search the approximately 1M-document corpus released by ( Chen et al., 2026a ) .


##### 3.1.2. Reranker Baselines

We compare SOARS against monoT5 ( Nogueira et al., 2020 ) and gpt-oss-120b with medium reasoning ( OpenAI, 2025 ) , following their use in prior deep search agent work ( Meng et al., 2026 ; Sharifymoghaddam and Lin, 2026 ) . We also include RankGPT ( Sun et al., 2023 ) with GPT-4.1 as its backbone, Qwen3-Reranker-4B ( Zhang et al., 2025 ) , and GTE-ModernBERT ( Zhang et al., 2024b ) . We run the latter two rerankers, along with monoT5, on a single NVIDIA A10 GPU.


##### 3.1.3. Evaluation Metrics

We organize our metrics around the three research questions. For retrieval effectiveness (RQ1), we measure the recall of the reranked list that each search exposes to the agent. For agent effectiveness (RQ2), following prior work ( Chen et al., 2026b ; Chen et al., 2026a ; Hsu et al., 2026 ; Sharifymoghaddam and Lin, 2026 ) , we measure end-to-end Accuracy and Calibration Error with GPT-4.1 as the judge, and we trace gold/evidence through the trajectory with three recalls ( Hsu et al., 2026 ) . Specifically, surfaced recall is computed over the documents returned by the agent’s searches, previewed recall over those whose snippets the agent inspects, and behavior recall over those it opens or cites in its answer. For agent efficiency (RQ3), we report average search calls, per-query latency, and total cost. We calculate costs using submission-time API rates per million input, output, and cache-read tokens.


##### 3.1.4. Implementation Details

We integrate SOARS inside the Pi-Serini agent framework ( Hsu et al., 2026 ) and study six LLM backbones of different families and sizes, namely GPT-5.5, GPT-5.4 Mini, Claude Opus 4.7, Claude Haiku 4.5, Gemini 2.5 Pro, and Gemini 2.5 Flash. Each backbone runs at medium reasoning effort under a 300-second per-query budget. Following ( Hsu et al., 2026 ) , we use BM25 ( $k_{1}=25$ , $b=1$ ) as the first-stage retriever. For System One reranking, we employ Jev ( TypeSafe AI, 2026 ) , reranking the top $k=100$ BM25 candidates at each search using document titles and query-relevant passages of $m=128$ tokens. Jev costs $0.042 per million input tokens, with free output ( TypeSafe AI, 2026 ) . For the vanilla baseline without SOARS, we reuse Pi-Serini’s released trajectories for GPT-5.5, Opus 4.7, and Haiku 4.5 to evaluate answer accuracy using GPT-4.1 as the judge, while running the remaining backbones under identical settings.

#### 3.2. Results and Findings


##### 3.2.1. RQ1: Retrieval Effectiveness

We investigate how System One models can be adapted for in-loop reranking and compare their effectiveness against existing rerankers. We randomly select 50 BrowseComp-Plus questions comprising 1,044 sub-queries generated by GPT-5.4 Mini and their BM25 candidates. For each sub-query, SOARS and all baselines rerank the top 100 BM25-retrieved documents. We examine two query representations to assess global and local information needs in agentic search. The first uses the agent-generated sub-query to capture the immediate retrieval objective, while the second combines it with the original question to preserve broader context and constraints. We also compare two document representations, using either the leading tokens ( Lead ) or a passage starting at the earliest occurrence of a non-stopword sub-query term ( Overlap ), capturing evidence deeper in documents. These comparisons assess how query context and passage selection affect reranking effectiveness. Table 1 reports macro-averaged Recall@5, Recall@10, and reranking latency at the question level. The oracle prioritizes ground-truth gold or evidence documents within each BM25 candidate pool, establishing an upper bound on recall.

Both query and document representations influence retrieval effectiveness. Combining the original question with agent-generated sub-query improves recall for most rerankers, while Overlap generally outperforms Lead . Under the combined setting, SOARS achieves the highest recall across all four metrics, reaching 47.2% gold and 44.4% evidence Recall@10. These results approach the oracle upper bound, demonstrating that System One reranking can be highly effective when jointly considering global and local information needs through focused document passages.

Beyond retrieval effectiveness, SOARS offers a substantial latency advantage. Although GTE-ModernBERT and monoT5 offer low per-query latency, SOARS achieves substantially higher recall with even lower latency. More notably, using overlap-selected passages and the original question combined with the sub-query, SOARS consistently outperforms RankGPT, the strongest LLM-based reranker, while requiring only 254 ms per query compared to 8.7 seconds. This combination of strong retrieval effectiveness and low latency makes System One reranking particularly suitable for repeated invocation throughout the agent’s search trajectory.


##### 3.2.2. RQ2: Agent Effectiveness

We assess how integrating System One reranking into deep search agents affects end-to-end answer accuracy and evidence recall across two benchmarks.

BrowseComp-Plus. SOARS significantly improves answer accuracy across all LLMs, with relative gains ranging from 10.2% for GPT-5.5 to 63.8% for Gemini 2.5 Pro. These improvements are particularly pronounced for weaker agents, narrowing the performance gap with stronger backbones. Calibration error also consistently decreases, indicating more reliable confidence estimates. More importantly, the evidence recall analysis reveals where these gains originate. Despite using the same first-stage retriever and achieving similar surfaced gold recall, SOARS significantly improves previewed and behavior recall across all LLMs. For GPT-5.5, previewed gold recall increases from 72.9 to 88.7, while behavior gold recall rises from 56.1 to 79.0.

These findings suggest that SOARS improves answer accuracy by promoting already-retrieved evidence into the documents agents preview, read, and cite. Furthermore, the average number of documents read increases significantly across all LLMs. As agents preview short document excerpts before selectively opening promising ones for full-text reading, this suggests that SOARS helps identify more useful evidence for deeper inspection. Notably, these gains are accompanied by fewer search calls (Figure 1 ), suggesting that better evidence prioritization reduces the need for additional retrieval.

WebShaper. The same pattern generalizes to WebShaper, where previewed and behavior recall increase significantly for every backbone, with significant accuracy improvements for most. The number of documents read also increases significantly across all backbones, suggesting more promising evidence is selected for deeper inspection. These findings confirm that SOARS consistently improves evidence utilization throughout the search trajectory, contributing to higher answer accuracy.


##### 3.2.3. RQ3: Agent Efficiency

We evaluate the efficiency of per-step System One reranking across three dimensions, namely the number of search calls, per-query latency, and cost. We report results on BrowseComp-Plus, with broadly similar trends observed on WebShaper.

Search calls. SOARS reduces search calls across all LLMs (Figure 1 ), especially for search-intensive agents, from 23 to 14 for GPT-5.4 Mini and 32 to 21 for Haiku 4.5. By promoting relevant documents to the top of the ranked list, SOARS helps agents identify and utilize useful evidence earlier in the search trajectory, reducing the need for subsequent searches.

Latency. Despite adding a reranking call per search, SOARS reduces per-query latency for nearly all backbones (Figure 2 a), from 113 to 84 seconds for GPT-5.4 Mini and 100 to 73 seconds for Opus 4.7. Fewer search calls offset the reranker’s modest overhead, yielding a net latency reduction. These findings demonstrate that lightweight reranking can accelerate the overall search process by reducing the time spent on repeated search interactions.

Cost. Total cost decreases for five of six backbones (Figure 2 b), particularly for expensive agents, from $247 to $119 for Opus 4.7 and $194 to $122 for Haiku 4.5. Reduced search effort offsets the minimal reranking cost, lowering overall agent compute. GPT-5.5 is the sole exception, with a modest cost increase potentially due to reading more evidence, contributing to higher accuracy (Table 2 ).


### 4. Concluding Remarks

We introduced SOARS, a training-free framework that adapts a System One model as a reranker inside the deep search agent’s iterative loop. Across six LLM backbones on BrowseComp-Plus and WebShaper, SOARS consistently improves answer accuracy and evidence recall while reducing the agent’s search calls, latency, and cost. These results show that fast, calibrated System One models make per-step reranking both effective and efficient, establishing them as a practical component for building deep search agents.
