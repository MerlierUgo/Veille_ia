## AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher

Task success alone does not specify which behaviors post-training should reinforce. Even successful teacher trajectories can contain unsupported assumptions, unproductive repetition, or superficial verification. We propose Skill-FT (Skill-Guided Fine-Tuning), which uses natural-language skills to suppress undesirable habits and elicit underrepresented effective behaviors during teacher rollouts, then fine-tunes a target model on the resulting trajectories. We introduce AutoMaster, an autonomous post-training system in which an LLM agent develops these interventions through trajectory analysis, skill design, data selection, and feedback from rollouts and target-model evaluation. Across Terminal, Search, and software engineering tasks with 4B and 9B target models, AutoMaster improves mean performance over Vanilla SFT on successful unguided teacher trajectories by 1.42–8.99 percentage points, with the teacher, task pool, training set size, and SFT recipe held fixed. Together with the ablations and trajectory analyses, these results suggest that behavioral shaping can make a fixed model a more effective teacher. We further find that retaining skill instructions during SFT yields higher mean performance than removing them across all six settings, despite their absence at evaluation and identical supervised outputs. These findings suggest that preserving skill context as part of a training demonstration can support better behavioral internalization.

### 1 Introduction

LLM agents are beginning to undertake model development itself, from creating training data to executing post-training pipelines ( Kulikov et al., 2026 ; Chen et al., 2026c ; Rank et al., 2026 ) . This opens a path toward autonomous post-training, in which an agent diagnoses model weaknesses, proposes interventions, and uses training feedback to guide further improvement. A central question is what such a system should seek to change.

A common approach to agent post-training is supervised fine-tuning (SFT) on successful trajectories ( Chen et al., 2023 ; Ta et al., 2026 ) . Yet task success does not specify which behaviors post-training should reinforce . Unsupported assumptions, unproductive repetition, or superficial verification can lead to failure, but they can also persist in trajectories that reach the correct outcome. Fine-tuning on such successful trajectories can reinforce these behaviors alongside the actions that support success. Meanwhile, desirable behaviors may remain underrepresented even among successful trajectories. We therefore argue that autonomous post-training should actively shape the behaviors demonstrated by the teacher, alongside selecting trajectories for training.

To this end, we propose Skill-FT (Skill-Guided Fine-Tuning), which uses natural-language skills to shape the teacher’s behavioral patterns during rollout. Skills specify how to reason or act in relevant situations and are appended to the system prompt. By suppressing undesirable habits and eliciting effective behaviors that are underrepresented in unguided rollouts, this guidance aims to improve task execution and the demonstrations available for learning. We fine-tune the student on selected teacher trajectories, retaining any skill instructions used to generate them in the training input.

A skill can change how the teacher solves a task, but observing that change alone does not tell us how useful the resulting demonstration will be for a student. We introduce AutoMaster, an autonomous post-training framework in which an LLM agent investigates both questions. The agent tests candidate skills in teacher rollouts, examines which behaviors they elicit, and selects demonstrations for SFT. It then examines the student’s evaluation scores and trajectories to decide whether to revise a skill, apply it to different tasks, or select different demonstrations in the next round.

We evaluate AutoMaster on Terminal, Search, and software engineering tasks with Qwen3.5-4B and 9B ( Qwen Team, 2026 ) as student models. Across all six benchmark–model settings, AutoMaster improves mean performance over Vanilla SFT by 1.42–8.99 percentage points, with the teacher, task pool, training set size, and SFT recipe held fixed. These gains indicate that successful-trajectory distillation can understate the post-training headroom available from a fixed teacher. Together with the component ablations and the task-matched comparison, these results suggest that Skill-FT can make a fixed model a more effective teacher by shaping the behaviors it demonstrates. Trajectory analyses further illustrate how skill guidance addresses behavioral weaknesses, even when both unguided and skill-guided rollouts succeed.

We further find that reducing a training–evaluation prompt mismatch can make the same trajectories less effective for learning . With the same trajectories and SFT recipe, retaining skill instructions during training yields higher mean performance than removing them across all six settings, even though all students are evaluated without generated skills. The training examples suggest a possible explanation: retaining skill instructions keeps behavioral rules and their conditions of application explicit in the input. Removing them preserves the same reasoning and actions as supervision, but may require the student to infer more of these rules from the task and trajectory. For reasoning that explicitly references a skill, retaining the instructions also preserves the correspondence between the input guidance and the supervised output. These findings suggest that preserving skill context can help the student better internalize the behaviors shaped during teacher rollouts.

Our contributions are summarized as follows:

- • Behavioral shaping beyond task success. We propose Skill-FT, which uses natural-language skills during teacher rollouts to shape the behaviors represented in SFT demonstrations, including on tasks the teacher already solves. Our results suggest that such interventions can make a fixed model a more effective teacher.

- • Autonomous post-training framework. We introduce AutoMaster, a framework in which an LLM agent designs, executes, and refines behavioral interventions. It jointly optimizes skill guidance and data selection using rollout evidence to guide subsequent exploration.

- • Skill context for behavioral internalization. Controlled comparisons across three domains and two model sizes show that retaining skill instructions during SFT improves mean performance without test-time skills. This suggests that preserving the context behind supervised reasoning and actions can support better behavioral internalization.


### 2 Related Work


##### Autonomous Post-Training.

Recent systems use LLM agents to iteratively revise training code in response to evaluation feedback ( Karpathy, 2026 ; Chen et al., 2026a ; Wei, 2026 ) . For post-training, FT-Agent ( Li et al., 2026 ) refines data and training strategies through structured planning and feedback analysis, while RSI-Master ( Du et al., 2026 ) organizes research exploration through persistent experiment records and reviewer guidance. Within this paradigm, AutoMaster centers autonomous post-training on skill-guided behavioral shaping during teacher rollouts.


##### Skill-Based Agent Learning.

Prompt and skill optimization methods use execution feedback to refine natural-language guidance without updating model parameters ( Agrawal et al., 2025 ; Shi et al., 2026 ; Ge et al., 2026 ) . Related work couples the evolution of skill libraries or procedural scaffolds with model training ( Xia et al., 2026 ; Ding et al., 2026 ) . Skill-to-LoRA ( Zhang and Qi, 2026 ) trains skill-specific adapters on skill-guided demonstrations, while Skill-SD ( Wang et al., 2026 ) uses a skill-conditioned teacher to score tokens in the student’s own rollouts for on-policy self-distillation. Our work examines both how skills shape teacher demonstrations and whether retaining the skill instructions during SFT improves learning when those instructions are absent at evaluation.


##### Learning from Agent Trajectories.

Prior work improves reasoning and agent capabilities by learning from generated trajectories ( Chen et al., 2024a ; Chen et al., 2024b ; Zeng et al., 2024 ) , including trajectories that demonstrate error recovery ( Fu et al., 2025 ; Yuan et al., 2025 ) . Behavior Priming ( Jin et al., 2026 ) selects trajectories exhibiting beneficial behaviors, while PROOF-Gen ( Ta et al., 2026 ) uses per-task prompt optimization to recover verified demonstrations from teacher failures. Skill-FT complements trajectory selection and failure recovery by actively shaping behavioral patterns during teacher rollouts, including on tasks it already solves.


### 3 Autonomous Post-Training with Skill-FT

> Figure 2 : Overview of AutoMaster. An LLM agent designs skills for subsets of a fixed training task pool and tests them in pilot teacher rollouts. It refines the skills as needed, runs promising interventions on larger batches, and selects demonstrations for SFT. In each outer-loop round, the student is trained from the same initial checkpoint, with any skill instructions used by the teacher retained in the training input. The student is evaluated without generated skills.

AutoMaster uses an LLM agent to develop and refine Skill-FT interventions through two nested loops (Figure 2 ). Within each setting, the teacher, training task pool, and initial student checkpoint are fixed. In the inner loop, the agent decides how to guide the teacher and which demonstrations to use for training. In the outer loop, it fine-tunes the student on the selected demonstrations and uses the student’s subsequent evaluation scores and trajectories to guide the next round.


#### 3.1 Skill-FT: Skill-Guided Fine-Tuning

To shape the behavioral patterns represented in training trajectories, we guide the teacher with natural-language skills. These skills are designed to suppress undesirable habits and elicit effective behaviors that are underrepresented in unguided rollouts. A skill specifies how to reason or act in relevant situations and may include behavioral principles, concrete procedures, or domain-specific knowledge. Skills can be shared across tasks or combined to address different aspects of the same task. For a task $x$ , let $s$ denote the combined text of the selected skills. We append $s$ to the base system prompt $p$ and generate a trajectory through interaction with the task environment:

[Tableau] $$\tau\sim\operatorname{Rollout}(\pi_{T},x;p\oplus s),$$ (1)

where $\pi_{T}$ denotes the teacher model and $\oplus$ denotes text concatenation. This guidance conditions the teacher’s reasoning and actions during execution, enabling behavioral interventions even on tasks it already solves.

To internalize the demonstrated behaviors, we fine-tune the student on selected teacher trajectories using standard SFT. For each trajectory, we retain the original system prompt, including any skill instructions, so the student sees the same instructions that guided the teacher. At evaluation, the student follows the benchmark’s official protocol without the generated skills.


#### 3.2 Inner Loop: Developing Behavioral Interventions

The agent begins by examining the training tasks and initial trajectories from both the unguided teacher and the initial student. It looks for habits to discourage and useful behaviors that the teacher rarely demonstrates, including on tasks the teacher already solves. In later rounds, the agent also inspects student evaluation trajectories to see where the intended behaviors appear and which weaknesses persist. These observations guide the skills it designs and the training tasks to which it applies them.

As shown in Figure 2 , pilot rollouts test whether candidate skills elicit the intended behaviors without introducing new problems during task execution. The agent uses the resulting trajectories to refine both the skill instructions and their scope of application, repeating trials as needed.

The agent then scales promising interventions to batched rollouts and selects trajectories it judges valuable for training, considering both task outcomes and demonstrated behaviors. The agent may also select unguided teacher trajectories that already exhibit useful behavioral patterns. Feedback from generation and selection can prompt further revisions to skills or task coverage, followed by additional rollouts as needed. The selected trajectories form the training set for the outer loop.


#### 3.3 Outer Loop: Model Training and Feedback

The outer loop evaluates the student trained on the demonstrations selected in each round. In round $r$ , the inner loop produces a training set $\mathcal{D}_{r}$ . SFT starts from the same initial student checkpoint $\theta_{0}$ in every round:

[Tableau] $$\theta_{r}=\operatorname{SFT}(\theta_{0},\mathcal{D}_{r}).$$ (2)

The agent receives both scores and trajectories from evaluating $\theta_{r}$ without generated skills. Scores summarize how well the student performs, while trajectories let the agent inspect how it handled individual tasks. The agent can compare these observations with earlier skills, teacher rollouts, and training sets to decide whether to revise a skill, change its task coverage, or select different demonstrations in the next round. This experiment history carries forward, while each student is trained from $\theta_{0}$ .

> Figure 3 : Infrastructure of AutoMaster. The agent accesses data and submits rollout and SFT jobs through the MCP interface. After SFT, the execution controller automatically schedules evaluation on a separate GPU cluster, where SGLang workers load the checkpoint directly from storage shared with the training cluster. Linked experiment records let the agent trace each evaluation back to the training set and the skills that guided the teacher.


#### 3.4 Infrastructure

The infrastructure lets the AutoMaster agent test how a skill shapes teacher behavior and examine whether the student exhibits that behavior after fine-tuning (Figure 3 ). From its Docker container, the agent uses the Model Context Protocol (MCP) ( Anthropic, 2024 ) to access tasks and initial trajectories, submit teacher rollout jobs, and launch SFT on selected demonstrations. The rollout harness calls the teacher API, while the evaluation harness queries the student model served by SGLang ( Zheng et al., 2024 ) . Both harnesses use a shared sandbox cluster that runs task tools and verifiers in isolated Docker containers, allowing multiple tasks to execute concurrently.

When an SFT job completes, the execution controller checks that the checkpoint is available and automatically schedules evaluation. The training and evaluation GPU clusters share a checkpoint store: SGLang workers load the weights directly from the location where the SFT service wrote them, avoiding an intermediate copy to the evaluation cluster. The controller also records job and stage progress so that it can restart a failed inference worker and resume evaluation without rerunning SFT.

Across rounds, AutoMaster links each student’s evaluation scores and trajectories to its checkpoint, its training set, and the skills used during teacher rollouts. When a weakness recurs in student evaluations, the agent can inspect earlier rollouts to see whether the teacher demonstrated the desired behavior and check which of those demonstrations entered the training set. This evidence informs whether the agent revises a skill, changes its data selection, or both in the next round.


### 4 Experiments


#### 4.1 Experimental Setup


##### Benchmarks and Task Pools.

We evaluate Terminal, Search, and software engineering (SWE) tasks using Terminal-Bench 2.1 ( Merrill et al., 2026 ) , BrowseComp (BC; using the Lite-185 subset released by Traverse) ( Wei et al., 2025 ; Ma et al., 2026 ) , and Doc2Repo ( Chen et al., 2026b ) , respectively. For each domain, we randomly sample 1,000 training tasks from public datasets ( Meng et al., 2026 ; Deng et al., 2026 ; Zhao et al., 2026 ) to form a fixed task pool shared across all methods.


##### Models and Baselines.

We use Qwen3.5-4B and Qwen3.5-9B ( Qwen Team, 2026 ) as target models. Across all experiments, the LLM agent runs in Codex with GPT-6 Astra ( OpenAI, 2026 ) at xhigh reasoning effort, while DeepSeek-V4-Pro-Preview ( DeepSeek-AI, 2026 ) serves as the teacher at high reasoning effort. We compare against Base , the target model without additional fine-tuning, and Vanilla SFT , which performs standard SFT on 512 trajectories randomly sampled from successful unguided teacher rollouts on the shared task pool.


##### Training and Evaluation.

For AutoMaster, the agent starts with trajectories generated by the initial target model and the unguided teacher on the training task pool, with a budget of five outer-loop rounds. Across all settings, each training run starts from the corresponding initial checkpoint and performs full-parameter SFT on 512 trajectories for three epochs, with a learning rate of $10^{-5}$ and a global batch size of 32. We evaluate final-epoch checkpoints without generated skills using domain-specific harnesses ( Meng et al., 2026 ; Sun et al., 2026 ; Chen et al., 2026b ) , with identical settings across methods within each domain. We measure task accuracy on Terminal-Bench 2.1 and BC and mean test pass rate on Doc2Repo, reporting mean $\pm$ SD over three evaluation runs per checkpoint. Further experimental details are provided in Appendix A .

#### 4.3 Ablation Studies

To understand how AutoMaster improves on Vanilla SFT, we separately ablate skill guidance and data selection. In w/o Skill Guidance , the LLM agent selects training trajectories from unguided teacher rollouts. In w/o Data Selection , the agent designs and refines skills for a fixed, randomly sampled subset of training tasks, without agent-directed trajectory selection. Both variants retain autonomous experimentation with the same teacher, task pool, training set size, and SFT recipe.

Removing either component lowers mean performance in all six settings, but their relative contributions vary (Figure 4 ). On Terminal-Bench 2.1 with the 4B student, skill guidance without agent-directed selection yields higher mean accuracy than selection from unguided rollouts (20.22% versus 17.60%). Both fall below Vanilla SFT (22.47%), whereas the full method reaches 28.09%. On BrowseComp at the same model size, the ordering reverses: selection from unguided rollouts yields 45.77%, compared with 43.78% for guidance without selection. One possible explanation is that the value of selection depends on what the teacher already demonstrates: selection can favor trajectories that exhibit useful behaviors, while guidance can elicit behaviors that are rare in unguided rollouts.

To test whether the choice of training tasks alone explains the gains, we construct Task-Matched SFT from unguided rollouts by the same teacher, matching both the task IDs and the per-task sample counts of AutoMaster’s final training set. With task composition held fixed, AutoMaster achieves higher mean scores in all six settings, by 1.08–10.11 percentage points. Across the four Terminal and Search training corpora, both the unguided rollout and the selected AutoMaster demonstration succeed in 79.3–91.2% of matched pairs (Table A5). For these pairs, the success label alone cannot distinguish what the two trajectories demonstrate. Together with the component ablations, these results support jointly optimizing how training demonstrations are generated and selected .

#### 5.1 Behavioral Shaping Beyond Task Success

Task success can conceal weaknesses in a teacher’s reasoning and actions. To examine the behaviors targeted by Skill-FT, Figure 5 contrasts unguided and skill-guided teacher trajectories on the same tasks across three domains.

The first two cases illustrate behavioral differences that task outcomes alone cannot distinguish. In Figure 5 (a), both executions satisfy the numerical error threshold, yet the unguided teacher claims fourth-order accuracy despite measured convergence of approximately second order. The guided teacher uses independent numerical checks to revise and validate its method. Similarly, both search executions in Figure 5 (b) reach the correct answer. The unguided trajectory repeatedly pursues unverified award guesses before finding supporting records, while the guided trajectory uses retrieved episode–director records to identify and verify a candidate. A filter based solely on successful completion would leave these behavioral differences unexamined.

The third case highlights the importance of diagnosing verification failures. Both executions initially construct a self-test with an input different from the specification while retaining the original expected order. The unguided teacher reverses the global sorting rule to satisfy this mistaken expectation. The guided teacher checks the input encoding, corrects the self-test, and preserves the specified rule, passing 38 of 38 tests compared with 32 of 38. The useful behavior here is to establish what a failed check actually implies before changing the implementation.

Across these cases, the guided trajectories illustrate changes in how the teacher validates a numerical claim, redirects a search, or diagnoses a failed check. The first two cases show how skill guidance can address behavioral weaknesses even when both executions succeed , while the third illustrates an improvement in implementation correctness. These differences highlight the value of examining demonstrated behaviors alongside task outcomes to identify opportunities for improvement. AutoMaster identifies such opportunities through trajectory analysis and designs skills to address them. Together with the downstream results, these observations suggest that Skill-FT can improve the training value of the demonstrations produced by a fixed teacher.

#### 5.2 Preserving Skill Context for Better Internalization

We investigate how to train the target model to better internalize skill-guided behaviors. Specifically, we examine whether the skill instructions used to guide teacher rollouts should be retained during fine-tuning. We compare Keep , which retains these instructions in the training input, with Remove , which omits them. Both conditions use the same trajectories and SFT recipe. All models are evaluated without generated skills, following the official evaluation protocols.

Removing the skill instructions leaves the supervised reasoning, responses, and tool calls unchanged while making the training prompt more like the evaluation prompt, which contains no generated skills. Yet students perform better when the training input retains the instructions that guided the teacher . Across all six settings, Keep exceeds Remove in mean score by 2.15–4.01 percentage points (Figure 6).

Figure 7 illustrates a possible explanation. In (a), the teacher consults the skill to decide whether the script needs an execute bit: because the script runs through the interpreter, no permission change is needed. In (b), the teacher explicitly refers to the skill and uses its grammar to determine how to group an expression. Removing the instructions preserves the teacher’s reasoning and actions as supervision, including any rule it quotes, but removes the original instruction from the input. Retaining that context may help the student learn when the demonstrated action applies.

#### 5.3 Autonomous Experimentation Across Rounds

Having examined how skill context affects learning from teacher demonstrations, we next investigate how AutoMaster develops the interventions used to generate and curate those demonstrations. The agent draws on accumulated rollout and training feedback to explore alternative behavioral hypotheses and intervention strategies.

Figure 8 shows that continued experimentation identifies higher-performing candidates in all six benchmark–model settings. The highest mean scores occur in rounds two through four, exceeding first-round performance by 2.16–4.87 percentage points. Variation across rounds is consistent with the exploratory protocol: the agent continues to investigate alternative interventions after finding a strong candidate, without requiring each trial to improve on its predecessor. On BrowseComp-9B, mean accuracy remains near 49% for the first three rounds before reaching 51.53% in the fourth. This delayed improvement illustrates how continued experimentation can uncover further gains after several rounds of limited progress.

The consistency of gains also differs across model sizes. The 9B model exceeds Vanilla SFT in mean performance in every round across all three domains, whereas the 4B model does so throughout all five rounds only on Terminal-Bench 2.1. The component ablations show a similar pattern: both variants exceed Vanilla SFT in all three domains for the 9B model, but only on BrowseComp for the 4B model (Section 4.3 ). Together, these observations suggest that greater target-model capacity may support more consistent gains from the interventions explored by AutoMaster .


### 6 Conclusion

We introduced Skill-FT for shaping teacher behavior with natural-language skills and AutoMaster, an autonomous post-training system that designs, executes, and refines these interventions. Across three domains and two model sizes, AutoMaster achieves higher mean performance than Vanilla SFT. The results and trajectory analyses suggest that a fixed model can become a more effective teacher through behavioral shaping, even on tasks it already solves. Retaining skill instructions during SFT also yields higher mean performance than removing them, despite their absence at evaluation, suggesting that preserving skill context can support better behavioral internalization.

#### A.4 Model Evaluation

For each SFT run, we evaluate the checkpoint saved at the end of the third epoch without generated skills. We follow each benchmark’s official evaluation protocol using the domain-specific harnesses listed in Table A1 . Inference and execution settings are identical across methods within each domain. These benchmark evaluations provide scores and execution trajectories for subsequent experimentation.

Across all domains, we use a temperature of 1.0, a top- $p$ of 0.95, a maximum of 65,500 tokens per model response, and a limit of 600 execution steps per task. The per-task agent time limit is three hours for Terminal-Bench 2.1 and four hours for Doc2Repo. No overall task time limit is imposed for BrowseComp.

At the end of autonomous experimentation, AutoMaster selects a final checkpoint based on accumulated evaluation feedback and records its choice in a final report. We then evaluate the selected checkpoint in three new runs to obtain the reported results. For all methods, we report mean $\pm$ SD over three evaluation runs per checkpoint, using task accuracy for Terminal-Bench 2.1 and BrowseComp and mean test pass rate across tasks for Doc2Repo. The SD summarizes evaluation variability for a fixed checkpoint.

#### A.6 Paired Analysis of Performance Gains

We quantify uncertainty in the gains over Vanilla SFT using paired bootstrap resampling ( Koehn, 2004 ; Dror et al., 2018 ) . This estimates uncertainty in the performance difference while preserving the correspondence between the two methods’ scores on each evaluation task. For each task, we first average its scores over the three evaluation runs for each method. We then resample task IDs with replacement, retaining both methods’ scores for each sampled task, and recompute the mean performance difference. We use 10,000 resamples with random seed 0 to obtain pointwise 95% percentile bootstrap confidence intervals. For Doc2Repo, resampling is performed over whole repositories, each corresponding to one task in the 50-repository evaluation set. All tasks and their recorded scores are retained. The intervals summarize variation across tasks or repositories for the reported checkpoints and recorded evaluations.
