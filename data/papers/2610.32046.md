## Can Test-Time Memory Evolution Outperform Test-Time Training for Scientific Discovery?

Recent test-time training (TTT) frameworks have enabled open-weight large language models (LLMs) to outperform inference-only frameworks powered by frontier models on scientific discovery tasks. However, TTT introduces additional computational cost for online weight updates during the discovery process, making computational efficiency an important consideration when scaling to larger models. This motivates us to explore an efficient test-time adaptation method for scientific discovery. We introduce Test-Time Memory Evolution (TTME), a plug-and-play test-time adaptation method, as an alternative to TTT. TTME continually updates the external memory by distilling the experience to guide subsequent discovery without updating model weights. To have a clean comparison, we evaluate TTME and TTT under the same discovery framework, replacing only the test-time adaptation method. Our evaluation shows that TTME outperforms TTT on all five mathematical tasks, while reducing computational cost by $82.8$ - $84.6\%$ in FLOPs and $47.7$ - $58.4\%$ in runtime. These results establish TTME as an effective and computationally efficient alternative to TTT in the evaluated discovery settings. Our code is available at https://github.com/yepengliu/TTME .

The three settings use the same discovery framework, with TTT, with TTME replacing TTT, or with neither method. TTME achieves the best scores at low computational cost across all three tasks.


### 1 Introduction

Scientific discovery often involves proposing hypotheses, evaluation, and using the resulting evidence to guide further investigation [ 13 , 19 ] . Advances in reasoning, coding, and agentic tool-use capabilities of large language models (LLMs) have enabled systems that automate part of this discovery process [ 22 , 14 ] . In the iterative discovery loop, a failed attempt can reveal an implementation constraint, while a successful modification can suggest an idea worth applying elsewhere. A key design question is how to learn from this accumulated experience to improve subsequent search efficiently.

Recent test-time training (TTT) frameworks, such as TTT-Discover [ 36 ] and ThetaEvolve [ 33 ] , provide a promising solution to this challenge by combining iterative search with test-time reinforcement learning (RL) [ 28 , 8 ] . Specifically, an LLM generates candidate solutions and receives evaluation feedback. These evaluated attempts provide training data for RL, which internalizes search experience in model weights to guide subsequent generation. Their results demonstrate that TTT is a powerful test-time adaptation method on challenging scientific discovery tasks, enabling smaller open-weight models to outperform inference-only systems based on frontier models, such as AlphaEvolve [ 22 ] . However, TTT requires online model weight adaptation during the whole discovery process, which is usually computationally expensive and time-consuming (see Table 3 ). It makes TTT hard to scale to larger models for more complex discovery tasks. This motivates us to explore: under the same discovery framework, is there a more efficient test-time adaptation method that can achieve comparable or even better performance than test-time training?

We hypothesize that evolving external memory could be a efficient alternative to online weight updates for scientific discovery. Our core intuition is that current LLMs already have broad foundational knowledge, reasoning and coding capabilities to use experience accumulated during discovery. Continually distilling and organizing this experience in external memory may therefore be sufficient to improve subsequent discovery, without internalizing it through weight updates. Building on this intuition, we introduce Test-Time Memory Evolution (TTME), a plug-and-play self-evolving memory system for scientific discovery. We update the memory from evaluation feedback and provide relevant content in the context to guide the subsequent steps.

Specifically, we divide the search experience into two components: practical lessons for implementing candidate solutions and algorithmic ideas for improving task scores. Correspondingly, TTME maintains two complementary memory modules: Guideline Memory and Strategy Memory . Guideline Memory distills execution and evaluation feedback into shared operational guidelines for reliable implementation. Strategy Memory extracts effective algorithmic ideas from score-improving modifications and consolidates related experiences into reusable strategies. We select and adapt relevant strategies to guide subsequent exploration, combining ideas from different search attempts.

Our contributions are summarized as follows:

- • We investigate whether a test-time memory evolution can outperform test-time weight updates in scientific discovery, and introduce an plug-and-play self-evolving memory method that continually updates external memory from evaluated search experience to guide subsequent discovery with a fixed-weight model.

- • We evaluate TTME under two TTT frameworks across five mathematical construction tasks and three models spanning 8B and 120B parameters. We preserve each framework’s experimental configuration, replacing only its TTT part with TTME. TTME outperforms the reported TTT results in all evaluated tasks. Our analysis shows that TTME reduces running time by $47.7-58.4\%$ and computational costs by $82.8-84.6\%$ relative to TTT. These results demonstrate that TTME is a more efficient alternative to TTT for scientific discovery.

- • We analyze the search behavior of TTME and TTT during the discovery. Both methods improve the implementation validity rate relative to the underlying discovery framework without TTT or TTME, but TTME achieves better performance. Moreover, compared with TTT, TTME more frequently builds on score-improving combinations of previously explored ideas.


### 2 Related Work


##### Non-Parametric Adaptation.

Non-parametric discovery methods use fixed-weight LLMs to generate executable candidates and guide subsequent search with evaluation feedback [ 27 , 30 , 14 , 18 , 17 , 16 ] . The effectiveness of this process depends on how search policies interact with the operators used to generate and modify candidates [ 32 , 7 ] . FunSearch [ 27 ] and AlphaEvolve [ 22 , 9 ] evolve candidate programs through repeated generation and evaluation with proprietary LLMs. Adaptive search methods further use observed progress to adjust exploration intensity and allocate computation across candidate populations [ 5 ] . These studies establish search organization as an important factor in the quality and efficiency of automated discovery. Beyond selecting promising candidates, execution experience can also help subsequent exploration [ 1 , 37 , 20 , 15 , 29 , 38 , 34 ] . [ 35 ] and [ 6 ] compare candidate solutions and their evaluation results to identify promising modifications. [ 4 ] uses execution feedback to guide which optimizations to attempt next by adding, reprioritizing, or pruning proposed modifications in a search tree. These studies improve discovery through the joint design of search, planning, and feedback utilization. We instead study experience accumulation specifically as a modular adaptation mechanism and introduce TTME, a plug-and-play memory system for existing discovery frameworks.


##### Parametric Adaptation.

Parametric methods update the LLMs through RL on evaluated search attempts [ 31 , 25 , 12 ] . ThetaEvolve [ 33 ] turns evolutionary program search into a dynamic RL environment. As its program archive evolves, training proceeds from newly discovered candidates rather than repeatedly starting from the same initial program. TTT-Discover [ 36 ] designs both its learning objective and search rule around finding a single high-quality solution rather than maximizing average performance. It exponentially upweights high-reward attempts during training and uses the best observed outcomes to prioritize states for further search. These methods internalize search experience in model weights, enabling open-weight models to surpass results achieved with proprietary models [ 33 , 36 ] . However, continually updating model weights during discovery incurs additional computational cost. We show that evolving external memory offers a more effective and efficient alternative to online weight adaptation. TTME achieves better discovery outcomes within both frameworks, and our efficiency experiments demonstrate lower computational cost.


### 3 Method


#### 3.1 Background and Problem Formulation

We study scientific discovery as an iterative process of proposing hypotheses, evaluating them, and using the resulting evidence to guide subsequent proposals. We focus on tasks with executable candidate programs and a task-specific verifier, where a program produces a construction whose validity and objective value are assessed by the verifier.

Let $v(x)\in\{0,1\}$ indicate whether candidate program $x$ produces a valid result, and let $s(x)$ denote its evaluated score, oriented so that larger values are better. For the set $\mathcal{X}_{\mathrm{eval}}$ of candidates evaluated within the search budget, the best valid score is

[Tableau] $$s^{\star}=\max_{\begin{subarray}{c}x\in\mathcal{X}_{\mathrm{eval}}\\ v(x)=1\end{subarray}}s(x).$$ (1)

Our goal is to find the highest-scoring valid candidate within a given search budget.

Our study builds on two existing TTT scientific discovery frameworks, TTT-Discover [ 36 ] and ThetaEvolve [ 33 ] . We describe two frameworks using a common formulation. Each framework maintains an archive of search states, each representing a candidate solution and its associated records. At each search step, the framework selects states from the archive as parents for new attempts. The code associated with a selected parent is its parent program. Given the task specification, parent program, and associated records, the LLM generates candidate programs. We execute and evaluate these programs, recording their validity, scores, and execution feedback. The framework then updates the archive for subsequent search. We preserve each framework’s original parent-selection and archive-update rules.

Both frameworks use search feedback to update model weights through test-time RL. We ask whether non-parametric methods, e.g., memory adaptation, can substitute for these parametric methods, e.g., online weight adaptation . Writing $\mathcal{D}_{t}$ for evaluated search records available to an update, we contrast two adaptation mechanisms:

[Tableau] $\displaystyle\text{Weight adaptation:}$ $\displaystyle\theta_{t+1}\leftarrow U_{\mathrm{RL}}(\theta_{t},\mathcal{D}_{t}),$ (2) $\displaystyle\text{Memory adaptation:}$ $\displaystyle\mathcal{M}_{t+1}\leftarrow U_{\mathrm{mem}}(\mathcal{M}_{t},\mathcal{D}_{t}),\qquad\theta_{t}=\theta_{0}.$

Here, $U_{\mathrm{RL}}$ updates model parameters, whereas $U_{\mathrm{mem}}$ updates external memory used to construct subsequent generation contexts. $t$ denotes the search step, $\theta_{t}$ is the model parameter, and $\mathcal{M}_{t}$ is the external memory. We retain the underlying discovery framework and task verifier while replacing only TTT with TTME. Figure 2 compares these two adaptation mechanisms.

> Figure 2 : Weight adaptation updates model parameters through test-time RL (top). Memory adaptation updates external memory that conditions generation while keeping model weights fixed (bottom). Both retain the same underlying discovery framework.

Evaluated search attempts provide practical lessons for implementing candidate solutions and algorithmic ideas for improving task scores. We organize this experience into two complementary memories, $\mathcal{M}_{t}=(\mathcal{L}_{t},\mathcal{S}_{t})$ . Guideline Memory $\mathcal{L}_{t}$ stores shared guidelines for implementing candidate solutions. Strategy Memory $\mathcal{S}_{t}$ organizes algorithmic ideas into reusable strategies that we select and adapt to guide subsequent search.


#### 3.2 Guideline Memory: Shared Operational Lessons

Execution and evaluation feedback can reveal implementation problems and choices that improve task scores. Lessons from one attempt can guide the implementation of later candidates. We distill these observations into compact guidelines stored in $\mathcal{L}_{t}$ . Each guideline specifies when it applies, explains the relevant failure or improvement, and recommends a concrete action.

Every $K$ search steps, we form a summary $r_{t}$ of outcomes collected across parents since the previous update, including valid results, their scores, and observed failures. We update the memory in two stages, first proposing guidelines $\mathcal{G}_{t}$ and then incorporating them into the existing memory:

[Tableau] $$\mathcal{G}_{t}\leftarrow\operatorname{Distill}(r_{t},\mathcal{L}_{t}),\qquad\mathcal{L}_{t+1}\leftarrow\operatorname{Maintain}(\mathcal{L}_{t},\mathcal{G}_{t},t).$$ (3)

Here, $\operatorname{Distill}$ prompts the same base model with $r_{t}$ and the existing guidelines $\mathcal{L}_{t}$ to propose $\mathcal{G}_{t}$ . In $\operatorname{Maintain}$ , we match each proposal against existing entries. For a match, we increment the entry’s recurrence count and refresh its last reaffirmed step to $t$ ; otherwise, we add a new entry. We remove stale entries and enforce a capacity limit, prioritizing recurrence counts and breaking ties by recency. The retained guidelines provide shared context for implementing subsequent candidate solutions.


#### 3.3 Strategy Memory: Reusable Algorithmic Experience

Combining existing ideas is important in scientific discovery. An idea behind a score-improving modification may also be useful for other candidates. Strategy Memory preserves these ideas and how they were applied, so they can be adapted and combined in subsequent searches.

We update Strategy Memory every $K$ search steps, together with Guideline Memory. We select evaluated cases where a modified program produces a valid result with a higher score than its parent, and denote this collection by $\mathcal{D}_{t}^{+}$ . For each case, we analyze the original and modified programs, their differences, and the evaluation results using the same base model. The model extracts one or more experience notes from each case, each describing an algorithmic idea, how it was applied, and its source case. We denote the resulting collection of notes by $\mathcal{E}_{t}$ .

Different modifications can implement the same algorithmic idea in different ways. We group experience notes that share an underlying idea into a strategy family and maintain a persistent strategy entry for each family. Each entry describes the shared idea, its application conditions, and the different ways it has been implemented, with references to the source cases. The extraction of experience notes and the update of Strategy Memory are expressed as:

[Tableau] $$\mathcal{E}_{t}\leftarrow\operatorname{Extract}(\mathcal{D}_{t}^{+}),\qquad\mathcal{S}_{t+1}\leftarrow\operatorname{Consolidate}(\mathcal{S}_{t},\mathcal{E}_{t}).$$ (4)

Here, $\operatorname{Extract}$ denotes the case-wise extraction described above. In $\operatorname{Consolidate}$ , we use the same base model to compare new notes with existing entries and assign them to existing or new families. For an existing family, the model combines the new notes with the current entry to update its content. For a new family, the model creates an entry from its notes.


#### 3.4 Strategy-Guided Search and Candidate Generation

With two memories established, we now describe how they guide new candidate generation. Guideline Memory provides shared guidance for implementation. Strategy Memory contains ideas drawn from specific modifications, which may need adaptation before they can be applied to another parent. We therefore propose Strategy-Guided Search to select relevant strategies and turn them into parent-specific modification instructions. When no suitable strategy is selected, we use the parent context and Strategy Memory to propose a new idea and formulate its modification instruction.

Specifically, at search step $t$ , let $p_{i}^{(t)}$ denote the program associated with the $i$ -th selected parent. Let $C_{i}^{(t)}$ denote the input context supplied by the underlying framework for the $i$ -th parent at step $t$ , such as task specification and parent program $p_{i}^{(t)}$ .

> Algorithm 1 Scientific Discovery with Test-Time Memory Evolution

For each parent, we use a selector (base model) to analyze and select up to $N$ distinct strategies from Strategy Memory based on their potential to improve the parent program. The selector is provided with the parent context, a summary of each strategy entry, and the strategies already assigned to earlier parents in the current step. Selection proceeds sequentially across parents:

[Tableau] $$\mathbf{a}_{i}^{(t)}=\operatorname{Select}\bigl(C_{i}^{(t)},\hat{\mathcal{S}}_{t},\mathbf{A}_{<i}^{(t)}\bigr),\qquad\mathbf{a}_{i}^{(t)}=(a_{i,1}^{(t)},\ldots,a_{i,N}^{(t)}),$$ (5)

Here, $\hat{\mathcal{S}}_{t}$ denotes the summaries of strategy entries. We collect the nonempty strategy selections for earlier parents into

[Tableau] $$\mathbf{A}_{<i}^{(t)}=\left\{a_{j,n}^{(t)}\;\middle|\;1\leq j<i,\;1\leq n\leq N,\;a_{j,n}^{(t)}\neq\varnothing\right\}.$$

Each nonempty $a_{i,n}^{(t)}$ denotes a selected strategy. If fewer than $N$ strategies are selected, we set the remaining elements of $\mathbf{a}_{i}^{(t)}$ to $\varnothing$ . The selector prioritizes improvement potential for the current parent. Among similarly plausible choices, it prefers a strategy not yet included in $\mathbf{A}_{<i}^{(t)}$ .

Then, we produce a parent-specific modification instruction $d_{i,n}^{(t)}$ for $n=1,\ldots,N$ :

[Tableau] $$d_{i,n}^{(t)}=\begin{cases}\operatorname{Adapt}\bigl(C_{i}^{(t)},\mathcal{S}_{t}[a_{i,n}^{(t)}]\bigr),&a_{i,n}^{(t)}\neq\varnothing,\\ \operatorname{Propose}\bigl(C_{i}^{(t)},\mathcal{S}_{t}\bigr),&a_{i,n}^{(t)}=\varnothing.\end{cases}$$ (6)

For a selected strategy, one adaptor (base model) reads its full entry and the full parent code, then specifies how to apply the strategy to that parent. When $a_{i,n}^{(t)}=\varnothing$ , the adaptor uses the parent and available strategy memory content to propose a new idea.

We use the constructed instructions to guide candidate generation. Adapting an explored strategy allows us to combine an idea extracted from a score-improving modification with the parent program’s existing approach. Moreover, to explore additional ideas that may improve the task score, we also generate candidates without a modification instruction.

Specifically, let $B$ denote the total candidate budget per parent. Both generation branches receive the parent context $C_{i}^{(t)}$ and Guideline Memory $\mathcal{L}_{t}$ . We generate $\alpha B$ candidates through Direct Generation using this shared context, where $\alpha$ denotes the fraction of the budget allocated to this branch. We set $\alpha=1/2$ in our experiments. For Strategy-Guided Generation , we additionally supply a modification instruction $d_{i,n}^{(t)}$ and generate $(1-\alpha)B/N$ candidates for each of the $N$ instructions:

[Tableau] $\displaystyle x$ $\displaystyle\leftarrow\operatorname{Generate}(C_{i}^{(t)},\mathcal{L}_{t}),$ (7) $\displaystyle x$ $\displaystyle\leftarrow\operatorname{Generate}(C_{i}^{(t)},\mathcal{L}_{t},d_{i,n}^{(t)}).$ (8)

The candidates’ evaluation outcomes inform subsequent memory updates, which provide guidance for later search steps. The complete procedure is summarized in Algorithm 1 . Implementation details and prompts appear in Appendices C and D .


### 4 Experiments


#### 4.1 Experiment Settings


##### Models.

We use Qwen3-8B [ 26 ] and gpt-oss-120b [ 23 ] in the TTT-Discover framework. For ThetaEvolve, we use DeepSeek-R1-0528-Qwen3-8B [ 8 ] , abbreviated as Distill-Qwen3-8B. In our method, we keep the model weights fixed throughout the search. The same base model performs candidate generation and all memory-related operations.


##### Frameworks.

We evaluate our method within two frameworks, TTT-Discover [ 36 ] and ThetaEvolve [ 33 ] , that combine iterative search with test-time RL. We compare three settings within two frameworks: w/o TTT, which keeps model weights fixed without our TTME; w/ TTT, which updates model weights through test-time RL; and w/ TTME, which keeps model weights fixed and updates self-evolving memory. For weight adaptation, we report results from the original papers, with model weights updated through test-time RL. Without weight adaptation, we run the underlying search procedure with fixed model weights and its existing generation context. Our method also keeps the weights fixed, but updates Guideline Memory and Strategy Memory to guide subsequent generation. We retain each framework’s parent-selection rules, archive-update rules, and task verifier (settings in Appendix B ).


##### Tasks.

We evaluate five mathematical construction tasks. (1) Erdős : Erdős’s minimum overlap problem searches for density functions that certify tighter upper bounds on the minimum-overlap constant. (2) First autocorrelation inequality (AC1) : AC1 constructs a nonnegative function $f$ to minimize $\|f*f\|_{\infty}/\|f\|_{1}^{2}$ , yielding an upper bound on the first autocorrelation constant. Here, $f*f$ denotes the autoconvolution of $f$ . (3) Second autocorrelation inequality (AC2) : AC2 constructs a nonnegative function $f$ to maximize ${\|f*f\|_{2}^{2}/(\|f*f\|_{1}\|f*f\|_{\infty})}$ , yielding a lower bound on the second autocorrelation constant. (4) Third autocorrelation inequality (AC3) : AC3 allows functions with both positive and negative values and seeks a tighter upper bound using the absolute autoconvolution peak. (5) Maximal determinant problem (Hadamard) : Hadamard maximizes the normalized absolute determinant of a $29\times 29$ matrix with entries in $\{-1,+1\}$ .

The comparison with TTT shows that evolving external memory can yield better discovery results than existing weight-update methods. The comparison with search without TTT shows the benefit of adding memory to the underlying fixed-weight search procedure. Together, these results establish TTME as an effective alternative to test-time weight adaptation across the evaluated settings. Appendix E visualizes the discovered constructions.

#### 4.3 Ablation Studies


##### Combining TTME with TTT.

Having established the effectiveness of TTME with fixed model weights, we examine whether adding TTT further improves performance. We compare four settings under the TTT-Discover framework with Qwen3-8B: neither TTT nor TTME, TTT alone, TTME alone, and their combination (Table 4 ). In the combined setting, the RL-updated model performs both candidate generation and memory-related operations. TTME alone achieves the best scores on AC2 and Erdős, while adding TTT worsens both results. This comparison further supports using TTME as an alternative to TTT rather than requiring both forms of adaptation.

#### 4.4 Search Behavior Analysis


##### Candidate validity and discovery performance.

Successful discovery requires candidates that are both valid and capable of improving the task score. We consider a program valid if it compiles successfully and receives a score from the evaluator. Figure 4 compares mean validity over 50 steps and best-found scores under the TTT-Discover framework with Qwen3-8B. Both TTT and TTME improve the mean program validity rate over search without TTT. On AC1 and Erdős, TTT and TTME achieve similar validity rates, while TTME achieves better best-found scores. This suggests TTME generates more effective ideas for improving task scores.

##### Combining ideas for further search.

Beyond validity, we examine how search combines and builds on previously explored ideas under the TTT-Discover framework with Qwen3-8B. We count a candidate as a combination if it retains an idea from its parent and adds an idea previously explored outside its ancestry. The added idea must be absent from the parent. We measure how often these combinations are selected as parents for further search.

> Figure 5 : Combination of ideas in subsequent search under TTT-Discover with Qwen3-8B. TTME has a higher combination share on both tasks, with and without the $10^{-5}$ improvement requirement.

TTME selects combinations more frequently than TTT on both AC1 (10.2% versus 8.2%) and AC2 (24.7% versus 18.6%; Figure 5 ). We also count selections of combinations that improve on their own parents by more than $10^{-5}$ . TTME again has higher shares on AC1 (5.4% versus 4.8%) and AC2 (17.1% versus 13.3%). Thus, TTME not only selects combinations of existing ideas more frequently for further search, but also more frequently selects combinations that improve task scores. These observations support using external memory to combine ideas from different search branches and carry productive combinations into subsequent exploration.


### 5 Conclusion

We investigate whether evolving external memory can outperform test-time training for scientific discovery within the same discovery frameworks. We introduce TTME, which distills search experience into operational lessons and algorithmic strategies to guide a fixed-weight model. Across two frameworks, three models, and five mathematical tasks, TTME achieves better scores than TTT in every evaluated setting. Under TTT-Discover with Qwen3-8B, it reduces runtime excluding evaluation by 47.7–58.4% and FLOPs by 82.8–84.6%, including all memory-related calls. These results establish self-evolving memory as an effective and computationally efficient alternative to test-time weight updates for the discovery tasks we study.

### Appendix A Task Definitions and Evaluation

We evaluate five mathematical construction tasks from TTT-Discover [ 36 ] and ThetaEvolve [ 33 ] : three autocorrelation inequalities (AC1–AC3), Erdős’ minimum overlap problem, and the maximal determinant problem (Hadamard). The scores below retain the task’s original objective direction; Section 3.1 uses a higher-is-better convention for $s(x)$ .


#### A.1 First Autocorrelation Inequality (AC1)

For a nonzero, nonnegative step function $f$ supported on $[-\tfrac{1}{4},\tfrac{1}{4}]$ , its autoconvolution is

[Tableau] $$(f*f)(t)=\int_{\mathbb{R}}f(x)\,f(t-x)\,dx.$$

AC1 minimizes the ratio [ 21 , 2 ]

[Tableau] $$S_{\mathrm{AC1}}(f)=\frac{\lVert f*f\rVert_{\infty}}{\lVert f\rVert_{1}^{2}}.$$ (9)

For heights $a_{0},\ldots,a_{n-1}$ on $n$ equal-width intervals, this score is

[Tableau] $$S_{\mathrm{AC1}}(a)=\frac{2n\,\max_{k}(a*a)_{k}}{\left(\sum_{i=0}^{n-1}a_{i}\right)^{2}},$$ (10)

where $a*a$ denotes discrete convolution.


#### A.2 Second Autocorrelation Inequality (AC2)

For the same class of step functions, AC2 maximizes the ratio [ 21 , 3 ]

[Tableau] $$S_{\mathrm{AC2}}(f)=\frac{\lVert f*f\rVert_{2}^{2}}{\lVert f*f\rVert_{1}\lVert f*f\rVert_{\infty}}.$$ (11)

We compute the squared $L^{2}$ norm by integrating over each linear segment of the autoconvolution. A segment of width $\Delta$ with endpoint values $u$ and $v$ contributes

[Tableau] $$\frac{\Delta}{3}\bigl(u^{2}+uv+v^{2}\bigr).$$


#### A.3 Third Autocorrelation Inequality (AC3)

AC3 optimizes over real-valued step functions $f$ satisfying

[Tableau] $$\operatorname{supp}(f)\subseteq\left[-\tfrac{1}{4},\tfrac{1}{4}\right],\qquad\int_{-1/4}^{1/4}f(x)\,dx\neq 0.$$

The heights may be positive or negative. The objective is to minimize [ 33 ]

[Tableau] $$S_{\mathrm{AC3}}(f)=\frac{\lVert f*f\rVert_{\infty}}{\left(\int_{-1/4}^{1/4}f(x)\,dx\right)^{2}}.$$ (12)

For heights $a_{0},\ldots,a_{n-1}$ on $n$ equal-width intervals, the score is

[Tableau] $$S_{\mathrm{AC3}}(a)=\frac{2n\,\max_{k}\lvert(a*a)_{k}\rvert}{\left(\sum_{i=0}^{n-1}a_{i}\right)^{2}}.$$ (13)


#### A.4 Erdős’ Minimum Overlap Problem

The continuous formulation [ 10 ] uses a step function $h$ and its complement $g$ :

[Tableau] $\displaystyle h$ $\displaystyle:[-1,1]\rightarrow[0,1],$ $\displaystyle\qquad\int_{-1}^{1}h(x)\,dx$ $\displaystyle=1,$ $\displaystyle g(x)$ $\displaystyle=1-h(x),$ $\displaystyle x$ $\displaystyle\in[-1,1].$

We extend both functions by zero outside this interval and minimize the maximum overlap

[Tableau] $$S_{\text{Erd\H{o}s}}(h)=\sup_{t\in\mathbb{R}}\int_{\mathbb{R}}h(x)g(x+t)\,dx.$$ (14)

For heights $h_{0},\ldots,h_{n-1}$ on $n$ equal-width intervals, the constraints are

[Tableau] $$0\leq h_{i}\leq 1\quad(i=0,\ldots,n-1),\qquad\sum_{i=0}^{n-1}h_{i}=\frac{n}{2}.$$

The score is

[Tableau] $$S_{\text{Erd\H{o}s}}(h)=\frac{2}{n}\max_{k=-(n-1),\ldots,n-1}\sum_{\begin{subarray}{c}0\leq i<n\\ 0\leq i+k<n\end{subarray}}h_{i}(1-h_{i+k}).$$ (15)


#### A.5 Maximal Determinant Problem (Hadamard)

The maximal determinant problem searches for a matrix with the largest absolute determinant [ 24 ] . We use the search space

[Tableau] $$H\in\{-1,+1\}^{n\times n},\qquad n=29.$$

We maximize the normalized score used in ThetaEvolve [ 33 ] :

[Tableau] $$S_{\mathrm{Had}}(H)=\frac{\lvert\det H\rvert}{2^{28}\cdot 7^{12}\cdot 342}.$$ (16)

The evaluator computes the determinant using exact integer arithmetic.

#### C.2 Memory Updates

We update both memories every $K=2$ search steps using outcomes collected since the previous update.


##### Guideline Memory.

- 1. Summarize recent outcomes. The outcome summary covers recent attempts across parents, including valid results, their scores, and execution or validity failures.

- 2. Distill guidelines. The same fixed-weight base model reads the outcome summary and current guidelines, then proposes up to three lessons per update, at most one for failure avoidance. Each lesson specifies a trigger, explains the mechanism, and gives a concrete action. The parser extracts the lesson text from the response.

- 3. Match and merge. For each proposed lesson, we compute its Jaccard similarity to stored guidelines using lowercased word-token sets. A similarity of at least $0.5$ counts as a match: we retain the stored text, increment its recurrence count, and refresh its last reaffirmed step. An unmatched lesson enters memory with count one and the current step.

- 4. Remove stale entries and enforce capacity. Guidelines expire when more than 20 search steps have passed since their last reaffirmation. Among the remaining entries, we retain at most 24, ranked by recurrence count with recency breaking ties.

- 5. Include guidelines in generation prompts. Both Direct Generation and Strategy-Guided Generation receive the retained guidelines as shared context. Each prompt displays up to 240 characters per guideline; memory stores the full lesson text.


##### Strategy Memory.

- 1. Select valid improvement cases. We select evaluated parent–child pairs in which the child passes the task verifier and improves on its parent. Both scores must be finite; improvement follows the task’s objective direction, consistent with $s(\text{child})>s(\text{parent})$ in Section 3.3 .

- 2. Extract experience notes. The same fixed-weight base model reads the parent and child programs, their code diff, and evaluation results. It writes an experience note describing the algorithmic idea behind the change and its application conditions. Each note retains a reference to its source case; a change containing independent ideas can yield separate notes.

- 3. Group notes into strategy families. The model compares new notes with existing strategy entries and groups notes that share an underlying algorithmic idea into the same family. It creates a new family for a distinct idea and preserves implementation differences as variants within each family.

- 4. Consolidate and store strategy entries. For each family receiving new notes, the model combines those notes with the previous entry, if one exists, to update the description of the shared idea, application conditions, and implementation variants. We store the entry, its summary, and the supporting notes with source references. Families without new notes retain their existing entries.
