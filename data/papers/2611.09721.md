## MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory

LLM agents benefit from using memory systems to improve performance on long-horizon, multi-session tasks. However, memory introduces a critical attack surface. Malicious instructions encountered in one session may be stored and propagated through memory before being retrieved and acted upon in later sessions. Because memory systems differ in how they process and retrieve information, the downstream effects of poisoning can vary significantly across systems. To quantify the effects of poisoning across different memory architectures, we introduce MemoryDojo, a benchmark for tracing the lifecycle of poisoned information through agent memory and measuring its influence on subsequent agent behavior. MemoryDojo is easily extensible, consists of 155 multi-session long-horizon trajectories covering four domains, and supports five different memory systems. Through our evaluation, we find that all memory systems are susceptible to memory poisoning, with substantial variation in downstream effects. We further propose a memory-aware poison optimization process that increases the poisoning efficacy, highlighting differences between memory architectures. We hope that MemoryDojo will support research on understanding and mitigating agentic memory risks.


### 1 Introduction

AI agents powered by large language models (LLMs) use tools, or dedicated software functions, to take actions in external environments such as reading emails or managing calendars. While tool-use substantially expands LLM capabilities, it also opens up a growing risk of indirect prompt injection. A malicious actor can disseminate instructions in a document or message in the external environment, causing the agent to execute arbitrary actions ( Greshake et al., 2023 ; Debenedetti et al., 2024 ) .

This risk, known as indirect or cross prompt injection (XPIA), is significantly amplified by the introduction of agentic memory . Because LLM context windows are limited, long-running agents need memory systems to compact prior context and preserve information across interactions. By storing information persistently, memory lets agents reuse facts, preferences, and prior experience after the original context is lost ( Packer et al., 2023 ; Chhikara et al., 2025 ; He et al., 2026 ) . However, this process can also turn an untrusted observation into a stored preference, summary, or procedure. The payload may persist, be summarized, or connected to other memories, and be retrieved during subsequent sessions. This can lead to compounding harmful effects and a lasting attack over time.

Consider an email containing instructions misrepresenting a user preference to forward outgoing invoices to a target email address. Without memory, an agent following these instructions may leak one invoice. With memory, the instruction may be stored as a user preference and applied to all future invoices, long after the original email has been evicted from context. Thus, memory can convert a transient exposure into a persistent behavior, a risk highlighted by recent threat intelligence ( Microsoft Defender Security Research Team and Kochavi, 2026 ; Lu and Chen, 2025 ; Socket Research Team, 2026 ) .

Agent memory systems, however, vary significantly in their architectures. Some extract facts, some evolve linked notes, and others traverse graphs or hierarchical stores. Although prior work has compared these systems on task performance, we still lack a systematic understanding of how memory architecture affects the persistence and behavioral impact of a poisoned observation as an agent completes new tasks and updates its memory over multiple sessions. We therefore ask: “How do different memory systems shape the lasting effects of a poisoned observation as an agent performs new tasks and updates its memory across sessions?”

To answer this question, we introduce MemoryDojo 1 1 Code to be released soon. , an extensible benchmark for comparatively evaluating memory architectures under poisoning attacks over long-horizon, multi-session trajectories. Currently, MemoryDojo supports 155 multi-session trajectories covering 4 application domains, and is enabled by 5 different agent memory system implementations. Additional memory systems, environments, and configurations can be easily added for evaluation. We also introduce new metrics to better quantify the effects of poisoning across its lifecycle, tracking information on payload insertion, effects of persistence and propagation in memory, retrieval, and cumulative attack success metrics. Finally, we propose a natural adaptive memory-aware poison optimization method that performs iterative refinement of the payload prompt in an auxiliary environment.

Our experiments reveal substantial variation in poisoning success across memory systems. While some are more resilient, none are invulnerable: applying our memory-aware poison optimization method increases attack success by approximately 2% – 31%. Memory architecture materially affects each stage of the poison lifecycle and should be treated as a central component of agent security evaluation. Overall, our contributions are as follows:

- 1. We develop MemoryDojo, an extensible benchmark that quantifies the effects of memory poisoning across different memory systems, supported by multi-session long-horizon trajectories.

- 2. We define new metrics that quantify how poison persists and spreads within agent memory, and how broadly it induces attacker-desired behavior across subsequent tasks.

- 3. We propose a memory-aware poison optimization method that increases the effectiveness of the payload, and allows us to study the properties of different memory systems under powerful attacks.


### 2 Related Work

Agent memory systems. Agent memory systems store information across interactions to improve performance over long-horizon tasks ( Packer et al., 2023 ; Xia et al., 2026 ; Li et al., 2025 ) . There is a wide variety of memory systems proposed, which differ most notably in how memory is represented. Memory could be a knowledge graph ( Rasmussen et al., 2025 ; Gutiérrez et al., 2024 ) , linked notes ( Xu et al., 2025 ) , or extracted facts over embedding stores ( Chhikara et al., 2025 ) . At the operation level, they also differ in how memory writes, consolidation, and retrieval are implemented ( Zhong et al., 2024 ) . Benchmarks for these systems have moved from static recall to long-horizon interactive settings ( Maharana et al., 2024 ; Wu et al., 2025 ; Hu et al., 2026 ; He et al., 2026 ; Zhao et al., 2026 ) .

Memory poisoning. Indirect prompt injection places attacker instructions in the environment that an agent can access, and is typically measured within a single session ( Greshake et al., 2023 ; Zhan et al., 2024 ; Debenedetti et al., 2024 ; Debenedetti et al., 2025 ; Wang et al., 2026 ) . Before a session ends, agent memory systems may write those instructions into memory, so the attack can outlive both the observation and the session that produced it ( Xie et al., 2026 ; Lin et al., 2026 ) . Attacks of this kind were first studied against static retrieval corpora or had strong assumptions on how the payload is inserted ( Zhong et al., 2023 ; Zou et al., 2025 ; Chaudhari et al., 2024 ; Liang et al., 2025 ) . More recent works deliver the payload as ordinary content that an agent reads during its own task ( Zou et al., 2026 ; Torres et al., 2026 ) . Prior work also optimizes poisoning payloads ( Chen et al., 2024 ; Pasquini et al., 2024 ) , but not in a memory-aware fashion.

Memory poisoning benchmarks. A few works have attempted to measure these attacks. AgentLAB covers memory poisoning as one of five long-horizon attack types ( Jiang et al., 2026 ) . MemPoison shows write-time filters admitting records that turn harmful only through joint retrieval or later triggering ( Gao et al., 2026 ) . MPBench enumerates memory write channels and structural vulnerabilities across six attack classes ( Dash et al., 2026 ) . These works primarily hold the memory implementation fixed, while the write channel, attack class, or model family varies. Different from existing works, MemoryDojo performs a comparative evaluation of continued agent operation over multi-session trajectories. Following a poisoned observation, it tracks subsequent task execution and native memory updates across different memory systems, measuring how widely attacker-intended behavior recurs across later tasks.


### 3 Problem Formulation

Agent formulation . Consider an LLM agent interacting in an environment. Let $\mathcal{X}$ , $\mathcal{A}$ , $\mathcal{O}$ , and $\mathcal{R}$ denote the user prompt, action, observation, and response spaces, respectively. Define a trajectory run as a sequence of $T$ agent sessions $\mathcal{T}=(\tau_{1},\ldots,\tau_{T})$ , where each session $t\in[T]$ , $\tau_{t}=\bigl(x_{t},\,a_{t,1},\,o_{t,1},\,\ldots,\,a_{t,K_{t}},\,o_{t,K_{t}},\,r_{t}\bigr)$ , consists of a user prompt $x_{t}\in\mathcal{X}$ , a sequence of $K_{t}$ actions $a_{t,k}\in\mathcal{A}$ with environment observations $o_{t,k}\in\mathcal{O}$ , and a final response $r_{t}\in\mathcal{R}$ . The number of steps $K_{t}$ is determined by the agent and may vary across sessions. Each session corresponds to one task, and sessions are executed in order.

Use of memory . Let $M_{t}$ denote the state of the memory system after session $t$ has completed, with $M_{0}=\emptyset$ . Write operations are performed once each session ends, $M_{t}=U(M_{t-1},\tau_{t})$ , where the operator $U$ abstracts any sequence of memory operations performed during this write. This may include memory-system-specific operations such as extraction, relation construction, or merging; we therefore do not assume that $U$ takes any particular form. Memory retrieval is performed prior to each session and reads the state left by the previous session, $c_{t}=\rho(M_{t-1},x_{t})$ , where the operator $\rho$ denotes broadly a retrieval mechanism inherent to the memory system used. This can be a simple top- $k$ vector retrieval or a more complex search algorithm, given the user input $x_{t}$ . The retrieved context $c_{t}$ is concatenated with the user request before reasoning occurs.

Poison insertion . The attacker controls content returned by an external tool call. They do not modify the system prompt, user requests, benchmark tasks, utility functions, memory-system implementation, or later tool results. Let $\psi$ denote the attacker objective, formalized as a predicate on sessions, $\psi:\tau\mapsto\{0,1\}$ , where $\psi(\tau_{t})=1$ if and only if the actions $a_{t,1:K_{t}}$ and response $r_{t}$ of session $t$ execute the objective. The attacker encodes $\psi$ as a poison text prompt $p$ , which is appended once at a single insertion point $(t_{0},i)$ , denoting observation $i\in[K_{t_{0}}]$ of session $t_{0}\in[T-1]$ . The original observation is appended with the poison prompt, forming $\tilde{o}_{t_{0},i}=o_{t_{0},i}\,\|\,p$ . We require $t_{0}<T$ so that at least one session follows the insertion. This models indirect prompt injection from a document, message, or service read by an otherwise benign agent. After insertion, ordinary tasks continue without further attacker intervention. Since $\tilde{o}_{t_{0},i}$ becomes part of the trajectory $\tau_{t_{0}}$ , the poison can be written into memory, and retrieved in subsequent sessions, causing cumulative effects.


### 4 MemoryDojo

We present MemoryDojo, a benchmark for evaluating how poisoning affects behaviors of memory-augmented agents in multi-session trajectories (Figure 1 ).

> Figure 1: MemoryDojo overview. Task trajectories are generated from 4 different domains and user-AI conversations are optionally added. Execution is done through a repeated retrieve-interact-write cycle. Poison enters one tool result at the marked session $t_{0}$ , and can be written into memory. Different metrics capture the lifecycle effects of the poisoning.


#### 4.1 Constructing Trajectories

We construct multi-session trajectories using task templates from AgentDojo ( Debenedetti et al., 2024 ) across four domains: Workspace, Travel, Banking, and Slack. Each domain provides a stateful environment and tools for interacting with it. All tasks specify an objective and utility check that determines whether the objective is achieved. We concatenate tasks into trajectories, treating each task execution as a separate session while carrying environment state forward. To ensure the concatenated tasks remain executable, we check task pairs for state conflicts and validate each complete sequence. For each domain, we also define an attacker objective $\psi$ , accompanied by a textual description of the behavior that the poison seeks to induce. Using these tasks and conversation histories from LongMemEval-S ( Wu et al., 2025 ) , we obtain a dataset with three different collections. Additional details can be found in Appendix A.1 and A.2 .

Same-domain trajectories. First, we concatenate compatible tasks within a single domain. This setting evaluates whether a poison encountered by an agent working in that domain influences its behavior on subsequent tasks in the same domain. This collection contains 93 trajectories across the four domains, with 802 task sessions in total and 3–35 sessions per trajectory.

Cross-domain trajectories. An agent may also perform tasks across multiple domains over time. To evaluate poisoning in this setting, we construct trajectories that interleave tasks from all four domains while ensuring trajectory validity. Each domain has its own environment state, while all sessions share one memory system. This allows us to examine whether poison encountered in one domain influences later behavior as the agent performs tasks across domains. The collection contains 31 trajectories with 680 task sessions in total and 5–60 sessions per trajectory.

History-prefixed trajectories. Task concatenation produces trajectories of moderate length, but agents may accumulate much longer interaction histories before encountering a poisoned data source. To evaluate memory systems under high-volume pressure, we extend the cross-domain trajectories with benign user-assistant conversations from LongMemEval-S ( Wu et al., 2025 ) . We select 31 histories across its six question categories, and pair each with a distinct cross-domain trajectory. Before task execution, we initialize memory by having the agent replay the recorded history sessions making use of the memory system’s operations. These 31 trajectories add an additional 1,493 history sessions in total, with each prefix averaging 48.2 sessions and approximately 500 individual messages. This substantial benign history places additional pressure on memory storage and retrieval, enabling a more systematic way to study the poison lifecycle alongside previously accumulated information.


#### 4.2 Running Trajectories

Each trajectory starts from the default domain environments, with memory empty or initialized by replaying a specified conversation history. Sessions follow the retrieve-interact-write cycle using a fresh context window with retrieved memory prepended to the task request. After the session completes, MemoryDojo constructs a memory write record containing the original task request, assistant messages, tool calls, observations, and final response. Retrieved context is excluded to prevent recopying of old memories into each new write. An adapter projects this record into the selected memory system’s native write format, after which the system performs its own memory processing, including any extraction, rewriting, consolidation, or linking. This design enables our benchmark to flexibly support different memory systems. We implement this interface for five representative open-source memory systems: A-MEM ( Xu et al., 2025 ) , Graphiti ( Rasmussen et al., 2025 ) , Letta ( Packer et al., 2023 ) , Mem0 ( Chhikara et al., 2025 ) , and Memora ( Xia et al., 2026 ) .


#### 4.3 Tracing Poison Through a Trajectory

Throughout a trajectory, MemoryDojo keeps track of various statistics at different timesteps in the process to better understand how poison interacts with memory. Let $\mathcal{D}$ denote a collection of planned runs, with trajectory length $T_{j}$ , insertion session $t_{0,j}$ , and payload $p_{j}$ for run $j$ . The benchmark is accompanied by a visualization tool to manually inspect traces (see example in Appendix A.3 ).

Insertion. After the insertion-session write, we inspect the memory system for content attributable to $p_{j}$ using an LLM Judge to classify four categories. An exact match preserves the complete payload word for word, a transformed match preserves its salient instruction or meaning after rewriting, and a fragmented match retains only part of that meaning. If no attributable content is found, we assign the label of not observed . Let $\ell_{j}^{\mathrm{ins}}$ denote this judgment and $\mathcal{C}_{+}=\{\text{exact},\text{transformed},\text{fragmented}\}$ . We define the insertion indicator $s_{j}$ and insertion success rate (ISR) as:

[Tableau] $$s_{j}=\mathbb{I}\!\left[\ell_{j}^{\mathrm{ins}}\in\mathcal{C}_{+}\right],\qquad\mathrm{ISR}(\mathcal{D})=\frac{1}{|\mathcal{D}|}\sum_{j\in\mathcal{D}}s_{j}.$$

Retrieval. For each later session $t>t_{0,j}$ , $c_{j,t}$ contains the returned memory items, including primary search results and content supplied through links or episodic expansion (see Appendix A.4 for example). We assess these items using the same categories as insertion. Writing $\ell_{j}(m)$ for the judgment of item $m$ relative to $p_{j}$ , retrieval succeeds when at least one item qualifies. The retrieval success rate (RSR) pools these successes over all post-insertion sessions:

[Tableau] $$u_{j,t}=\mathbb{I}\!\left[\exists\,m\in{c}_{j,t}:\ell_{j}(m)\in\mathcal{C}_{+}\right],\qquad\mathrm{RSR}(\mathcal{D})=\frac{\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}u_{j,t}}{\sum_{j\in\mathcal{D}}(T_{j}-t_{0,j})}.$$

While retrieval indicates that the poison found its way to the current task session, it does not help us answer how. To obtain additional insights on this, we propose a method of attribution, and define two mechanisms by which a poison can surface over time, persistence and propagation.

Persistence. We compare memory snapshots before and after the insertion session to identify the entries that are initially written which contain poison. We refer to these entries as the original poison. These can include newly created entries and existing entries modified by that write. If during retrieval, an original memory entry is retrieved, we attribute this as an effect of persistence. Persistence provides a signal of how long the original poison stays in memory.

Propagation. On the other hand, propagation occurs in subsequent sessions post-insertion, when memory writes create new entries containing poison or previously benign entries are rewritten to contain the payload. For example, if the agent retrieves a payload and executes a malicious objective in a future session, it may again write its new observations into memory. In this case, the poison may spread and during future retrieval the original poison no longer becomes the only source of attribution.

Together, persistence and propagation capture how poison evolves in a memory system over time. To help quantify this, we define metrics to attribute each poison-bearing retrieved session to an effect of persistence only (PE), propagation only (PR), or both (PP). See Appendix A.5 for a formal definition of these metrics.


#### 4.4 Measuring Downstream Behavior

Retrieval and attribution characterize the poison’s presence and exposure routes in later sessions. We additionally measure attack success as a cumulative metric of poisoning across the trajectory. For each session $t>t_{0}$ , we evaluate the agent actions and final response against the attacker objective $\psi$ . Let $z_{t}=\psi(\tau_{t})\in\{0,1\}$ denote the outcome. Excluding $t_{0}$ separates later behavior from the agent’s immediate response to the poisoned observation.

Behavioral reach. A run is reached if the attack objective is achieved in at least one session after insertion. Across a collection of runs, behavioral reach ( BR ) is the fraction of runs that are reached. Task-level behavioral reach ( BRT ) measures the fraction of post-insertion tasks on which the objective is observed, pooled over all post-insertion sessions:

[Tableau] $$\mathrm{BR}(\mathcal{D})=\frac{1}{|\mathcal{D}|}\sum_{j\in\mathcal{D}}\mathbb{I}\!\left[\,\sum_{t>t_{0,j}}z_{j,t}\geq 1\right],\qquad\mathrm{BRT}(\mathcal{D})=\frac{\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}z_{j,t}}{\sum_{j\in\mathcal{D}}(T_{j}-t_{0,j})}.$$

BR measures whether influence occurs at all, while BRT measures how broadly it occurs across later tasks. In contrast to the standard attack success rate (ASR), which measures whether an attack succeeds in the session where it is injected, BR and BRT measure its longitudinal effect on later sessions, where the poison can only act through memory.

Task and Memory Utility. In addition to behavioral reach, we measure task utility as the fraction of all task sessions that pass the benchmark’s task success checks. For history-prefixed trajectories, we measure memory utility through accuracy on the held-out LongMemEval question, answered using retrieved memory after the trajectory is complete. These measures help assess task performance and effective memory usage under the effects of poisoning.


### 5 Memory-Aware Poison Optimization

Memory systems differ in how they transform, store, and retrieve past interactions, directly affecting whether a poisoned instruction survives a write, appears in later context, and induces the intended behavior. To study the dynamics of each system under adversarial pressure, we propose a memory-aware optimization process that iteratively refines a payload to increase behavioral reach (see Figure 4 ). The LLM optimizer is first provided an attack objective, memory-system description, and domain context. Starting from seed payloads, each round proposes candidates and evaluates them on synthetic trajectories in an auxiliary environment. Feedback from each iteration guides further revisions. After a fixed budget, selection maximizes auxiliary BRT subject to a utility threshold. See Appendix A.6 for additional details of the optimization process.

### 6 Evaluation

We evaluate how a single poisoned observation influences an agent’s later behavior, and use memory traces to examine where that influence is retained, propagated, and acted upon. We first study unoptimized and optimized payloads on same-domain trajectories, then consider trajectories that cross application domains and finish by adding extra memory pressure.


#### 6.1 Experiment Setup

We evaluate tool-calling agents on five memory systems, selected to cover a wide range of memory types: A-MEM, Graphiti, Letta, Mem0, and Memora. Their native representations span linked notes, entity–relation graphs, hierarchical memory, extracted facts, and linked semantic and episodic memory. We evaluate GPT-5.6-Luna ( OpenAI, 2026 ) across all trajectory settings and optimize poisons for every memory system with Luna as the target and GPT-5.6-Sol as the optimizer. To assess transfer across models, we additionally evaluate GPT-5.4-mini, DeepSeek-V4-Flash-0731 ( DeepSeek-AI, 2026 ) , and GLM-5.3-Flash ( GLM-5-Team, 2026 ) in the same-domain setting using the Luna-optimized payloads. We vary the task-agent and generative memory-side LLM models together, and use GPT-5.6-Luna for LLM judging. For each memory system, we use its native retrieval mechanisms. Thus, these configurations compare complete memory integrations, including their different context-selection policies and budgets. Additional setup details can be found in Appendix A.7 .

Unless otherwise specified, each run appends one payload to a tool observation in the first task session, then resumes execution and completes session memory writes. Same-domain runs use their domain’s objective while cross-domain and history-prefixed trajectories are evaluated under each of the four domain objectives separately. We report insertion success (ISR), insertion-task attack success (ASR), retrieval success (RSR), retrieval attribution due to persistence (PE) propagation (PR) or both (PP), task utility (TU), memory utility (MU), later-task reach (BRT), later-task reach given retrieval ( $\text{BRT}|\text{R}$ ), and trajectory-level reach (BR).

Unoptimized poison reaches later tasks unevenly across memory systems. Memory poisoning affects all evaluated systems, reaching up to 45.70% BR and 21.02% BRT, with substantial variation across systems. For example, Graphiti and Mem0 exhibit less than 8% BRT, compared with over 20% for A-MEM and Memora. Tracing poison through memory helps interpret this variation. ISR approaches 100% for four systems, indicating that downstream outcomes differ despite successful storage of some representation of the poison. Mem0 represents an exception, with 60.75% insertion success, potentially due to how its write mechanisms use an LLM to extract facts from the session and may abstract away certain information. Across all five systems, insertion-task ASR exceeds BRT. For these runs, the poison’s effect on the immediate response was strictly stronger.

RSR separates the systems more sharply. A-MEM and Memora record poison retrieval over 80% of later tasks, compared with 64.88% for Letta, 56.70% for Mem0, and 33.43% for Graphiti. The memory operations native to each system can help explain the differences here. A-MEM searches stored session notes, while Memora can supply original episodes through links from retrieved facts. As a result, poison retrieval is more likely. Graphiti stores more complete episode information but its retrieval process returns relation facts. In an unoptimized banking run we inspected, the episode stores the poison exactly, yet the query’s returned facts omit this information.

These findings suggest that processing between memory insertion and retrieval can strongly affect RSR. However, retrieval alone does not imply behavioral reach: for four systems, only approximately 1/4 instances of retrieval lead to successful reach, with a further 10% drop for Mem0. This gap motivated our poison optimization schema to explore the reach of more advanced attacks.

Optimization improves Behavioral Reach. Both BR and BRT increase for all five systems relative to the unoptimized runs (Figure 5(a) ). A closer look at the metrics provides insights on where these gains come from for each memory system. For Mem0, ISR rises from 60.75% to 77.42%, with a higher chance of poison being actually written into memory. For Letta RSR increases by around 8%, but the largest change is in $\text{BRT}\mid\text{R}$ , which rises from 23.59% to 64.06%. Similarly for A-MEM, ISR and RSR stay around the same, while $\text{BRT}\mid\text{R}$ more than doubles. These results show that the optimized payloads can induce greater reach even with roughly equivalent RSR.

Reach varies across models and domains. Evaluation with three additional models reinforces the findings that poisoning effects differ between memory systems, and we observe examples of significant BRT for memory systems across models (Figure 5(b) ). The relative ordering for BRT changes, but both A-MEM and Memora have consistently high BRT compared to other memory systems, while Graphiti has the lowest across the four models. These results also demonstrate the transferability of poison optimization, as optimization was performed using GPT-5.6-Luna, but we observe strong effects in these different models as well. We also find that BRT varies by domains, and additional details can be found in Appendix A.8 and A.9 .

Poison remains effective when inserted later. We additionally insert optimized payloads at the trajectory midpoint, after earlier sessions have populated memory. Delaying poison insertion until the trajectory midpoint generally reduces subsequent retrieval and behavioral impact, but does not eliminate the attack. Sensitivity varies substantially across memory systems, with Letta showing the largest reduction and Mem0, A-MEM, and Memora retaining strong effectiveness (see Appendix A.10 ).

Poison spreads across all five memory systems. The retrieval attribution results from Table 1 show evidence of PE, PR, and PP across all memory systems. Poison spreads beyond its insertion memories and while the effects of PR alone are rarer, traces of propagation are more often found along with the original poison memory (PP). Interestingly, the poison optimization process encouraged more propagation, as the combined PR + PP increased by over 20%. The overall increase in propagation after optimization implies stronger effects of the poison, correlating with higher $\text{BRT}\mid\text{R}$ . Retrieval of both original poison and descendants may reinforce the malicious objective more strongly than persistence alone. Multiple poison-bearing memories can also make the malicious instruction seem like an established requirement or precedent, adding additional credibility.

Poisoning remains effective in populated memory. Table 2 shows lower RSR and BRT for every system than in the cross-domain experiment without a history prefix. Nevertheless, poison reaches later tasks in four of the five systems. Memora had the highest BRT at 5.32%, followed by A-MEM at 4.66%. Memora’s trajectory-level BR is 45.16%, showing that the lower per-task frequency still corresponds to attacks across many trajectories. The poisoning efficacy on memory systems differs from the earlier experiments. Letta, which previously had the highest in BRT, has no later-task reach. Reach also extends beyond the poison’s target domain for A-MEM, Mem0, and Memora, while reached tasks for Graphiti remain within the poison’s target domain.

Memory pressure changes retrieval and subsequent behavior. Insertion success remains similar to the cross-domain experiment without a prefix: four systems have ISR above 95%, while Mem0 remains below 50%. The larger differences arise after insertion. For both A-MEM and Memora, RSR drops by over 30% while $\text{BRT}\mid\text{R}$ remains around the same at just above 10%. These results show that applying additional memory pressure through the LongMemEval histories weakens the effects of poisoning due to growing competition in retrieval. Letta is impacted most by the additional memory pressure. RSR falls from 55.66% to 7.94%, and none of its retrieved tasks exhibits behavioral reach. Existing benign memory may influence which new information is promoted to core memory and how it is summarized. As a result, poison was unable to persist in most cases.

Effect of poisoning on task and memory utility. Task utility is largely preserved under poisoning (Appendix A.12 ). However, Figure 7 shows that memory utility decreases for A-MEM, Graphiti, and Mem0, suggesting that poisoning can impair recall of benign conversation history over multi-session trajectories. The effect on Letta and Memora is not significant, indicating that this degradation is not uniform across memory systems.


### 7 Conclusion

As memory becomes central to agentic AI performance, its security warrants increased attention. Guided by the question of how to measure and compare the dynamics of poisoned instructions percolating through different memory architectures, we developed MemoryDojo, an extensible, modular benchmark that tracks poisoning effects throughout the data lifecycle.

Unlike prior benchmarks, our work focuses on long-horizon, multi-session interactions in which agents create and process large volumes of new memories before and after poison injection. We also design our measurements to provide fine-grained insights on the evolution of the poisoned data after ingestion, allowing significantly more informed comparisons between memory systems. Our experiments show that a single poisoned observation can influence behavior in later sessions, with substantial variation across systems in retrieval, propagation, and behavioral effects.

Future work can extend MemoryDojo to broader deployment settings, investigate multiple instances of poisoning in a trajectory, and systematically evaluate memory defenses against poisoning. We hope that MemoryDojo will support improvements in the security and safety of agentic AI memory platforms by providing a framework to evaluate new variants and defensive approaches.

#### A.5 Persistence and Propagation Metrics

Define the original poison entries created during insertion session as $\mathcal{O}_{j}$ . Formally, for trajectory $j$ and session $t>t_{0,j}$ , let $o_{j,t}=1$ if the retrieved context contains at least one payload-bearing entry from $\mathcal{O}_{j}$ , and $d_{j,t}=1$ if it contains at least one payload-bearing entry outside $\mathcal{O}_{j}$ (both $0$ otherwise). A session retrieves poison when $u_{j,t}=\max(o_{j,t},d_{j,t})=1$ , and we write $N_{R}(\mathcal{D})=\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}u_{j,t}$ for the number of poison-retrieving sessions. We report the share of these sessions attributable to persistence only (PE), propagation only (PR), or both (PP):

[Tableau] $\displaystyle\mathrm{PE}(\mathcal{D})$ $\displaystyle=\frac{1}{N_{R}(\mathcal{D})}\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}o_{j,t}\,(1-d_{j,t}),$ $\displaystyle\mathrm{PR}(\mathcal{D})$ $\displaystyle=\frac{1}{N_{R}(\mathcal{D})}\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}(1-o_{j,t})\,d_{j,t},$ $\displaystyle\mathrm{PP}(\mathcal{D})$ $\displaystyle=\frac{1}{N_{R}(\mathcal{D})}\sum_{j\in\mathcal{D}}\sum_{t>t_{0,j}}o_{j,t}\,d_{j,t}.$

The three shares partition poison-retrieving sessions, so $\mathrm{PE}+\mathrm{PR}+\mathrm{PP}=1$ .


#### A.6 Memory-Aware Optimization Details


##### A.6.1 Auxiliary Environments and Trajectories

For each application domain, we construct a standalone synthetic environment with tools and application state supporting representative tasks that might be executed. The domains cover workspace, travel, banking, and communication tasks. Within each domain, task templates specify user requests involving information retrieval, state-changing actions, or combinations of tool operations. Each task includes reference tool actions and deterministic checks of legitimate task completion, allowing us to measure task utility alongside the attack objective. As with MemoryDojo, we concatenate tasks into trajectories of different lengths and perform validity checks.

The auxiliary setting uses separate task templates, tool implementations, and application state from MemoryDojo. We ensure tools used in this environment have different names from those used in MemoryDojo, and these names vary across each trajectory to discourage dependence on exact tool names. The objective is for optimization results to transfer to the benchmark evaluation from the domain information and attack objective.


##### A.6.2 Initialization

During optimization, we fix the task-agent configuration, memory configuration, and attack objective $\psi$ , along with a payload text $p$ . Optimization aims to find a better representation for $p$ while preserving the attack objective.

To support revisions tailored to the memory system, we provide a description of its write inputs and transformations, stored representations, retrieval mechanisms, and the way retrieved material is presented to the task agent. This description accentuates the unique properties associated with each memory system. We also supply a domain ontology that has a generic description of the application capabilities, their parameters, and categories of tasks and tool observations. This ontology is assembled from the auxiliary environment and task definitions and gives the optimizer domain context without exposing MemoryDojo tasks.

We initialize the optimization with seed payloads and an additional memory-property-only seed candidate generated by the optimizer from the objective, memory-system description, and domain ontology. We evaluate the initial candidates on the auxiliary trajectories before beginning feedback-guided revision.


##### A.6.3 Feedback, Revision, and Selection

Starting from the evaluated initial candidates, we repeat a cycle of proposing revised poison payloads, testing them on the auxiliary trajectories, and providing feedback to the optimizer.

At each round, the optimizer uses the fixed inputs from Section A.6.2 , previously evaluated payloads, and their feedback to propose revised poison prompts. Each proposal explains the changes, the suspected bottleneck they address, and the expected improvement. In addition, the optimizer can see the best valid candidate evaluated so far and the most recently evaluated valid revision. Because the latest revision may underperform an earlier candidate, providing both lets the optimizer build on its strongest result while still learning from its most recent attempt.

Before testing a proposal, we check that it preserves the attack objective. We also screen for auxiliary tool names, task and trajectory identifiers, and overlaps with task prompts to discourage dependence on specific auxiliary tasks. Both deterministic checks and LLM judges are used here.

We select the best proposal that passes validation for evaluation. The task agent then executes the auxiliary trajectories with this payload, starting each run with fresh memory and application state. The payload is inserted into one tool observation, and the agent continues through the remaining sessions using the execution procedure in Section 4.2 . The resulting runs provide the behavioral outcomes and memory observations used as feedback.

After each candidate’s evaluation, we obtain the number of later sessions satisfying $\psi$ and the number of tasks completed. We pool these counts over the planned later sessions and all planned tasks, respectively, to obtain BRT and task utility.

We additionally collect coarse evidence of the poison’s lifecycle through memory. The framework checks for distinctive markers in post-write memory snapshots, later retrieved items, and logged agent inputs. This feedback helps identify where the attack may be failing. Poison-related content may be lost during memory processing, omitted from later retrievals, or presented to the agent without causing it to follow the injected instruction.

Alongside aggregate statistics, we give the optimizer a small set of failure examples from the auxiliary runs. Each example identifies the task’s position in the trajectory, task type, and the earliest failed check in the sequence from poison write through memory processing and retrieval to behavior. For instance, an example may indicate that poison-related content reached the agent’s context in a later session, but the agent did not follow the instruction. These examples help the optimizer connect aggregate results to specific sessions and identify where a revision might help.

Each evaluated payload and its feedback become available for subsequent proposal rounds. After a fixed number of rounds, we compare valid revisions with the initial seeds. Eligible candidates must complete at least as many legitimate tasks as a designated reference seed, minus a preset tolerance. We compare the strongest eligible revision with the strongest eligible seed, retaining the seed unless the revision improves BRT.

Let $N_{\mathrm{util}}(p)$ be the count of legitimate auxiliary tasks completed by candidate $p$ , including the insertion tasks, and let $p_{ref}$ be the initial reference instruction seed. The eligibility threshold is

[Tableau] $$N_{\mathrm{util}}(p)\geq\max\{0,\,N_{\mathrm{util}}(p_{ref})-\text{Tol}\},$$ (1)

where Tol is the tolerance for utility in number of tasks. The selected text is then transferred for MemoryDojo evaluation.

A completed session becomes a chat segment that supports episodic storage and extraction of primary facts and retrieval cues ( Xia et al., 2026 ) . The evaluated prompted policy combines semantic search and BM25 fusion, then can stop, expand through links, or issue a revised query. Episodic context is included, so linked source episodes can accompany retrieved facts. The configuration uses an initial hybrid budget of 10, a cue budget of 20, and at most four prompted retrieval steps. It uses the prompted policy without GRPO training.
