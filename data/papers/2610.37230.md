# TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving

- **arXiv** : 2610.37230 — https://arxiv.org/abs/2610.37230

## Résumé

Agentic services alternate between model inference on clustered GPUs and external tools on distributed CPUs. In this scenario, existing systems (1) overlook tool-return readiness in service evaluation, wasting limited resources, and (2) use heuristic strategies to decide admission and placement on GPUs, resulting in suboptimal scheduling decisions. To bridge this gap, we present TAO, a tool-aware joint scheduling framework for LLM-based agentic serving. Its value interface combines near-term tool readiness, node-specific cache credit with time-aware decay, and token footprint; a dynamic program jointly selects and places waiting sessions under capacity constraints. Across the 12 reported model-workload-concurrency settings, TAO reduces latency by up to 26.8%, reduces mean time to first token (TTFT) by up to 36.3%, and increases decode throughput by up to 29.5% relative to the best evaluated state-of-the-art baseline for each metric.

### 1 Introduction

Recent advances in language models have expanded their use beyond basic chatbots to complex agents, making CPU-based tool execution a substantial source of latency alongside GPU-based inference ( Qiao et al., 2026 ; Huang et al., 2026 ) . Specifically, an agent operates through an agent session that alternates between LLM inference and external tools, such as compilers and retrievers, to complete multi-step tasks ( Anthropic, 2026b ; OpenAI, 2026 ) . When tools run outside the inference service, a session’s demand for GPU computation becomes interruptible. We call this serving scenario C lustered- G PUs with D istributed- C PUs (CGDC), illustrated in Figure 1 (Left): clustered GPUs, i.e., nodes, provide shared inference capacity, while external tool calls introduce delays between LLM requests 1 1 One agent session consists of multiple LLM inference requests (i.e., steps) after tool calls. . Hence, efficient agentic serving must account for both inference demand and tool timing to sustain throughput and session responsiveness.

We find that existing serving systems generally follow an evaluate-then-decide scheduling pattern ( Guy et al., 2025 ; SGLang Team, n.d. ; vLLM Production Stack Team, n.d. ) . They evaluate node features at the session level and then decide where and when to serve each session. This separates the problem into two related challenges: (1) how to value a session’s next model turn, and (2) how to select and place sessions under shared capacity constraints.

For session evaluation , existing systems in CGDC scenarios generally overlook tool-call latency when evaluating established workload features. Cache-aware systems reuse KV prefixes and balance inference load ( Zheng et al., 2024 ; Srivatsa et al., 2025 ; Qin et al., 2025 ; NVIDIA, 2025 ) ; workflow-aware systems anticipate future calls ( Wadlom et al., 2026 ; Pan et al., 2026 ) ; and latency-aware schedulers prioritize sessions using latency or remaining-work estimates ( Choi et al., 2025 ; Chen et al., 2025 ) . Tool timing provides another useful signal, yet timing is utilized only as a surrogate for KV reuse or token count: Li et al. (2025) predicts tool duration to choose KV-cache retention times, while Kang et al. (2026) discounts the token footprint of sessions executing tools as time elapses. Such features commonly enter fixed scoring rules or manually chosen thresholds.

For decision making , existing systems usually apply heuristic scheduling strategies to each session, leading to myopic and suboptimal placements. In llm-d and SGLang ( Guy et al., 2025 ; SGLang Team, n.d. ) , per-session scoring and routing rules assign inference opportunities individually . Yet sessions compete for the same node capacity. In particular, assigning one session can prevent a more valuable combination of other sessions from being served. Furthermore, the heuristic selection and placement rules can also lead to suboptimal choices ( Peng et al., 2026 ; Yuan et al., 2026 ) . As shown in Figure 1 (Right), they fail to formulate scheduling jointly across multiple sessions.

> Figure 1: Left: In the CGDC serving scenario, external tool calls create intervals between LLM requests and opportunities to reallocate inference capacity. Right: Two scheduling challenges motivate TAO, including (1) overlooking tool-return readiness and using heuristic merging for evaluation, and (2) making myopic and suboptimal decisions about session admission and placement.

To address these challenges, we propose TAO, a T ool- A ware j O int scheduling framework for LLM-based agentic serving. To incorporate tool latency into session evaluation , we propose tool-return readiness and explicitly integrate it with established features such as KV-cache reuse. Following Kang et al. (2026) , we interrupt sessions during tool calls and put them into a waiting pool . Tool-return readiness estimates which sessions will need inference within the next scheduling window. For each session–node pair, we form a value triplet from readiness, time-decayed KV-cache reuse , and token footprint. Given these evaluation triplets, we design a joint scheduling algorithm in the decision making stage that considers all sessions in the waiting pool. Across deployments in different scenarios, joint optimization considers how the admission of each session affects the placements available to others. The optimizer maximizes the additive evaluation triplets using dynamic programming. Their coordinates evolve with cache age and tool progress, allowing distinct signals to guide decisions over time without a weighted sum. Separating the optimization procedure from session evaluation makes the framework extensible.

We summarize our contributions as follows:

- • We identify the Clustered GPUs with Distributed CPUs (CGDC) serving scenario in the era of LLM-based agents, which shifts the key bottleneck of latency to tool calls.

- • We propose TAO, a tool-aware joint scheduling framework for LLM-based agentic serving. It improves the evaluate-then-decide paradigm through session evaluation with explicit tool-return readiness and decision making with joint modeling and optimization.

- • TAO can be generalized and extended to different workloads such as multi-agent orchestration and Looped Agents. Moreover, it is also compatible with non-agent chatbot scenarios.

- • Across the 12 reported model–workload–concurrency settings, TAO reduces latency by up to 26.8%, reduces mean time to first token (TTFT) by up to 36.3%, and increases decode throughput by up to 29.5% relative to the state-of-the-art baseline for each metric.


### 2 Background and Problem Description


#### 2.1 Agent Session and distributed resources

An agent session is a persistent interaction that alternates between model requests and external tool calls. During a model request, it uses a serving node; during tool execution, it awaits a result outside the inference service. A scheduler records each session’s state and controls session admission, while the serving engine manages physical KV-cache residency and eviction.

A later model request can reuse the KV prefix produced by earlier turns and avoid prefill computation ( Kwon et al., 2023 ) . Because an agent session carries its instructions, history, and tool observations across turns, reuse depends on both the agent session history and the node selected for its next request. SGLang and Preble exploit related prefix structure in model programs and distributed scheduling ( Zheng et al., 2024 ; Srivatsa et al., 2025 ) .

Our CGDC separates clustered GPU inference from distributed tool execution. Client or remote tools introduce variable delays between model requests, while their CPU and RAM are managed outside the GPU admission budget ( Anthropic, 2026b ; OpenAI, 2026 ; Chang et al., 2026 ) . Tool latency therefore determines when an agent session may need GPU resources for inference again.


#### 2.2 session interruption and session restart

During tool execution, a session can release its GPU resources safely, although its cached prefix may subsequently be evicted. In contrast, preempting an active inference session requires recomputation. Repeated recomputation and reconstruction cause KV-cache thrashing , wasting capacity on state that must be rebuilt. This phenomenon motivates cache-aware engine and scheduling work ( Kwon et al., 2023 ; Zheng et al., 2024 ; Srivatsa et al., 2025 ; NVIDIA, 2025 ) , as well as policies that weigh retaining state against serving other work ( Li et al., 2025 ; Abhyankar et al., 2024 ) .

Therefore, at a tool boundary, the scheduler can apply session interruption . Specifically, a scheduler can interrupt the agent session’s model admission and release its node resources while the external tool continues. When inference service is needed again, session restarting restores admission on an eligible node and resumes the existing interaction. Session interruption and session restarting describe session state transitions. They are decoupled from the underlying inference engine.

We find that the decisions made for these two operations can be based on the same session evaluation. Thus, we optimize toward a unified goal for maximizing the evaluation. Session interruption can be decided by ordering sessions according to their values. Interrupted sessions join new arrivals in a waiting pool. We focus on unified session evaluation and restarting decisions from this pool.


### 3 Method


#### 3.1 Framework overview

We present TAO, which combines agentic session evaluation with decision making, i.e. dynamic programming for joint selection and placement. The detailed formulation appears in Section 3.2 .

Figure 2 illustrates the pipeline of our method. First, session evaluation maps agent session and node observations to assignment values (Section 3.2 ), including KV cache with time-aware decay (Section 3.3 ) and tool-return readiness (Section 3.4 ). Second, an exact dynamic program jointly selects waiting agent sessions and assigns them to nodes under residual capacity constraints (Sections 3.2 and 3.5 ). Separating session evaluation from decision making lets the evaluation interface evolve while preserving the scheduling procedure.

> Figure 2: The TAO evaluate-then-decide framework in CGDC. External tools on distributed CPUs provide historical tool-call durations, while the serving engines on clustered GPUs provide cache observations. Then, the session evaluation component constructs triplets (decayed KV-cache credit, binary readiness, token count) . The decision making component jointly selects and places waiting agent sessions. The executor validates the plan against live state before applying it. The resulting assignments schedule sessions to eligible nodes.


#### 3.2 Formulation and Agentic session evaluation

At each restart scheduling decision, let the waiting pool $P$ contain the agent sessions awaiting inference admission, including interrupted sessions and new arrivals. Let $B$ be the nodes in the frozen snapshot. Each agent session $i$ has admission cost $w_{i}$ , and each node $b$ has residual capacity $C_{b}$ . Let $E\subseteq P\times B$ denote eligible assignments, and let $x_{i,b}\in\{0,1\}$ indicate whether session $i$ is admitted to node $b$ . The feasible set is

[Tableau] $$\mathcal{X}=\left\{x:\sum_{b\in B}x_{i,b}\leq 1,\quad\sum_{i\in P}w_{i}x_{i,b}\leq C_{b},\quad x_{i,b}=0\ \text{if }(i,b)\notin E\right\}.$$ (1)

TAO assigns each agent session–node pair the lexicographic value

[Tableau] $$\bm{v}_{i,b}=(k_{i,b},r_{i},t_{i}),$$ (2)

where $k_{i,b}$ is decayed cache credit, $r_{i}$ is the binary readiness signal, and $t_{i}$ is token count. We jointly select and place sessions to maximize their aggregate value:

[Tableau] $$x^{\star}\in\underset{x\in\mathcal{X}}{\operatorname{arg\,lexmax}}\sum_{i\in P}\sum_{b\in B}x_{i,b}\bm{v}_{i,b}.$$ (3)

The evaluation triplet’s order remains fixed while its values evolve over time. Our design rationale is detailed as follows:

- • KV-Cache credit takes precedence, but its value decays quickly after interruption, because prefix reuse directly avoids repeated prefill, motivating cache-aware scheduling ( NVIDIA, 2025 ) . The age-based discount in Section 3.3 favors recent cache evidence, which is often most useful when a tool returns quickly.

- • As unrefreshed credit decays and the first component is equalized, tool-return readiness can distinguish agent sessions nearing a return from those still far from their next model turn (Section 3.4 ).

- • Token footprint then favors larger accumulated contexts among plans tied on cache credit and readiness. The optimizer accounts for the greater capacity cost of such contexts when choosing the complete set of assignments.

> Figure 3: Observed cache-token retention in DeepSeek-V4 Flash traces from two nodes with $4\times$ H100 per node.


#### 3.3 Time-aware cache value for Clustered GPUs

TAO estimates reusable KV state from observations associated with each target node. It uses an observed cached-token count when available, or estimates the count from observed token volume and cache rate. A node without matching evidence receives zero credit. Figure 3 reports observed cache-token retention in DeepSeek-V4 Flash traces from two nodes with $4\times$ H100 per node; the decline in binned medians motivates discounting older observations. Points show binned medians with bootstrap 95% intervals; the curve is a descriptive exponential fit over the populated bins through 1,800 s. Older observations receive less credit:

[Tableau] $\displaystyle k_{i,b}(t)=k^{0}_{i,b}\,2^{-\tau_{i,b}/h},$ (4) $\displaystyle\tau_{i,b}=\max(0,t-t^{\mathrm{obs}}_{i,b}).$

Here $k^{0}_{i,b}$ is the observed cache credit and $h$ is its decay half-life. We use $h=10$ seconds and round the resulting credit for valuation. The discount makes the admission value responsive to observation age; the serving engine continues to control physical allocation, reuse, and eviction. The half-life is a scheduler parameter, distinct from the fitted trace time constant. Dynamo similarly adjusts overlap value under excess prefill load, and ThunderAgent discounts token demand over time ( NVIDIA, 2025 ; Kang et al., 2026 ) .


#### 3.4 Tool-return readiness in a distributed CPU

In our CGDC deployment, external executors manage tool CPU and RAM, while TAO controls GPU admission. Tool-return readiness connects these resource domains by identifying sessions likely to request model service within a short horizon. Tool timing reflects external execution conditions; the GPU admission budget accounts for the returning session’s inference footprint. Tool interfaces can expose progress or return deadlines: Claude Code’s Monitor forwards background-work events, while OpenCode reports termination after a Bash timeout ( Anthropic, 2026a ; OpenCode Contributors, 2026 ) .

The predictor combines these hints, parsed sleep commands, and historical tool durations, using direct timing evidence first and falling back to the tool-specific history, global history, or a five-second default ( Li et al., 2025 ) . For a call with elapsed time $e_{i}(t)$ , the historical estimate $\widehat{D}_{f}$ gives

[Tableau] $$\widehat{d}_{i}(t)=\max\{0,\widehat{D}_{f}-e_{i}(t)\}.$$ (5)

The implementation adds a finite-sample margin to the historical mean; Appendix A specifies this estimator in detail.

Binary readiness. Let $o_{i}(t)$ indicate observed tool completion, $a_{i}(t)$ indicate an established tool execution candidate with an eligible prediction source, and $g_{i}(t)$ indicate valid prediction timestamps refreshed within 30 seconds. Write $z_{i}(t)$ for the earlier available predicted completion or exposed return deadline, treating an unavailable deadline as $+\infty$ . With horizon $H$ and overdue-probe indicator $b_{i}(t)$ , we define

[Tableau] $$r_{i}(t)=\begin{cases}1,&o_{i}(t)=1,\\ a_{i}(t)b_{i}(t),&o_{i}(t)=0,\ z_{i}(t)\leq t,\\ a_{i}(t)g_{i}(t)\mathbf{1}[z_{i}(t)\leq t+H],&\text{otherwise}.\end{cases}$$ (6)

TAO uses $H=1$ second; the scheduler’s session interruption valuation uses its configured scheduling interval. Overdue predictions receive temporary probe opportunities instead of remaining ready indefinitely. Observed completion takes precedence over prediction checks. This signal prioritizes near-term returns among plans tied on higher-precedence values.


#### 3.5 Joint scheduling with dynamic programming

The optimizer is a capacity-state dynamic program for the multiple-knapsack and generalized-assignment structure ( Kellerer et al., 2004 ; Shmoys and Tardos, 1993 ) . Let $\Delta$ be the capacity quantum, $\bar{w}_{i}=\lceil w_{i}/\Delta\rceil$ , and $\bar{C}_{b}=\lfloor C_{b}/\Delta\rfloor$ . For candidate $j$ , let $D_{j}(\bm{s})$ be the best objective attainable from the first $j$ candidates at the used capacity $\bm{s}$ , and let $\bm{u}_{j,b}$ embed the value and count for assigning $j$ to node $b$ :

[Tableau] $$D_{j}(\bm{s})=\mathop{\mathrm{lexmax}}\left\{D_{j-1}(\bm{s}),\;\max_{b\ \mathrm{eligible}}^{\mathrm{lex}}\left[D_{j-1}(\bm{s}-\bar{w}_{j}\bm{e}_{b})+\bm{u}_{j,b}\right]\right\}.$$ (7)

Only nonnegative states within $\bar{\bm{C}}$ are allowed; $D_{0}(\bm{0})=\bm{0}$ and other initial states are unreachable. Skipping or assigning each candidate exhausts the feasible choices, so induction gives exactness for the frozen, discretized problem; rounding can exclude plans feasible before discretization.

Node-specific cache observations are decayed and folded into assignment values during $O(nm)$ preprocessing; cache-equivalent nodes can be grouped into $g\leq m$ aggregate capacity dimensions without moving physical KV blocks. The planner runs in an isolated asynchronous worker (detailed in Appendix B ) and revalidates before application; recorded preparation plus completed-solve work is below 0.12% of runtime in the four-replica sweep (Appendix I ).

#### 4.1 Experiment Setup

Models and workloads. We evaluate DeepSeek-V4 Flash, Qwen3-32B, and GLM-4.7 ( DeepSeek-AI et al., 2026 ; Yang et al., 2025 ; Team et al., 2025 ) on the SWE-bench Lite workload (SWE-Lite) using the mini-SWE-agent harness (MiniSWE) ( mini-SWE-agent Contributors, 2026 ; Jimenez et al., 2024 ) . For DeepSeek, we also use Claude Code on Terminal-Bench 2.0 ( Merrill et al., 2026 ) for challenging tasks. For Qwen, we test with SWE-verified to exercise the serving capacity of its smaller model replicas. We further evaluate GLM-4.7 on SWE-Lite to test single-node performance. Appendix F reports an InferenceX trace-replay evaluation.

Deployment. DeepSeek runs on 2 nodes with $4\times$ H100 per node; Qwen runs on 4 nodes with $2\times$ H100 per node. Each node hosts one tensor-parallel model replica. GLM-4.7 runs on one node with $8\times$ H100. Appendix E.1 reports a lower-concurrency DeepSeek check on the same single-node topology.

Baselines. vLLM Scheduler w/ RR and vLLM Scheduler w/ CA denote the vLLM schedulers with round-robin and cache-aware policies, respectively ( vLLM Production Stack Team, n.d. ) , which align with the policy in SGLang ( Zheng et al., 2024 ) . These baselines cover load spreading and prefix-locality scheduling. Dynamo is a KV-aware scheduler ( NVIDIA, 2025 ) . ThunderAgent uses token-count scheduling and best-fit-decreasing placement ( Kang et al., 2026 ) . TAO combines predictive cache-aware session evaluation with joint dynamic-programming placement.

Metrics. We report mean task end-to-end latency, mean time to first token (TTFT), and decode throughput in tokens per second (TPS). Task latency includes both model inference and tool execution. Component analyses also measure prefix-cache hit rate, tool-end-to-first-token delay, and pause wait, which includes the tool call latency of an interrupted session.

#### 4.3 Improvement Breakdown

As shown in Section 4.2 , the worker sweep exposes a latency–throughput tradeoff: the lowest latency and TTFT occur at the smallest worker count, while peak decode throughput occurs at 64 workers for DeepSeek SWE-Lite and Terminal-Bench, 128 workers for Qwen SWE-Lite, and 96 workers for SWE-verified. We use DeepSeek at 32 workers as a balanced operating point and examine how cache-aware valuation, tool readiness, and joint placement improve reuse, tool-return responsiveness, and admission decisions.


##### Cache-aware valuation.

In a fixed-workload replay of 218 tasks with DP placement held fixed for the ThunderAgent control and cache-aware variants, cache-token ordering raises prefix-cache hit rate by 0.19 percentage points and reduces mean pause wait by 4.5% relative to ThunderAgent. Adding cache-credit decay raises hit rate by 0.31 percentage points and decode throughput by 1.68% relative to ThunderAgent. ### 5 Related Work

PagedAttention and RadixAttention improve engine-level KV management, while Preble, Mooncake, and Dynamo exploit distributed cache locality ( Kwon et al., 2023 ; Zheng et al., 2024 ; Srivatsa et al., 2025 ; Qin et al., 2025 ; NVIDIA, 2025 ) . SMetric combines session affinity with load balancing ( Wang et al., 2026a ) , and production schedulers support extensible scoring ( Guy et al., 2025 ) . Autellix prioritizes programs using service history, while ThunderAgent introduces the lifecycle and waiting pool on which TAO builds ( Luo et al., 2025 ; Kang et al., 2026 ) . InferCept and Continuum manage KV retention across tool calls, with Continuum using historical tool-duration distributions ( Abhyankar et al., 2024 ; Li et al., 2025 ) . TAO brings cache opportunity and tool readiness into a joint scheduler-level admission and placement objective, complementing engine-level KV management. Parrot and Helium exploit workflow dependencies, while KVFlow and CacheScout guide residency or prefetching using execution structure ( Lin et al., 2024 ; Wadlom et al., 2026 ; Pan et al., 2025 ; Zhang et al., 2026 ) . TOPAS jointly considers prefix residency and admission through bounded search and greedy packing ( Ni et al., 2026 ) . Conveyor, Sutradhara, and PASTE reduce exposed tool latency through partial execution, overlap, or speculation ( Xu et al., 2024 ; Biswas et al., 2026 ; Sui et al., 2026 ) . TAO converts tool timing into near-term model-service opportunities that inform joint admission and placement. AgentSysBench and MARS motivate accounting for tool delays and deployment boundaries ( Chang et al., 2026 ; Wang et al., 2026b ) . TAO couples an agentic value interface with joint placement and asynchronous revalidation, using the insights from classical multiple-knapsack and generalized-assignment machinery ( Kellerer et al., 2004 ; Shmoys and Tardos, 1993 ) . It becomes popular to formulate some optimization problems in LLM and agentic serving and solve online, from edge scenarios ( Li et al., 2026 ) to large-scale infrastructure ( Bu et al., 2026 ; Chen et al., 2026 ) .


### 6 Conclusion

Tool execution makes agentic inference demand intermittent, while accumulated context makes the choice of node consequential. TAO brings these two properties into a common scheduling objective through cache credit, tool-return readiness, and token footprint. Joint dynamic-programming placement maximizes this objective under snapshot capacity constraints, and asynchronous revalidation connects the plan to live execution. Across the evaluated DeepSeek-V4 Flash and Qwen3-32B settings, this design delivers improvements of up to 26.8% in latency, 36.3% in mean TTFT, and 29.5% in decode throughput. The resulting architecture gives agentic serving an extensible way to translate workload knowledge into coordinated admission and placement.

### Appendix A Historical Tool-Duration Estimator

The history-based predictor in Section 3.4 uses a lightweight summary of completed calls. A finite-sample margin augments the historical mean, allowing the estimate to account for observed variability and the amount of available history.

For calls without direct timing evidence, we maintain statistics of completed durations keyed by the structured tool name $f$ . Let $n_{f}$ , $\bar{d}_{f}$ , $s_{f}^{2}$ , and $R_{f}$ denote the sample count, mean, sample variance, and observed duration range. We use the following conservative upper estimate as a duration heuristic ( Maurer and Pontil, 2009 ) :

[Tableau] $$\widehat{D}_{f}=\begin{cases}\bar{d}_{f},&n_{f}=1,\\[2.0pt] \displaystyle\bar{d}_{f}+\sqrt{\frac{2s_{f}^{2}\log(3/\delta)}{n_{f}}}+\frac{3R_{f}\log(3/\delta)}{n_{f}},&n_{f}\geq 2,\end{cases}$$ (8)

with $\delta=0.2$ . We use global completed-call statistics when tool-specific history is empty. Subtracting elapsed time from $\widehat{D}_{f}$ gives the remaining-duration estimate. The finite-sample margin is a scheduling heuristic; it does not provide calibrated coverage for an individual call. Continuum also exploits tool-duration history to choose a KV-retention TTL ( Li et al., 2025 ) . Our estimate converts this historical timing evidence into a signal for scheduler admission.

If both tool-specific and global histories are empty, the implementation uses a five-second duration default. The remaining-time estimate subtracts elapsed time and clips at zero, as in equation ( 5 ). Exposed timing hints take precedence as described in the main text.

#### B.2 Asynchronous execution

The scheduler solves a frozen snapshot in an isolated worker. Before applying the plan, it checks that selected agent sessions remain eligible and match their recorded state signatures, then applies the longest prefix permitted by current capacities. Changed selected-agent session signatures cause the plan to be discarded. Revalidation preserves feasibility under current admission constraints. We quantify the effect of stale values, discarded plans, and partial application through a loss bound relative to the fresh-snapshot optimum, and measure these execution outcomes alongside solve time and plan age.


##### Conditional loss bound.

Let $s$ and $t$ be planning and application times, $x_{s}$ the exact snapshot plan, and $y_{t}$ the revalidated plan (empty if discarded). Write $\mathcal{X}_{s}^{\Delta}$ and $\mathcal{X}_{t}^{\Delta}$ for the quantized feasible sets. For analysis, represent the lexicographic objective by one fixed scalar score $U_{\tau}$ that preserves its order on the finite plans and values under comparison; the implementation still compares vectors. Define

[Tableau] $\displaystyle\epsilon_{s,t}$ $\displaystyle=\max_{x\in\mathcal{X}_{s}^{\Delta}}|U_{t}(x)-U_{s}(x)|,$ $\displaystyle A_{s,t}$ $\displaystyle=\max_{x\in\mathcal{X}_{t}^{\Delta}}U_{t}(x)-\max_{x\in\mathcal{X}_{s}^{\Delta}\cap\mathcal{X}_{t}^{\Delta}}U_{t}(x),$ $\displaystyle T_{s,t}$ $\displaystyle=[U_{t}(x_{s})-U_{t}(y_{t})]_{+}.$ (9)

These terms capture value drift, opportunities introduced by feasibility changes, and value lost during execution. The empty plan ensures a nonempty intersection. Then

[Tableau] $$\max_{x\in\mathcal{X}_{t}^{\Delta}}U_{t}(x)-U_{t}(y_{t})\leq A_{s,t}+2\epsilon_{s,t}+T_{s,t}.$$ (10)

The proof in Appendix C inserts the best common feasible plan and applies snapshot optimality plus two value-drift terms. If every plan has at most $K$ assignments and each scalar assignment value changes by at most $\eta_{s,t}$ , then $\epsilon_{s,t}\leq K\eta_{s,t}$ . With an additional drift bound $\eta_{s,t}\leq L(t-s)$ , the value-drift term becomes $2KL(t-s)$ ; readiness jumps require separate allowances. An unquantized comparator adds the quantization gap, and a fallback adds its snapshot suboptimality gap.

The bound connects planner freshness to retained scheduling value: short plan age limits value drift under the stated assumptions, while revalidation losses appear explicitly in $T_{s,t}$ . Its comparator is the fresh placement optimum on the same realized state; Appendix C details this scope.


### Appendix C Asynchronous Snapshot Loss: Proof and Scope


##### Loss relative to a fresh snapshot.

We compare the applied plan with the optimal placement at application time on the same observed system state. Let $s$ be the planning time and $t$ the application time. Write $\mathcal{X}_{s}^{\Delta}$ and $\mathcal{X}_{t}^{\Delta}$ for the discretized feasible sets, embedding both in the union of candidate–node assignments. The empty plan belongs to both sets. Let $x_{s}$ be the exact snapshot solution and $y_{t}\in\mathcal{X}_{t}$ the applied plan, feasible under the current admission contract; a discarded plan has $y_{t}=0$ .

To express loss numerically, let $U_{\tau}(x)$ be a fixed positive weighted sum of the objective coordinates in equation ( 3 ), with weights that preserve their lexicographic order on the finite collection of plans and objective values considered at $s$ and $t$ . Such weights exist for finite sets, with a scale determined by the coordinate ranges and gaps. The scalar score serves the analysis; the implementation compares vectors directly. In particular, $x_{s}$ maximizes $U_{s}$ over $\mathcal{X}_{s}^{\Delta}$ . Extend the additive objective to all assignments in the union, including plans that have become infeasible.

Define the value variation, loss from changes in feasibility, and execution loss as

[Tableau] $\displaystyle\epsilon_{s,t}$ $\displaystyle=\max_{x\in\mathcal{X}_{s}^{\Delta}}|U_{t}(x)-U_{s}(x)|,$ $\displaystyle A_{s,t}$ $\displaystyle=\max_{x\in\mathcal{X}_{t}^{\Delta}}U_{t}(x)-\max_{x\in\mathcal{X}_{s}^{\Delta}\cap\mathcal{X}_{t}^{\Delta}}U_{t}(x),$ $\displaystyle T_{s,t}$ $\displaystyle=[U_{t}(x_{s})-U_{t}(y_{t})]_{+}.$ (11)

Here $[z]_{+}=\max(z,0)$ . New candidates, new eligibility, and additional capacity can contribute to $A_{s,t}$ ; truncation or discard contributes to $T_{s,t}$ . Changes in feature values contribute to $\epsilon_{s,t}$ .


##### Conditional bound.

For every exact snapshot solve and feasible applied plan,

[Tableau] $$\max_{x\in\mathcal{X}_{t}^{\Delta}}U_{t}(x)-U_{t}(y_{t})\leq A_{s,t}+2\epsilon_{s,t}+T_{s,t}.$$ (12)

To prove this, choose $z$ maximizing $U_{t}$ over the intersection of the two feasible sets. Snapshot optimality gives $U_{s}(z)\leq U_{s}(x_{s})$ , and hence

[Tableau] $\displaystyle U_{t}(z)-U_{t}(y_{t})$ $\displaystyle\leq[U_{t}(z)-U_{s}(z)]+[U_{s}(x_{s})-U_{t}(x_{s})]$ $\displaystyle\quad+[U_{t}(x_{s})-U_{t}(y_{t})]\leq 2\epsilon_{s,t}+T_{s,t}.$

Adding $A_{s,t}$ proves equation ( 12 ). If the comparator uses the original, undiscretized capacities, add the nonnegative quantization gap $Q_{t}=\max_{x\in\mathcal{X}_{t}}U_{t}(x)-\max_{x\in\mathcal{X}_{t}^{\Delta}}U_{t}(x)$ to its right-hand side.

The bound isolates conditions under which asynchronous planning retains value. If every plan contains at most $K$ assignments and each scalar assignment value changes by at most $\eta_{s,t}$ , then $\epsilon_{s,t}\leq K\eta_{s,t}$ . A further assumption $\eta_{s,t}\leq L(t-s)$ yields a variation term $2KL(t-s)$ ; binary readiness require explicit jump allowances and do not satisfy this assumption automatically. Summing equation ( 12 ) over scheduling ticks bounds cumulative loss against fresh-snapshot optima on the realized states, using one common scalarization. It does not bound end-to-end latency or regret against a globally optimal online policy, whose earlier decisions can produce different future states. A uniform numerical bound requires corresponding bounds on state variation, feasibility changes, and discarded value. A fallback solve additionally contributes its snapshot suboptimality gap.

#### E.2 KV-Cache Management Compatibility

TokenCake uses workflow dependencies and agent priorities to guide its Space Scheduler, and tool-stall events and timing prediction to guide offload and upload in its Time Scheduler ( Bian et al., 2025 ) . Agentix prioritizes and preempts LLM calls using program-level service history to reduce request- and program-level blocking ( Luo et al., 2026 ) . It operates at the request-scheduling layer, so integrating it with TAO would require coordinating the two admission policies. KVFlow represents a workflow as an Agent Step Graph and uses steps-to-execution to prioritize cache eviction and prefetching ( Pan et al., 2025 ) . CacheScout learns execution transitions online to guide cache management without requiring a predefined graph ( Zhang et al., 2026 ) . These mechanisms provide information about future cache use. In our formulation, such information can inform the program–node values supplied to session evaluation, while engine-local cache policies can operate beneath TAO’s admission and placement decisions. This is an architectural extension for KVFlow and CacheScout, while the implemented composition evaluated here uses TokenCake.

### Appendix J Extended Related Work


##### Capacity-constrained optimization.

Dynamic programming and exact multiple-knapsack algorithms provide established tools for selecting items and assigning them to capacity-limited resources ( Bellman, 1957 ; Kellerer et al., 2004 ; Pisinger, 1999 ) . Node-dependent assignment values place our formulation within the multiple-knapsack/generalized-assignment family. Approximation algorithms address the computational cost of this family ( Chekuri and Khanna, 2005 ; Shmoys and Tardos, 1993 ) , while online resource-allocation algorithms analyze decisions under specified arrival models ( Li et al., 2020 ) . TAO uses this classical optimization machinery to connect agentic session evaluation with joint admission and node placement. Its additive, lexicographic objective makes cache opportunity, tool readiness, and token footprint precedence explicit, and its asynchronous executor revalidates assignments against live state. Section 3.5 and Appendix B.2 specify snapshot optimality and the bounds for asynchronous application.


##### KV locality and agent scheduling.

PagedAttention improves physical KV allocation and sharing, while SGLang’s RadixAttention reuses prefixes within the serving runtime ( Kwon et al., 2023 ; Zheng et al., 2024 ) . Preble co-optimizes distributed prefix reuse and computation balance; Mooncake combines a distributed KV store with disaggregated serving ( Srivatsa et al., 2025 ; Qin et al., 2025 ) . Dynamo and production gateways expose cache- and load-aware request scheduling ( NVIDIA, 2025 ; vLLM Production Stack Team, n.d. ; SGLang Team, n.d. ) , and llm-d provides pluggable scoring components ( Guy et al., 2025 ) . SMetric exploits session structure by balancing first-turn requests and assigning later turns to nodes with reusable cache, using a global cache tier to limit the cost of redistribution ( Wang et al., 2026a ) . TAO builds on these locality and load-balancing principles with joint optimization of assignments for waiting agent sessions under shared capacity. This joint view accounts for how one admission consumes capacity needed by other session–node assignments.

Program-level schedulers also preserve information across model calls. Autellix uses attained service and critical-path information to prioritize single-threaded and distributed programs ( Luo et al., 2025 ) . ThunderAgent introduces the program abstraction, state-aware pausing, elapsed-time discounting of tool execution programs’ effective token demand, and a global waiting queue ( Kang et al., 2026 ) . TAO adds node-specific cache values and readiness to the joint placement objective. Tool-gap cache management addresses a complementary decision: InferCept chooses among preservation, swapping, and recomputation by modeling resource waste ( Abhyankar et al., 2024 ) ; Continuum selects a cache-retention TTL using historical tool-duration distributions, reconstruction cost, and returning programs’ queueing cost, together with TTL-aware program ordering ( Li et al., 2025 ) . These systems control physical KV retention. TAO coordinates scheduler-level admission opportunities, with predicted readiness distinguishing plans that have equal higher-precedence cache value. The serving engine controls the resulting cache residency.


##### Workflow, prediction, and tool execution.

Workflow structure provides information beyond an isolated request. Parrot exposes inter-request dependencies through Semantic Variables, and Helium compiles workflow query plans for proactive reuse and cache-aware execution ( Lin et al., 2024 ; Wadlom et al., 2026 ) . KVFlow uses an Agent Step Graph and steps-to-execution to guide eviction and prefetching ( Pan et al., 2025 ) ; CacheScout learns execution transitions online without a predefined graph ( Zhang et al., 2026 ) . Their predictions guide context residency and prefetching; readiness supplies a binary near-term admission-opportunity signal derived from tool timing. SAGA combines workflow graphs, session-affinity batching, and work stealing ( Guo et al., 2026 ) . TOPAS also uses heuristic state searching: it scores prefix-residency and request-admission states using remaining workflow paths, movement costs, and downstream reuse, with bounded candidate search and greedy packing ( Ni et al., 2026 ) . Its task-dependent utility and engine-level residency decisions differ from our fixed additive value contract and exact multi-node scheduling problem.

Prediction also supports latency-oriented scheduling. ELIS predicts response length, while Kairos combines workflow-aware priority with memory-aware dispatch ( Choi et al., 2025 ; Chen et al., 2025 ) . Recent work separates already-ready turns from their release, using a mean–CVaR objective and an adaptive budget for committed inference work ( Feng et al., 2026 ) . This addresses tail-aware release after dependencies complete; TAO additionally evaluates near-term return opportunities during external tool execution. Complementary mechanisms change the execution timeline itself: Conveyor exposes partial tool execution, Sutradhara overlaps tool work and prefill through orchestrator–engine cooperation, and PASTE speculates on future tools while coordinating tool execution with returning model agent sessions ( Xu et al., 2024 ; Biswas et al., 2026 ; Sui et al., 2026 ) . SmoothAgent prepares transformed context on a lookahead stream, and Pie exposes programmable generation and KV handlers ( Pan et al., 2026 ; Gim et al., 2025 ) . TAO operates in the scheduler, using timing evidence to coordinate admission and node placement.


##### Deployment and workloads.

AgentSysBench documents substantial non-LLM latency and deployment-dependent resource demands ( Chang et al., 2026 ) . MARS explicitly coordinates GPU inference, CPU tool pressure, admission, and KV retention in heterogeneous serving ( Wang et al., 2026b ) . In our CGDC scenario, distributed executors manage tool CPU and memory, and their resource pressure reaches the GPU scheduler through tool-return timing. TAO captures this interaction through readiness when allocating GPU admission capacity. OpenHands supports separate execution environments ( Wang et al., 2025 ) . Coding and terminal workloads, together with InferenceX/AgentX trace replay, provide complementary evidence about task completion and serving behavior ( mini-SWE-agent Contributors, 2026 ; Jimenez et al., 2024 ; Merrill et al., 2026 ; SemiAnalysis, 2026b ; SemiAnalysis, 2026a ) , with workload-specific timing metrics defined in the evaluation.
