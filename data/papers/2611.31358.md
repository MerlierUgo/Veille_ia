## Nemotron-Labs-VisualCreation: Pixel as Code for Agentic Visual Creation

Visual creation demands expressive imagery together with precise control over text, layout, and structure. We introduce Nemotron-Labs-VisualCreation, an agentic framework that connects these capabilities through Pixel as Code . Raster images are represented by learned discrete visual tokens, while structured artifacts use explicit programs. A shared generation-and-rendering interface connects these representations to visual feedback across images, vector graphics, webpages, and documents. A Nemotron-native harness coordinates planning and raster candidate selection, with targeted repair for editable structured and hybrid artifacts. To support this interface, we develop Nemotron-Labs-Image-Tokenizer, the autoregressive raster generator Nemotron-Labs-Image-30B-A3B, and the structured-code model family Nemotron-Labs-VisionCode. On approximately 178K images spanning six visual domains, our tokenizer improves reconstruction PSNR from 26.08 to 29.57 dB over Emu3.5 IBQ. It also provides $7.13\times$ faster encoding and $10.93\times$ faster decoding at batch size one on A100. In standalone evaluation, one Nemotron-Labs-VisionCode variant surpasses Kimi K3.1 Pro on the aggregate across Chart2Code, MMSVG, Design2Code, and Image2Struct. At the system level, the Nemotron-native configuration raises GenEval2 Soft-TIFA GM from 31.71 to 52.56 using the same raster generator. With our best setting, Nemotron-Labs-VisualCreation achieves performance competitive with GPT Image 2 and Nano Banana Pro across most benchmarks with available comparisons.

### 1 Introduction

Visual creation spans photographs, illustrations, charts, webpages, posters, scientific figures, and slides. A single request may demand expressive imagery, exact wording, factual accuracy, spatial relationships, and an editable deliverable. Meeting these needs calls for both expressive synthesis and explicit control over content and structure, coordinated through representation, rendering, and visual inspection.

Recent work provides complementary foundations. Edify Image ( NVIDIA et al., 2024 ) , Sana ( Xie et al., 2024 ) , and PixelDiT2 ( Yu et al., 2026 ) explore representations and architectures for image synthesis, while Cosmos 3 ( NVIDIA, 2026a ) integrates multimodal understanding and generation. Agentic image creation ( Li et al., 2026b ) and scene-generation systems ( Xia et al., 2026 ; Ling et al., 2026 ) investigate planning, tool use, and visual assessment. These directions motivate a common interface for coordinating learned visual generation and explicit artifact structure.

We introduce Pixel as Code , a shared interface in which generators predict discrete representations and renderers produce visual outputs for inspection (Figure 1 ). Learned visual tokens capture raster appearance and are decoded into pixels. Explicit programs—including SVG, HTML/CSS, plotting code, and document markup—expose content, geometry, and layout for direct editing through their respective rendering backends. Hybrid artifacts combine these complementary representations, for example by embedding a generated image within an editable webpage.

Building on this interface, we present Nemotron-Labs-VisualCreation . Its harness coordinates semantic planning, raster generation, and visual selection. Structured and hybrid requests additionally establish a layout contract and produce editable representations. For browser-based artifacts, visual audits assign failures to causal owners for targeted repair and checkpoint selection; native formats use their corresponding generation and review workflows. Figures 2 and 4 illustrate representative outputs.

Our contributions span the creation interface, its learned components, and their evaluation:

A shared interface for agentic visual creation. We formulate Pixel as Code around a common generate representation $\rightarrow$ render $\rightarrow$ inspect interface and describe how a Nemotron-native harness coordinates planning, generation, visual selection, and route-specific refinement. The browser-based workflow makes rendered feedback actionable through a resolved layout contract, explicit repair ownership, and checkpoint retention (Section 2 ).

Complementary models for raster and structured generation. We develop Nemotron-Labs-Image-Tokenizer as the discrete raster interface, adapt Nemotron 3 Nano into the autoregressive generator Nemotron-Labs-Image-30B-A3B through multistage mid-training and reinforcement learning, and develop Nemotron-Labs-VisionCode as a family of specialized models for explicit programs and markup. Sections 4 and 5 describe the data and training, with coding variants introduced in Section 5.3 .

Evaluation from reconstruction to complete creation systems. We assess tokenizer reconstruction across six visual domains, raster generation across five capability categories, and structured code generation across five tasks. One Nemotron-Labs-VisionCode variant leads the task-balanced aggregate among models evaluated on all five tasks: Chart2Code, MMSVG image-to-SVG and text-to-SVG, Design2Code, and Image2Struct. It surpasses Kimi K3.1 Pro ( Moonshot AI, 2026 ) with fewer total and active parameters (Section 6.3 ). At the system level, the Nemotron-native configuration raises GenEval2 Soft-TIFA GM from 31.71 to 52.56 and WISE Verified from 46.30 to 88.60 with the same raster generator. With our best setting, the framework is competitive with GPT Image 2 and Nano Banana Pro across most benchmarks with available comparisons.

#### 2.1 Pixel as Code: Discrete Representations and Renderers

Let $q$ denote the user request, $v$ optional reference material, and $r$ the chosen representation. Visual creation produces a discrete representation $c_{r}$ and a rendered view $\hat{I}$ :

[Tableau] $$c_{r}\sim G_{r}(\,\cdot\mid q,v),\qquad\hat{I}=R_{r}(c_{r}),$$ (1)

where $G_{r}$ generates the representation and $R_{r}$ renders it (Figure 6 ). Here, code refers to either learned discrete visual tokens or an explicit artifact representation. This abstraction does not require all representations to share a vocabulary or renderer. Instead, it exposes a common interface through which an artifact can be executed, rendered, visually inspected, and, when its representation is editable, revised.

For the raster image route , the image tokenizer provides both the discrete representation and the rendering interface. Its encoder $E$ maps an image $I$ to discrete visual tokens $\mathbf{z}=E(I)$ , while its decoder $D$ reconstructs a raster image $\hat{I}=D(\mathbf{z})$ . This separation between discrete representation learning and generation builds on vector-quantized autoencoders ( van den Oord et al., 2017 ; Esser et al., 2021 ) ; HART ( Tang et al., 2025 ) further studies hybrid discrete and continuous visual representations. Nemotron-Labs-Image-30B-A3B serves as the raster image generator : it autoregressively predicts discrete visual tokens, and the tokenizer decoder acts as their learned renderer. Encoding supplies representations for reference images and training targets, whereas decoding converts generated codes into visible pixels. For a direct raster request, the rendered candidates are final artifact candidates.

For structured routes , the generated representation explicitly exposes content, geometry, and layout through formats such as SVG, HTML/CSS/JavaScript, presentation objects, document structures, or plotting programs. Corresponding SVG engines, browsers, office renderers, plotting runtimes, and document compilers convert these representations into visual evidence. Because the source representation remains accessible, localized edits can be applied after visual inspection. A hybrid route additionally embeds one or more generated raster assets within a structured artifact while preserving text, shapes, layout, and interactions in an editable representation. For browser-based artifacts, the Nemotron-native configuration assigns code generation to a Dual Coder composed of Nemotron 3 Ultra ( Blakeman et al., 2026 ) and Nemotron-3.5-Super-VL. Native presentation, document, and SVG outputs use format-specific generators and renderers. We separately train Nemotron-Labs-VisionCode for this interface (Section 5.3 ) and evaluate the models in standalone tests (Section 6.3 ).

#### 2.2 Agentic Creation Loop

Prior agentic scene-generation systems combine planning with visual feedback: SAGE ( Xia et al., 2026 ) coordinates generation tools and critics, and Scenethesis ( Ling et al., 2026 ) integrates language-based planning, visual layout refinement, and scene judging. Our harness makes this feedback operational through a resolved layout contract, renderer-grounded evidence, a root-cause report, and explicit repair ownership (Figure 5 ).

Routing and structured planning. Nemotron-3.5-Super-VL classifies each request as a natural image, structured canvas, interactive interface, multi-page document, or visual series. It jointly determines the target surface, output representation, canvas count, rendering backend, and whether generated raster assets are absent, optional, or required. Search and reference retrieval are invoked conditionally, only when external factual or visual grounding materially affects the request. Nemotron 3 Ultra then produces a semantic artifact plan. For structured and hybrid routes, this plan is resolved into a layout contract that specifies the layout mode, ordered regions, normalized bounds, component ownership, and rendering constraints.

Direct raster creation. Natural-image requests bypass structured code generation. Nemotron-Labs-Image-30B-A3B produces multiple raster candidates from the planned visual brief, optional references, and a supported aspect ratio. Acting as the multimodal judge, Nemotron-3.5-Super-VL compares the rendered candidates against the original request and retains the strongest image. This route therefore uses semantic planning and visual selection, but does not invoke the structured artifact repair loop described below.

Structured and hybrid artifact creation. Structured artifacts use explicit code or native document representations, while hybrid artifacts additionally request raster assets from Nemotron-Labs-Image-30B-A3B. In the browser-based Dual Coder configuration, Nemotron 3 Ultra and Nemotron-3.5-Super-VL independently instantiate the same frozen plan and asset manifest. Native presentation, document, and SVG routes use their corresponding format-specific generation workflows. Each candidate is executed or rendered and visually inspected before an eligible candidate is retained as the initial artifact checkpoint $C_{0}$ . Raster generation supplies requested image content, whereas the structured representation determines how assets, text, shapes, and interactions are composed into an editable artifact.

Evidence-grounded visual audit and targeted repair. For browser-based artifacts, the audit combines deterministic renderer evidence with a multimodal review against the frozen request and acceptance checklist. Renderer evidence identifies failures such as execution errors, missing regions, clipping, overlap, out-of-bounds geometry, and broken interactions. Nemotron-3.5-Super-VL evaluates the visible artifact and proposes a diagnosis code, causal evidence, a confidence score, and an owner within the rendered structure. Before automatic repair is applied, the harness validates this proposal against stable artifact selectors. Native formats use their own rendering, inspection, and review workflows.

The browser-based repair workflow distinguishes the visible diagnosis from the underlying repair target . Diagnosis codes cover component rendering, collision, containment, spatial density, typography, color contrast, layout structure, content fidelity, visual-asset quality, and interaction behavior. Repair targets identify the responsible layer: visual plan, asset, layout, code, interaction, or content . Findings associated with the same causal owner are grouped into a root-cause tree, allowing the harness to repair a shared cause while freezing unaffected pages or regions. Asset-related findings can trigger raster regeneration; planning or layout findings can trigger a localized replan; and code, interaction, or content findings are assigned to the structured generation path. Every resulting candidate is executed, rendered, audited, and compared with the retained checkpoint. The numbers of accepted repair rounds and total attempted repair cycles are bounded separately.

Checkpoint retention and output selection. For exposition, let $C_{t}=(P_{t},A_{t},c_{t},\hat{I}_{t})$ denote the artifact state after round $t$ , comprising its plan, assets, explicit representation, and rendered view. This tuple is a conceptual summary; the implementation additionally retains the frozen checklist, deterministic inspection results, multimodal review, and repair-validation records. Best-candidate retention can be expressed as

[Tableau] $$C^{\star}_{0}=C_{0},\qquad C^{\star}_{t}=\operatorname{Select}\!\left(q,C^{\star}_{t-1},C_{t}\right).$$ (2)

For ordinary browser-based requests, the selection operator first applies deterministic fatal-render guards and then performs a blind pairwise comparison between an eligible candidate and the incumbent using the same frozen request checklist. A tie or an insufficient-confidence decision retains the earlier incumbent. Native-format routes retain the strongest rendered candidate according to their format-specific inspection and judging criteria. The loop terminates when the audit passes, no eligible improvement is found, or the configured repair budget is exhausted. The retained checkpoint provides the editable artifact together with its rendered preview.

Implementation details. Before generation, the browser-based workflow freezes the request checklist and resolved layout contract. A candidate passes only when both deterministic rendering checks and the multimodal visual audit pass. The default harness configuration generates up to four candidates for each raster-generation job. The browser-based repair loop permits up to three accepted repairs within eight attempted repair cycles and retains the incumbent when pairwise selection returns a tie or confidence below $0.75$ . Model and renderer assignments are summarized in Section 3 . The routing and review prompt contracts, retrieval policies, machine-readable schemas, and harness control limits are documented in Appendix B .

Qualitative self-correction examples. Figure 7 shows three representative before-and-after repairs. In the furniture landing page, the agent resolves text–image overlap and restores the content hierarchy. In the FrostLine landing page, it restores the missing visual asset and reorganizes the hero and workflow sections. In the city-population chart, it recovers all 20 bars together with their values, city labels, and legend entries. These examples show how the agent translates rendered feedback into targeted edits while preserving the unaffected parts of the design.


### 3 System Components

The framework combines planning, discrete representation generation, rendering, and visual inspection. We describe these component responsibilities below. Section 4 presents data for both generation routes, and Section 5 describes training for the image tokenizer, raster image generator, and structured code generator.


#### 3.1 Planning and Tool Coordination

Nemotron-3.5-Super-VL ( NVIDIA, 2026b ) first performs artifact routing, and Nemotron 3 Ultra ( Blakeman et al., 2026 ) serves as the planner. Ultra turns the request and any retrieved context into a semantic plan. Structured and hybrid routes additionally resolve a layout contract with ordered regions, normalized bounds, component ownership, and rendering constraints. During repair, Ultra receives issues assigned to plan revision and updates the affected specification. Harness services supply search and reference retrieval when external grounding is needed. The shared interface in Equation 1 lets planning coordinate raster assets and explicit code within the same artifact.


#### 3.2 Discrete Representation Generators


##### 3.2.1 Raster Image Generator

Nemotron-Labs-Image-30B-A3B is an autoregressive raster image generator. Given text and optional source or reference images, it predicts a discrete visual-token sequence that the tokenizer decoder renders into a raster image. Training includes text-to-image generation and text-and-image-conditioned generation (TI2I) with flexible aspect ratios. TI2I covers image editing, multi-turn generation, and synthesis from one or more visual references.

The generator is initialized from Nemotron 3 Nano 30B-A3B and retains its hybrid Mamba2–Transformer MoE architecture and attention configuration ( NVIDIA, 2025c ; Dao and Gu, 2024 ) . Text prompts, reference images, and target images are represented as discrete tokens within a unified causal sequence. Section 5.2 describes its multistage mid-training and reinforcement learning.


##### 3.2.2 Structured Code Generator

The multimodal-coding component generates representations with explicit content and structure: plotting programs for charts, SVG from images or text, HTML/CSS from visual designs, edits to existing webpage code, and document markup. These outputs are interpreted by the corresponding rendering backends described below.

For browser-based artifacts, the Dual Coder combines Nemotron 3 Ultra and Nemotron-3.5-Super-VL for code generation and code or layout repair. The two models independently materialize the same frozen plan and asset manifest, then revise the code when visual diagnosis assigns an issue to this component. Native presentation, document, and SVG routes use format-specific generation workflows.

Nemotron-Labs-VisionCode is the model family we train and evaluate for the same structured-code interface. Its multimodal-coding supervision covers the explicit representations and editing operations needed by these tasks (Section 4.3 ). Section 5.3 introduces the model variants and their base models. Section 6.3 reports their standalone execution and quality results against reference models. These measurements evaluate the trained coding models; the Dual Coder is a separate harness-level model assignment.


#### 3.3 Rendering Backends


##### 3.3.1 Learned Image Renderer: Tokenizer Decoder

The dedicated image tokenizer, Nemotron-Labs-Image-Tokenizer , has approximately 642M parameters and uses a fixed Leech-lattice codebook ( Zhao et al., 2024 ; Zhao et al., 2025b ) . Its encoder discretizes a raster image into a compact visual-token sequence; its decoder is the learned image renderer that converts predicted tokens back to pixels. This separates prediction of the discrete representation from its visual realization.

The encoder and decoder follow a vision-transformer design ( Dosovitskiy et al., 2021 ) , each with 24 layers, a hidden width of 1,024, 16 attention heads, and an MLP ratio of 4. The tokenizer uses $16\times 16$ patches and 24-dimensional quantized embeddings with L2 normalization. Its codebook contains 196,560 normalized Leech-lattice vectors and remains fixed during training. Rotary position embeddings ( Su et al., 2021 ) use a base of 10,000. The decoder uses an output FFN with a configured dimension of 3,072 and clamps reconstructed values to $[-1,1]$ . ##### 3.3.2 Structured Rendering Backends

SVG engines render vector markup ( W3C, 2018 ) , browser engines render HTML/CSS/JavaScript ( WHATWG, 2026 ) , and office renderers, plotting runtimes, or document compilers render their respective representations. These backends play the same interface role as the tokenizer decoder: they map generated discrete representations to visual outputs that can be inspected. Their source representations also expose elements such as shapes, text, and layout for targeted edits. The harness executes and renders revised representations after repair and preserves artifact checkpoints for subsequent comparison.


#### 3.4 Multimodal Perception and Evaluation

Nemotron-3.5-Super-VL provides visual assessment and candidate selection in addition to its routing and coding roles. Direct raster requests use it to select an image. In the browser-based repair loop, its audit evaluates the rendered artifact against the frozen request checklist; the root-cause tree groups issues by causal owner for assignment to the responsible component; and pairwise selection identifies the artifact state to retain. Deterministic rendering checks and validation of artifact selectors supplement the multimodal review. Native formats use their own inspection and judging workflows. These responsibilities share rendered visual evidence but follow the route-specific control flow in Section 2.2 .


### 4 Training Data

The data pipeline follows the three trainable components of the framework: the image tokenizer learns the discrete raster representation and its renderer; Nemotron-Labs-Image-30B-A3B learns to predict visual tokens from conditioning inputs; and Nemotron-Labs-VisionCode learns to generate explicit programs and markup. We describe the data for each component in this order, following the representation–renderer interface of Section 2 .


#### 4.1 Image Tokenizer Data

We curate an approximately 200M-image pool from the NVCLIP image corpus ( NVIDIA, n.d. ) through clustering, deduplication, and filtering using SigLIP 2 ( Tschannen et al., 2025 ) , DINOv2 ( Oquab et al., 2023 ) , and SSCD ( Pizzi et al., 2022 ) . We train the tokenizer on approximately 153M images from this pool.

Images provide reconstruction targets for learning the encoder and decoder described in Section 3.3.1 . The resulting encoder supplies discrete visual tokens for raster image generation, while the decoder renders predicted tokens back into images. Section 5.1 details the reconstruction, perceptual, distillation, and adversarial objectives.


#### 4.2 Raster Image Generation Data

The raster image data pipeline combines text-to-image generation (T2I) with text-and-image-conditioned generation (TI2I). T2I conditions on a textual description; TI2I additionally conditions on one or more source or reference images. TI2I covers image editing, generation from visual references, and multi-turn generation using preceding visual context. Both task families use the image tokenizer to convert target images into the discrete visual codes predicted by the generator introduced in Section 3.2.1 .


##### 4.2.1 Text-to-Image Data

Data Collection. The web-scale portion of our text-to-image collection contains approximately 326M image–text pairs . It combines GPIC ( Chandrasegaran et al., 2026 ) , Conceptual 12M (CC12M) ( Changpinyo et al., 2021 ) , CommonCatalog CC-BY and CommonCatalog CC-BY-SA ( Gokaslan et al., 2023 ) , Megalith ( madebyollin, n.d. ) , and WIT ( Srinivasan et al., 2021 ) . Together, these collections provide broad coverage of visual concepts, web photographs, encyclopedic imagery, and visual content embedded in documents.

We supplement these sources with approximately 48M synthetic images generated with Z-Image ( Z-Image Team, 2025 ) , bringing the text-to-image collection to approximately 374M examples for mid-training.

Data Annotation and Filtering. We annotate images using Qwen3.5-27B, Qwen3.5-397B-A17B, and Qwen3.5-4B ( Qwen Team, 2026 ) . We remove watermarked and low-quality images, and use Qwen3.5-397B-A17B to filter out captions that do not align with the image content.


##### 4.2.2 Data Across Training Stages

The raster generator uses arbitrary-resolution mid-training with progressively increasing maximum image areas of $256^{2}$ , $512^{2}$ , and $1024^{2}$ pixels, allowing variable aspect ratios within each stage (Section 5.2.1 ). Reinforcement learning uses a prompt collection that is refreshed to emphasize harder semantic constraints and a broader distribution of resolutions and aspect ratios, as described in Section 5.2.2 .


#### 4.3 Structured Code Generation Data

The multimodal-coding mixture contains approximately 4.7M effective training examples , including configured sampling repetitions. It covers visual reconstruction, text-conditioned program generation, editing, and code understanding across several artifact types.

Vector-graphics and visual-program examples support SVG generation, editing, and understanding ( Wang et al., 2025a ; Zhao et al., 2025a ; Rodriguez et al., 2025 ) . Web examples connect rendered pages to their source code and provide generation and editing supervision ( Yun et al., 2024 ; Sun et al., 2025 ) . Chart and visualization examples cover plotting code, structured chart representations, and program understanding ( Xu et al., 2025b ; Ni et al., 2025b ; Ni et al., 2025a ) .

The mixture also includes formula transcription ( Blecher, 2025 ) , table-to- L a T e X conversion, and CAD-related supervision ( Niu et al., 2025a ) , supplemented by teacher-generated chain-of-thought examples and direct ground-truth anchors. Together, these task groups connect visual appearance and user intent to the explicit representations predicted by Nemotron-Labs-VisionCode; Section 5.3 describes their use in supervised adaptation.


### 5 Training

Training is organized around three components of the Pixel as Code framework. The image tokenizer learns a discrete visual representation and its decoder. The raster image generator , Nemotron-Labs-Image-30B-A3B, learns to predict visual tokens, and the structured code generator , Nemotron-Labs-VisionCode, learns to produce explicit programs and markup from the multimodal-coding mixture in Section 4.3 . We describe their training separately in Sections 5.1 , 5.2 , and 5.3 , following the component definitions in Section 3 .


#### 5.1 Image Tokenizer Training

The image tokenizer learns a discrete visual representation and its rendering interface from the NVCLIP images described in Section 4.1 , using the architecture in Table 1 . Training spans 670K steps and combines pixel reconstruction, perceptual supervision, feature distillation, and adversarial learning. The codebook remains fixed, while the encoder is frozen after 480K steps. The decoder continues to learn to reconstruct images from the resulting discrete codes.

Visual compression determines both reconstruction fidelity and the sequence budget for generation. Cosmos ( NVIDIA, 2025a ) develops visual tokenizers for world modeling, DC-AE ( Chen et al., 2024a ) studies deep compression for high-resolution diffusion, and DC-AR ( Wu et al., 2025a ) uses a deep-compression hybrid tokenizer for masked autoregressive generation. In our tokenizer, the $16\times 16$ patch size represents a $256\times 256$ image with 256 tokens, compared with 1,024 tokens for $8\times 8$ patches. In our tokenizer study, this setting enables $4\times$ more samples per node. This trade-off connects the fidelity of the learned renderer to the sequence budget of the raster image generator.

Reconstruction. We use an L1 reconstruction loss with weight 1.0 and an LPIPS perceptual loss ( Zhang et al., 2018 ) with weight 0.1.

Decoder feature distillation. We use DINOv2 ViT-L ( Oquab et al., 2023 ) as the distillation teacher. Student features are taken from the third decoder block, projected through an MLP, and aligned to the teacher’s spatial grid using two-dimensional adaptive average pooling. Both student and teacher features are L2-normalized independently at each token. For the resulting $N$ aligned token pairs $(s_{i},t_{i})$ , the distillation loss is the negative mean cosine similarity,

[Tableau] $$\mathcal{L}_{\mathrm{distill}}=-\frac{1}{N}\sum_{i=1}^{N}\cos(s_{i},t_{i}),\qquad\lambda_{\mathrm{distill}}=0.1.$$ (3)

This auxiliary supervision acts on the learned decoder and supports arbitrary image resolutions through spatial feature alignment.

Adversarial training. An unconditional PatchGAN discriminator ( Isola et al., 2017 ) operates on RGB images with three layers, a base width of 64, $4\times 4$ kernels, and batch normalization ( Ioffe and Szegedy, 2015 ) . It uses the pad_max mode for arbitrary resolutions, with blur downsampling and ActNorm disabled. The GAN objective is softplus, with a configured discriminator weight of 0.5 and adaptive discriminator weighting disabled. Adversarial training starts at step 0. R1 regularization ( Mescheder et al., 2018 ) uses $\gamma=10$ and is evaluated once every 16 steps with lazy regularization ( Karras et al., 2020 ) . On regularization steps, the R1 penalty is multiplied by $(\gamma/2)\times 16=80$ , giving a time-averaged coefficient of $\gamma/2=5$ . Table 2 collects these loss settings and the training configuration.

Quantizer training. We keep the codebook fixed throughout training and use a straight-through estimator ( Bengio et al., 2013 ; van den Oord et al., 2017 ) to propagate gradients through discrete quantization. The training objective does not include a commitment loss.

Variable-resolution token packing. Each image is represented as a sequence of $16\times 16$ patches. We pack sequences of different lengths into a batch while preserving image boundaries, so images retain their individual spatial resolutions without padding every sequence to a common length. ##### 5.2.2 Reinforcement Learning

Reinforcement learning has been studied for both discrete autoregressive image generation, as in X-Omni ( Geng et al., 2025 ) , and diffusion models. Data-regularized RL ( Ye et al., 2025 ) combines reward optimization with diffusion-based data regularization. We describe our discrete-token policy and its reward-driven training procedure below.

From supervised learning to preference optimization. Building on multistage mid-training, we introduce reinforcement learning once high-quality, prompt-faithful candidates consistently emerge under repeated sampling. This best-of- $N$ headroom provides a strong on-policy learning signal: repeated rollouts explore new compositions of the concepts and visual patterns acquired during mid-training, while reward-guided updates consolidate successful discoveries into reliable single-sample behavior. We adopt a two-stage RL scheme: broad-coverage optimization followed by learnability-driven data refresh to sustain informative learning signals as the policy improves.

Stage I: broad-coverage RL. The first RL stage draws from a broad prompt distribution spanning object-centric generation, attribute binding, counting, spatial relations, interactions, complex scene composition, stylistic control, and text rendering. This diverse coverage encourages the policy to explore and combine its acquired visual knowledge across a wide range of generation requirements. For every prompt, the current policy generates a group of candidates and receives pointwise alignment and image-quality scores. Groups with sufficient reward variation yield informative relative advantages, providing a discriminative learning signal for group-relative policy optimization.

Stage II: learnability-driven data refresh. As Stage I proceeds, easy prompts increasingly produce uniformly strong candidates and their within-group alignment-score range contracts. We retain for GRPO only prompt groups with sufficient within-group reward variation; groups lacking a discriminative relative ordering are discarded before the policy update. The growing prevalence of low-range groups signals that the current prompt distribution no longer matches the policy’s evolving learning frontier. We therefore refresh the prompt distribution while preserving the reward definition and optimizer state. The refreshed mixture retains structured compositional prompts, redistributes general prompts across multiple resolutions and aspect ratios according to the empirical prior of our mid-training corpus, and introduces longer, more challenging prompts with denser semantic and compositional constraints. Pairing these difficult cases with diverse image geometries restores informative reward variation without changing the optimization objective. The resulting loop— roll out, diagnose, recurate, and improve —uses the model’s evolving behavior to identify which examples can still induce informative on-policy comparisons. Our two-stage RL training instantiates one iteration of this broader self-improvement process. We next detail the optimization procedure used to obtain the RL-aligned policy. We first formulate autoregressive image generation as a discrete-token policy, then define the pointwise reward and group-relative objective, and finally describe the rollout filtering and distributed execution used in training. We optimize the policy with Group Relative Policy Optimization (GRPO) ( Shao et al., 2024 ) . Because trajectories are regenerated from the continually updated policy rather than drawn from a fixed preference set, successive rollout iterations explore previously unrealized combinations of the model’s acquired knowledge, while group-relative rewards determine which discoveries are reinforced by subsequent policies.

Discrete-token policy. Let $\mathbf{x}$ denote the prompt tokens and $\mathbf{z}=(z_{1},\ldots,z_{T})$ the discrete visual-token sequence generated by $\pi_{\theta}$ . The tokenizer decoder renders $\hat{I}=D(\mathbf{z})$ , instantiating Equation 1 . The autoregressive policy factorizes as

[Tableau] $$\pi_{\theta}(\mathbf{z}\mid\mathbf{x})=\prod_{t=1}^{T}\pi_{\theta}\!\left(z_{t}\mid\mathbf{x},\mathbf{z}_{<t}\right).$$ (5)

This permits direct application of the token-level GRPO objective used for language models. Prompt and reference-image tokens provide context but are excluded from the action loss; the action mask selects only generated response tokens, including visual-token IDs.

Composite pointwise reward. Each candidate code is rendered by the tokenizer decoder at its requested resolution and independently evaluated against the original prompt by a pointwise VLM judge. The judge scores six alignment dimensions—including counting, relations, actions, and text rendering—together with technical image quality. After aggregation and normalization to $[0,1]$ , we define

[Tableau] $$R(\mathbf{x},\mathbf{z})=0.7\,\bar{r}_{\mathrm{align}}(\mathbf{x},\mathbf{z})+0.3\,\bar{r}_{\mathrm{quality}}(\mathbf{x},\mathbf{z}),$$ (6)

One judge call produces both components under the same visual evidence and rubric. The complete instruction, structured output, and aggregation rule are given in Appendix A .

Group-relative credit assignment. For each prompt, the rollout policy samples $\mathcal{G}(\mathbf{x})=\{\mathbf{z}^{(i)}\}_{i=1}^{G}$ and normalizes rewards within this group:

[Tableau] $$A_{i}=\frac{R(\mathbf{x},\mathbf{z}^{(i)})-\mu_{\mathcal{G}}}{\sigma_{\mathcal{G}}+\epsilon},\qquad\mathbf{z}^{(i)}\in\mathcal{G}(\mathbf{x}),$$ (7)

where $\mu_{\mathcal{G}}$ and $\sigma_{\mathcal{G}}$ are the group statistics. This removes prompt-specific score offsets, and the resulting sequence-level advantage $A_{i}$ is shared by all generated tokens in trajectory $i$ . Let $m_{i,t}$ be the action mask and $\rho_{i,t}(\theta)$ the likelihood ratio between the current and rollout policies for token $z_{t}^{(i)}$ . The PPO-style clipped objective ( Schulman et al., 2017 ) is

[Tableau] $$\begin{split}\mathcal{L}_{\mathrm{GRPO}}(\theta)=-\mathbb{E}_{\begin{subarray}{c}\mathbf{x}\sim\mathcal{D},\\ \mathbf{z}^{(i)}\sim\pi_{\theta_{\mathrm{old}}}\end{subarray}}\Bigg[\frac{1}{\sum_{i,t}m_{i,t}}\sum_{i,t}m_{i,t}\min\Big(&\rho_{i,t}(\theta)A_{i},\\ &\operatorname{clip}(\rho_{i,t}(\theta),1-\epsilon_{\mathrm{lo}},1+\epsilon_{\mathrm{hi}})A_{i}\Big)\Bigg].\end{split}$$ (8)

> Figure 10 : Stage I saturation diagnostics. (a) RL reward over valid images; the light and dark curves show per-iteration values and a short-window median. (b) Fraction of fully valid groups satisfying Eq. 9 , audited every ten iterations; markers and line show the observations and their trend.

We use $\epsilon_{\mathrm{lo}}=0.20$ , $\epsilon_{\mathrm{hi}}=0.28$ , a learning rate of $2\times 10^{-6}$ , and no explicit KL penalty; Table 4 summarizes the remaining settings.

Rollout and update schedule. Each rollout iteration samples $G=32$ candidates at temperature 1.0 for each of $B=48$ prompts, yielding 1,536 trajectories. Keeping prompt groups intact, we partition them into two disjoint batches of 768 trajectories and take one optimizer step per batch; every trajectory is therefore used once. Consequently, the reported 200 rollout iterations correspond to 400 optimizer steps. In pilot experiments, smaller groups produced noisy baselines and often failed to improve reward, whereas $G=32$ more reliably exposed meaningful within-prompt reward variation.

Reward-range group filtering. Before optimization, we retain a prompt group only when its alignment-score range on the original 0–10 scale satisfies

[Tableau] $$\max_{i\in\mathcal{G}}r_{\mathrm{align},i}-\min_{i\in\mathcal{G}}r_{\mathrm{align},i}\geq 2.$$ (9)

This removes both saturated groups whose candidates are uniformly strong and failed groups with no useful relative ordering. Rejection does not shrink the update batch: the sampler draws a new prompt and repeats generation and reward evaluation until all $B=48$ accepted groups have been collected. The accepted-group yield therefore measures how much of the current prompt distribution still provides informative within-group comparisons.

Figure 10 isolates the dynamics of Stage I, before the prompt and resolution distribution is changed. Panel (a) reports the mean RL reward over successfully decoded images at every rollout iteration. Panel (b) audits the fraction of complete prompt groups for which all 32 candidates decode successfully and the alignment-score range satisfies Eq. 9 . As optimization proceeds, reward rises and gradually approaches a plateau, whereas the yield of informative groups decreases. This divergence indicates that the policy is improving on the current distribution while an increasing fraction of prompts no longer produces sufficiently discriminative within-group comparisons. We use this saturation signal to motivate the Stage II data refresh described above, replacing increasingly exhausted prompts with harder semantic constraints and a broader resolution distribution.

Rollout-policy consistency. Rollouts and gradient computation use separate inference and training implementations. To suppress bias from small numerical discrepancies over long visual-token sequences, we compute the geometric-mean likelihood ratio

[Tableau] $$g_{i}=\exp\!\left(\frac{1}{\sum_{t}m_{i,t}}\sum_{t}m_{i,t}\log\frac{\pi_{\theta_{\mathrm{old}}}(z_{t}^{(i)}\mid\mathbf{x},\mathbf{z}_{<t}^{(i)})}{\pi_{\mathrm{roll}}(z_{t}^{(i)}\mid\mathbf{x},\mathbf{z}_{<t}^{(i)})}\right).$$ (10)

We retain sequences with $g_{i}\in[0.95,1.05]$ and apply token-level importance weights to the surviving losses.

Scalable asynchronous execution. Following large-scale image RL systems ( Xu et al., 2026 ) , we decouple rollout generation, reward evaluation, and policy optimization across 256 GPUs. Disaggregated actors, inference engines, and decoding workers overlap generation with asynchronous VLM scoring. Failed scorer requests are retried; unrecoverable groups are discarded and backfilled rather than assigned artificial zero rewards. We checkpoint every 25 rollout iterations and retain complete rollout records for auditing.

The reward design follows the requirements of each structured-code task. Execution checks assess whether generated programs run successfully, markup renders, edits can be parsed, and documents compile. Quality scores measure visual fidelity for reconstruction, text-image alignment and aesthetics for text-to-SVG generation, and edit accuracy for code editing. These outcome-based signals complement supervised fine-tuning by rewarding functional correctness and the quality of the resulting artifacts.

We evaluate both trained variants against their respective base models using execution, compilation, rendering, and task-specific quality metrics (Section 6.3 ).

Configurations and metrics. We evaluate two members of the Nemotron-Labs-VisionCode family: Nemotron-Labs-VisionCode-30B-A3B and Nemotron-Labs-VisionCode-120B-A12B , referred to below as the 30B and 120B variants. Execution, compilation, and render success rates are percentages; quality metrics retain their original scales. Chart2Code reports F1 and execution success. Overall score. We normalize each metric as $s_{m,j}=100x_{m,j}/\max_{k}x_{k,j}$ , where $x_{m,j}$ is model $m$ ’s value for metric $j$ and the maximum is over models with a reported value for that metric. Overall in Table 11 covers two tasks, while Overall in Table 12 covers three. ### 7 Related Work


#### 7.1 Agentic Visual Creation

Visual creation increasingly combines generative models with planning, retrieval, and feedback. Mind-Brush ( He et al., 2026 ) retrieves multimodal evidence and uses reasoning tools to ground unfamiliar concepts and interpret implicit requests before image generation. For 3D environments, SAGE ( Xia et al., 2026 ) coordinates generators and critics through iterative tool use, while Scenethesis ( Ling et al., 2026 ) combines language-based scene planning with visual layout refinement and spatial verification. COMFYCLAW ( Li et al., 2026c ) constructs image-generation workflows through typed graph edits, uses region-level visual verification to guide repairs, and distills execution experience into reusable skills. At the candidate-selection level, Sana 1.5 ( Xie et al., 2025 ) studies inference-time scaling through repeated sampling and vision-language judging. These works establish planning, visual assessment, and revision as useful parts of a creation workflow. Nemotron-Labs-VisualCreation organizes these responsibilities around a shared representation–renderer interface for raster images, structured outputs, and artifacts that combine both. Its route-specific control flow connects visual feedback to asset replacement, code and layout repair, or plan revision.


#### 7.2 Visual Tokenization and Raster Generation

Discrete image representations connect visual reconstruction to sequence modeling. VQ-VAE ( van den Oord et al., 2017 ) learns quantized latent representations with an autoregressive prior, and VQGAN ( Esser et al., 2021 ) combines perceptual image compression with transformer-based synthesis. Binary Spherical Quantization ( Zhao et al., 2024 ) and Spherical Leech Quantization ( Zhao et al., 2025b ) study geometric constructions for visual quantization; the latter provides the fixed lattice codebook used in Nemotron-Labs-Image-Tokenizer. Efficient representation learning is also central to DC-AE ( Chen et al., 2024a ) , which studies higher spatial compression for latent diffusion. HART ( Tang et al., 2025 ) and DC-AR ( Wu et al., 2025a ) combine discrete structure with residual representations to support efficient visual generation. These studies motivate evaluating reconstruction quality and encoding and decoding cost alongside the downstream generator.

Raster generation spans several modeling spaces. Edify Image ( NVIDIA et al., 2024 ) uses cascaded pixel-space Laplacian diffusion, Sana ( Xie et al., 2024 ) combines compressed latents with a linear diffusion transformer, and PixelDiT2 ( Yu et al., 2026 ) supplies frozen visual representations to guide pixel-space denoising. Native multimodal models broaden the conditioning and output interface: Emu3.5 ( Cui et al., 2025 ) learns from interleaved vision and language through next-token prediction, while Cosmos 3 ( NVIDIA, 2026a ) jointly supports understanding and generation across modalities. In this report, Nemotron-Labs-Image-30B-A3B predicts discrete visual tokens, and a separately trained tokenizer decoder renders them into pixels. This assignment gives raster generation a concrete role within the same creation interface as explicit visual programs.


#### 7.3 Multimodal Understanding and Visual Grounding

Visual inspection ( Guan et al., 2024 ; Liu et al., 2024a ) depends on understanding both the artifact and the request that constrains it. Eagle 1 ( Shi et al., 2025 ) and Eagle 2 ( Li et al., 2025b ) study data strategies for vision-language post-training, including data diversity, quality, and mixture design. Eagle 2.5 ( Chen et al., 2025 ) extends this direction to long-context multimodal learning and high-resolution image understanding, with sampling and training strategies that preserve visual detail and context. LocateAnything ( Wang et al., 2026 ) addresses spatial grounding through Parallel Box Decoding, predicting the coordinates of a box or point jointly and supporting tasks such as object detection, text localization, document layout, and GUI grounding. Cosmos-Reason1 ( NVIDIA, 2025b ) studies physical common sense and embodied reasoning from visual observations. Vision-SR1 ( Li et al., 2025c ) decomposes visual and language reasoning to construct self-rewards for vision-language model training. Complementary perception tasks include chart understanding through MMC ( Liu et al., 2024b ) , linking figures to document text through DocumentCLIP ( Liu et al., 2023a ) , and color perception and reasoning through ColorBench ( Liang et al., 2025 ) . Together, these lines of work provide context for retaining reference information, interpreting rendered content, and linking observations to spatial regions. Our harness assigns artifact auditing and candidate selection to Nemotron-3.5-Super-VL ( NVIDIA, 2026b ) and combines these judgments with rendering and structural checks (Section 3.4 ).


#### 7.4 Structured Visual Code Generation

Explicit code exposes visual elements and their relationships to editing and execution. StarVector ( Rodriguez et al., 2025 ) generates SVG code from visual and textual inputs, while OmniSVG ( Yang et al., 2025 ) models vector commands and coordinates for conditional SVG generation. Broader multimodal-coding systems connect visual inputs to several program families: JanusCoder ( Sun et al., 2025 ) develops a visual-programmatic interface across charts and interactive web content, VisCodex ( Jiang et al., 2025 ) combines vision and coding models, and VinciCoder ( Zhao et al., 2025a ) uses rendered similarity for visual reinforcement learning. VisualClaw ( Tu et al., 2026 ) incorporates an agent harness for efficient execution of coding tasks and self-improvement in real-world scenarios. These directions connect program correctness with the appearance of the executed output.

We train both Nemotron-Labs-VisionCode variants for the explicit-code side of Pixel as Code and evaluate them on execution, compilation, rendering, and task-specific quality (Section 6.3 ). At the framework level, rendering connects editable programs and learned visual tokens, including raster assets embedded in structured artifacts.


### 8 Conclusion

We presented Nemotron-Labs-VisualCreation, an agentic framework that brings raster synthesis and editable structured creation together through Pixel as Code . Learned visual tokens and explicit programs share a generate, render, and inspect interface. The harness uses rendered feedback for candidate selection and targeted browser repair.

Our tokenizer improves reconstruction fidelity across six visual domains and reduces encoding and decoding costs on A100 and L4. In standalone visual coding, both Nemotron-Labs-VisionCode variants improve chart and SVG reconstruction over their respective base models. The 120B variant leads the task-balanced aggregate across five visual coding tasks among models with complete coverage, surpassing Kimi K3.1 Pro with fewer total and active parameters. At the system level, the Nemotron-native configuration improves GenEval2 and WISE Verified with the same raster generator. With our best setting, the framework is competitive with GPT Image 2 and Nano Banana Pro across most benchmarks with available comparisons.

Reconstruction gains vary across perceptual and distribution metrics. The system comparisons measure the complete workflow, and the standalone coding tests evaluate the trained variants separately from the harness Dual Coder. Future work can isolate individual agent capabilities under matched inference budgets and evaluate text-and-image-conditioned editing and multi-reference generation.

#### A.3 Score Aggregation

Let $s_{k}\in[0,1]$ be the judge score for alignment field $k$ after division by 10, and let $a_{k}\in\{0,1\}$ indicate whether that field is applicable. We aggregate the applicable fields as

[Tableau] $$\bar{r}_{\mathrm{align}}=\frac{\sum_{k}a_{k}w_{k}s_{k}}{\sum_{k}a_{k}w_{k}},\qquad\mathbf{w}=(0.35,0.25,0.15,0.15,0.10,0.25),$$ (11)

where the weights follow the field order subjects/count, attributes, layout/relations, actions/pose, scene/style, text rendering . The text-rendering term participates only when literal text is requested.

To prevent averaging from hiding severe failures, field scores at most 0.3 impose caps on $\bar{r}_{\mathrm{align}}$ : 0.35 for subjects/count, 0.55 for attributes, 0.65 for layout/relations or actions/pose, and 0.50 for text rendering when applicable. The image-quality score is normalized to $\bar{r}_{\mathrm{quality}}\in[0,1]$ and combined with alignment using Eq. 6 . ### Appendix B Harness Prompt Contracts and Runtime Configuration

This appendix records the implementation contracts used by the creation harness. It complements the conceptual description in Section 2.2 with the routing and review instructions, retrieval policy, machine-readable intermediate records, and bounded execution budgets. Model and renderer responsibilities are described separately in Section 3 .


#### B.1 Routing and Retrieval

The artifact router receives the original user request and optional reference material. It must select exactly one route from natural_image , structured_canvas , interactive_ui , multi_page_document , and visual_series . Its output additionally specifies the target surface, artifact subtype, aspect ratio, canvas count, primary format, visual-asset policy, rendering backend, and whether external search is required.

A standalone photograph, illustration, painting, or ordinary raster scene is routed to natural_image . Posters, charts, diagrams, infographics, and other single designed canvases use structured_canvas ; websites and application interfaces use interactive_ui ; presentations, reports, and other multi-page artifacts use multi_page_document ; and coordinated cards, storyboards, or other multi-canvas sets use visual_series . Explicit image-only or no-code instructions override weaker structural cues.

Retrieval is conditional rather than mandatory. Web search is used for factual grounding when current or externally verifiable information materially affects the requested artifact. Visual-reference search is used when external imagery is needed to establish subject appearance, style, or composition. Both are disabled when the request explicitly prohibits search. Retrieved material is converted into a bounded grounding record before planning and is not treated as an instruction that can override the user request.

#### B.3 Visual Review and Checkpoint Selection

The visual-review prompt receives the original request, the frozen acceptance checklist, a compact semantic plan, stable artifact selectors, and canonical rendered evidence. It evaluates instruction fidelity, required visible content, layout and hierarchy, typography, composition, asset quality, interaction feedback, accessibility, and rendering completeness. Each reported issue must identify visible evidence, the blocked requirements, a repair target, and a root-cause hypothesis. The reviewer cannot return pass=true while a hard-contract or required-content item remains visibly unsatisfied.

The pairwise selector receives two anonymously ordered rendered artifacts generated for the same request. It compares them only against visible evidence and the frozen checklist, without access to model identity or repair-round metadata. Hard-contract violations cannot be compensated for by aesthetic quality. The selector returns one artifact or a tie together with a confidence score and visible justification. A tie or confidence below $0.75$ retains the earlier incumbent. If pairwise evaluation is unavailable, checkpoint selection falls back to deterministic render guards and scalar ordering.
