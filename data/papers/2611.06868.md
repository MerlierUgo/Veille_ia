## On Turn-Level Best-of-N Sampling for Scaling LLM Agents

In this work, we evaluate a simple inference-time scaling approach based on turn-level best-of-N sampling (Turn-BoN) for large language model (LLM) agents on complex, long-horizon tasks. We instantiate this using a generator-selector framework with two LLMs; at each turn, a generator model generates $N$ candidate actions and a selector model selects one of them, which is then executed in the environment. This paper is closely related to the work of Zainullina et al. (2025) who used critic models for guided search at inference time. Different from their work, we evaluate if off-the-shelf, open-weight LLMs can be effective at comparing different candidate actions directly. Experiments on long-horizon terminal tasks show that Turn-BoN can lead to significant performance improvements, both in terms of accuracy (5–10%) and consistency across repeated attempts. Analysis of agent trajectories reveal a shift in agent behaviour towards desirable patterns such as reduction in number of attempts to solve the task, improved task instruction following, debugging and testing.


### 1 Introduction

Large language model (LLM)-based agents have recently achieved strong performance in solving complex, long-horizon tasks across different domains such as software engineering, knowledge work and scientific discovery. Unlike single-turn reasoning tasks, such as proving a theoretical result, agentic tasks require an LLM to take a sequence of actions while interacting with an external environment where the agent executes an action, observes any changes or feedback from the environment and takes the next action. Successfully solving a long-horizon task therefore requires the agent to make good decisions throughout the trajectory. However, LLM agents can often be inconsistent. They can successfully complete the task during some attempts while failing in others, partially because actions are sampled from a stochastic policy (see Figure 1 in Zainullina et al. (2025) for example).

Inference-time scaling has emerged as an effective technique to improve performance without altering model parameters, by using additional compute during task execution. Among the most prominent ideas is trajectory-level best-of-N sampling, where multiple complete agent trajectories are generated in parallel and scored using an outcome reward model (ORM) or an LLM judge, and the best one is selected. Recent work by Kwok et al. (2026) evaluates this idea for agentic tasks, showing gains on software engineering benchmarks such as Terminal-Bench v2.1 ( Merrill et al., 2026 ) and SWE-Bench-Verified ( Jimenez et al., 2024 ) , using an LLM-as-a-judge to score completed trajectories against evaluation rubrics. A limitation of this approach, however, is that selection happens only after the trajectories are completed, and therefore cannot change the distribution of the intermediate actions within each attempt. Other commonly used inference time search methods, such as depth-first search (DFS) ( Yao et al., 2023 ) and Monte Carlo tree search (MCTS) ( Kocsis and Szepesvári, 2006 ) , explore alternative actions from intermediate states. However, applying these methods to interactive agents requires checkpointing and restoring earlier environment states, which can be impractical in many settings Zainullina et al. (2025) .

We study a simple modification of trajectory level best-of-N sampling, which we call turn-level best-of-N sampling (Turn-BoN), where additional computation is used to generate $N$ candidate actions at each turn, one of them is selected for execution in the environment. Concretely, we use a generator-selector framework with two LLMs: a generator model proposes candidate actions, and a selector model chooses among them. Intuitively, we think of Turn-BoN as implementing (a sampled version of) one-step policy improvement at inference time, where we can improve over the rollout policy by selecting actions from a sampled set of candidates. We elaborate more about this connection in Sections 2.2 and 2.3 .

Note that in out setup, the action selection is done before environment execution, i.e. only the selected action is executed in the environment without requiring sandbox execution for the remaining candidates. On the other hand, trajectory level BoN generates $N$ independent trajectories in parallel which scales the number of environment executions and sandbox infrastructure by a factor of $N$ . Moreover, trajectory level BoN might have limited practical use beyond offline evaluation on benchmark tasks — for agents working on user machines (for example, agents working in a terminal, or computer use agents), it is not clear how $N$ sandboxes can be obtained for parallel generation since the user’s machine is the sandbox. Even sequentially generating up to $N$ agent trajectories and scoring these seems impractical.

The idea of selecting actions from a set of sampled candidate actions has also been explored in RL before. In settings with large or continuous action spaces where enumerating all possible actions to find the best one is infeasible, existing methods ( Fujimoto et al., 2019 ; Ghasemipour et al., 2021 ; Hubert et al., 2021 ; Gupta et al., 2023 ) sample a smaller set of candidate actions and use estimated action values or planning to select among them. More recently, Zainullina et al. (2025) applied the idea of value-guided action selection to LLM agents. The main motivation of this paper is to answer the following questions:

- Can we use an off-the-shelf LLM as a generative critic to perform per-turn action selection at inference time for agentic tasks? Does this improve task success, and how does it change the behaviour of agents over complete trajectories?

An advantage of using an off-the-shelf LLM for action selection is that we avoid the need to train a separate action-value critic. We summarize the main contributions and findings of our work below:

- 1. We study turn-level best-of-N (Turn-BoN) action selection for LLM agents using an off-the-shelf LLM to select among candidate actions before environment execution, without needing to train a separate critic model.

- 2. We empirically evaluate the performance and computational trade-offs of this approach across different generator models, selector models, and sampling widths. Results show improvements in pass rates (both pass@1 and pass@k) as well as consistency across repeated attempts.

- 3. We analyze how Turn-BoN sampling changes the actions selected by the agent and its behavior across complete trajectories. We observe substantially fewer executed turns and reduction in undesirable behaviors related to looping, testing, and debugging, including among unsuccessful attempts.

- 4. We interpret this method as a form of approximate sampled one-step policy improvement at inference time, and derive conditions based on the expected advantage of selected actions, under which the induced policy improves upon the generator policy.

We remark that Turn-BoN incurs substantial additional inference-time compute because it generates multiple candidate actions and invokes an LLM selector, at every turn (Section 3 ). Developing computationally efficient approximations that retain performance gains of Turn-BoN remains an open question. We discuss this in Section 5 .

We were studying Turn-BoN independently when we came across the work of Kang et al. (2026) , which investigates essentially the same idea of per-turn action selection, primarily using smaller generator models (of size 4B–9B) with both self-verification and GPT-5.6-Sol (a closed-source flagship frontier model) as the selector model. We decided to release our results and analysis so far, and communicated with the authors of Kang et al. (2026) . This work can be seen as concurrent, independent evaluation of the idea of action selection through guided search at larger model scales (Qwen3.6-35B at medium scale and K2-Horizon-375B at large scale), using open-weight models (such as Kimi-K3 and Deepseek-v4.1-Flash) as selector models and a different agentic harness (mini-SWE-agent).

Beyond an independent and detailed empirical investigation, our work also focusses on how per-turn action selection changes agent behaviour. For example, we analyze the categories of actions preferred by the selector model as well as evaluate trajectories over behaviour rubrics, finding significant improvements in agent behaviour related to testing, debugging, task instruction following and reduction in looping over failed commands. This is important to build an understanding of how Turn-BoN differs from other inference time approaches like trajectory level BoN (which does not change the agent behaviour) as well as in attributing gains across different metrics under turn-BoN sampling. Finally, we connect the idea of per-turn action selection to one step policy improvement at inference time, and give theoretical grounding to this approach.


### 2 Turn Level best-of-N using Generator-Selector Framework

We introduce the following notation from classic reinforcement learning (RL) which will help understand the main motivation behind this method. Consider a modified Markov decision process (MDP) $\mathcal{M}:=\left(\mathcal{S},\mathcal{A},\mathcal{O},\mathcal{P},\mathcal{R},\gamma\right)$ , 1 1 We formulate an MDP over the agent’s complete interaction history rather than the underlying environment state, which may be only partially observable. where $\mathcal{S},\mathcal{A},\mathcal{O}$ are the set of states, actions and observations, $\mathcal{P},\mathcal{R}$ are the transition and reward functions respectively and $\gamma\in[0,1)$ is the discount factor. Let $\pi$ be a stochastic policy such that $\pi(a|s)$ denotes the probability of taking action $a\in\mathcal{A}$ in state $s\in\mathcal{S}$ and let $\mu$ denote the initial-state distribution, $\mu(s):=\Pr(s_{0}{=}s)$ .

In the context of large language models (LLMs) and agentic tasks, we can define the agent state to be a concatenation of the system instruction, task statement, and past observations and actions, $s_{t}=(s_{0},a_{0},o_{0},\ldots,a_{t-1},o_{t-1})$ , where $s_{0}$ denotes the system instruction and task description provided at the start of the interaction, and $o_{t}\in\mathcal{O}$ denotes the environment feedback the agent observes by taking action $a_{t}$ in state $s_{t}$ . The environment interactions are episodic, i.e., interaction ends when the agent reaches a terminal state $s_{T}$ — for example, when the agents uses a “submit” tool to indicate task completion, or runs out due to context limit or timeouts. The transition function $\mathcal{P}$ can be assumed to be deterministic, 2 2 We assume there are no sources of randomness in environment execution and feedback. There can be settings, for example, with background processes running concurrently or race conditions when making edits to the same file, where this assumption may not hold. as after executing action $a_{t}$ and recieving observation $o_{t}$ , the agent state is updated as $s_{t+1}=\text{Concat}(s_{t},a_{t},o_{t})$ . For many RL tasks, it is common for the rewards to be sparse, i.e., $r_{t}=0\,\,\forall\,\,t<T$ , and binary reward (usually either 0 or 1) is provided at the end of the trajectory by running a verifier that evaluates the correctness of the final state.

We state some standard definitions in RL literature and use these throughout the paper ( Sutton et al., 1998 ) . Consider a policy $\pi$ . The value function, $V^{\pi}(s):=\mathbb{E}_{\pi}\left[\sum_{i=0}^{\infty}\gamma^{i}r_{t+i}|s_{t}{=}s\right]$ , denotes the expected discounted sum of rewards from state $s$ under policy $\pi$ . Similarly, the state action value function (or the critic function), $Q^{\pi}(s,a):=\mathbb{E}_{\pi}\left[\sum_{i=0}^{\infty}\gamma^{i}r_{t+i}|s_{t}{=}s,a_{t}{=}a\right]$ , denotes the expected discounted sum of rewards from state-action pair $(s,a)$ . The advantage function of policy $\pi$ is defined as the difference of the two: $A^{\pi}(s,a)=Q^{\pi}(s,a)-V^{\pi}(s)$ and denotes the expected gain in return when taking action $a$ in state $s$ .


#### 2.1 Value guided search with lookaheads

This study is inspired by the works of Wang et al. (2026a) and Zainullina et al. (2025) , both of which investigated the idea of using critic models (state action value functions) at test time to guide LLM generation, and evaluated such approaches on mathematical reasoning and software engineering tasks. The idea is simple: let $Q^{\pi}(s,a)$ be a critic function 3 3 Assuming binary rewards and $\gamma=1$ , the critic function predicts the probability of solving the task correctly when taking action $a$ in agent state $s$ . corresponding to rollout policy $\pi$ . Then, instead of just sampling actions from the policy $\pi$ , the critic model can be used to guide LLM generation at each step using lookaheads.

Formally, ( Zainullina et al., 2025 ; Wang et al., 2026a ) use sampled version of the policy improvement (PI) operator ( Sutton et al., 1998 ) for 1-step lookahead,

[Tableau] $$\hat{\pi}(s)=\mathrm{PI}(Q^{\pi})(s)=\argmax_{a^{\prime}\in\mathcal{A}}\,\,Q^{\pi}(s,a^{\prime})$$ (1)

Recall that from classical RL theory, it is well known that the greedy policy $\hat{\pi}$ defined in Equation 1 is strictly better than the base policy $\pi$ .

[ Sutton et al. (1998) ] Let $\hat{\pi}$ be a greedy policy as defined in Equation 1 . Then,

[Tableau] $$V^{\hat{\pi}}(s)\geq V^{\pi}(s),\quad\forall s\in\mathcal{S}.$$

We provide a short proof in Appendix 8 for reference. Note that the policy improvement operator is defined with respect to $Q^{\pi}$ , the critic model corresponding to policy $\pi$ . Indeed, past works of Wang et al. (2026a) and Zainullina et al. (2025) use a critic model trained with rollouts from the LLM policy $\pi$ to do guided search at inference time.


#### 2.2 Method: Guided search with generator-selector framework

Instead of using a value model to score candidates, we propose to use an off-the-shelf LLM to directly select among the sampled candidate actions. This approach can be seen an alternative implementation of the sampled policy improvement operator—using a generative critic to reason about different proposed actions and select the best one to make progress. Since the selection is performed at every step, we call it turn-level best-of-N sampling (Turn-BoN). Figure 1 below illustrates this idea and Algorithm 1 provides the pseudocode.

Note that unlike Kang et al. (2026) , we only experiment with the listwise scoring approach, i.e., the selector model is given all candidate actions as a list and asked to reason and return index of the best candidate to make progress to solve the task, we provide details of the prompts used in Appendix 7 . Pointwise scoring with off-the-shelf models as LLM-as-a-judge (uncalibrated for selection) tend to require scoring based on multiple criteria’s, averaged over more than one LLM-as-a-judge call ( Kwok et al., 2026 ) . Pairwise scoring approaches such as those described in Kwok et al. (2026) and Singh et al. (2026) involve having a tournament between different pairs. Although approximations can be made to limit computational cost to be $\mathcal{O}(N\cdot k)$ for some constant $k$ , we found it to be prohibitive in small scale experiments.


#### 2.3 Policy Improvement property of Turn-BoN

Recall that the main goal of this work is to investigate if off-the-shelf LLMs can act as a good critic for action selection at inference time. In this section, we provide a theoretical result which quantifies the policy improvement property of the policy induced by Turn-BoN sampling in terms of the quality of only the selected actions. For this, it is instructive to look at the proof of Proposition 1 in Appendix 8 . The greedy policy $\hat{\pi}$ in Equation 1 is defined with respect to the critic model $Q^{\pi}(\cdot)$ , corresponding to the base policy $\pi$ . Intuitively, the improvement property should still hold for any policy that selects “better” actions that the base policy. Formally, if for some policy $\pi^{\prime}$ , it holds that $\mathbb{E}_{a\sim\pi^{\prime}(\cdot\mid s)}\left[Q^{\pi}(s,a)\right]\geq\mathbb{E}_{a\sim\pi(\cdot\mid s)}\left[Q^{\pi}(s,a)\right]$ , then it should hold that $V^{\pi^{\prime}}(s)\geq V^{\pi}(s)\,\,\forall\,\,s\in\mathcal{S}$ , using the same arguments as in the proof of Proposition 1 . In Proposition 2 below, we present a somewhat weaker condition for policy improvement.

Let $\pi_{N}$ be the policy induced by Turn-BoN sampling, defined to be the (distribution over) actions selected from a candidate list of actions,

[Tableau] $\displaystyle\pi_{N}(a\mid s)=\mathbb{E}_{\mathcal{A}^{\pi}_{C}(s)}\left[\mathrm{Select}_{\phi}(a\mid s,\mathcal{A}^{\pi}_{C}(s))\right]$ (2)

where $\mathcal{A}^{\pi}_{C}(s)=(a_{1},\ldots,a_{N})$ is the list of $N$ candidate actions in state $s$ sampled i.i.d from the generator policy $\pi$ , i.e., $a_{i}\sim\pi(\cdot\mid s)\,\,\forall\,i\in\{1,\ldots,N\}$ , and $\mathrm{Select}_{\phi}(a\mid s,\mathcal{A}^{\pi}_{C}(s))$ denotes the probability that the selector model, parametrized by $\phi$ , selects 4 4 Note that the selector itself may be stochastic, and its choice may depend on the entire candidate list. action $a$ from the candidate list $\mathcal{A}^{\pi}_{C}(s)$ , sampled in state $s$ . Hence, Equation 2 defines the probability of selecting action $a$ under a two-stage process: first sampling $N$ candidate actions from $\pi$ , and then selecting one of them using the selector model. The expectation averages over the randomly sampled candidate lists.

We state the following result. A more detailed version along with the proof can be found in Appendix 8.1 .

Consider a discounted MDP with bounded rewards and $\gamma\in[0,1)$ . Let $\mu$ denote the initial-state distribution, and define $J_{\mu}(\pi):=\mathbb{E}_{s_{0}\sim\mu}[V^{\pi}(s_{0})]$ . Let $d_{\mu}^{\pi_{N}}(s)$ denote the normalized discounted state-visitation distribution of the Turn-BoN policy, $\pi_{N}$ , defined as $d_{\mu}^{\pi_{N}}(s)=(1-\gamma)\sum_{t=0}^{\infty}\gamma^{t}\Pr(s_{t}=s;\mu,\pi_{N})$ .

Then, $J_{\mu}(\pi_{N})\geq J_{\mu}(\pi)$ if

[Tableau] $$\mathbb{E}_{s\sim d_{\mu}^{\pi_{N}},\,a\sim\pi_{N}(\cdot\mid s)}\left[A^{\pi}(s,a)\right]\geq 0,$$ (3)

where $A^{\pi}(\cdot)$ is the advantage function under policy $\pi$ .

We remark on a few noteworthy points about Proposition 2 below:

Using the definition of $\pi_{N}(\cdot|s)$ and the advantage function $A^{\pi}(\cdot)$ , the condition for policy improvement under Turn-BoN as shown in Equation 8 can equivalently be written as

[Tableau] $$J_{\mu}(\pi_{N})\geq J_{\mu}(\pi)\quad\text{if}\quad\mathbb{E}_{s\sim d_{\mu}^{\pi_{N}}}\Big[\mathbb{E}_{a\sim\pi_{N}(\cdot\mid s)}\left[Q^{\pi}(s,a)\right]-V^{\pi}(s)\Big]\geq 0.$$

Note that this is a weaker condition that requiring $\mathbb{E}_{a\sim\pi_{N}(\cdot\mid s)}\left[Q^{\pi}(s,a)\right]\geq V^{\pi}(s)$ to hold for all states $s\in\mathcal{S}$ , as needed in the proof of Proposition 1 . Instead, we only need $\mathbb{E}_{a\sim\pi_{N}(\cdot\mid s)}\left[Q^{\pi}(s,a)\right]\geq V^{\pi}(s)$ to hold on average under states sampled from the steady state distribution of $\pi_{N}$ .

There can be alternate ways of formulating $\pi_{N}$ . One such way is to define is as a greedy policy with respect to a scoring function 5 5 This would correspond to the case where the selector model is used to score each candidate action and the highest scoring one is picked for being executed in the environment. $f(s,a):\mathcal{S}\times\mathcal{A}\to\mathbb{R}$ , such that $\pi_{N}(a\mid s)=\mathbb{E}_{\mathcal{A}^{\pi}_{C}(s)}\left[\argmax_{a\in\mathcal{A}^{\pi}_{C}(s)}f(s,a)\right]$ . The result in Proposition 2 applies to this setting as well.


### 3 Experiments

We present results from some preliminary experiments below. For the analysis, we focus on how Turn-BoN framework can change the generation quality in addition to improving accuracy metrics like pass rates. As mentioned above, we think of this as more of a thought experiment rather than a practical approach, primarily due to the additional compute required — we evaluate compute in terms of additional generator tokens as well as additional selector tokens incurred rather than wall clock time which tend to depend more on infrastructure optimizations implemented for sandboxing (for e.g. concurrency) or, for inference engines (e.g., cache aware routing), etc.

We evaluate Turn-BoN sampling on Terminal-Bench v2.1 tasks ( Merrill et al., 2026 ) with the mini-SWE-agent harness SWE-agent Team (2025) , experimenting with Qwen3.6-35B ( Qwen Team, 2026 ) and K2-Horizon-375B model ( IFM Team, 2026 ) as generator models, and Kimi-K3 ( Kimi Team, 2026 ) and Deepseek-v4.1-Flash (released in September, 2026) ( DeepSeek-AI, 2026 ) as selector models. Note that the average pass@1 for Qwen3.6-35B and K2-Horizon-375B models on Terminal-Bench v2.1 is around 47% and 73% respectively, while the average pass@1 for Kimi-K3 and Deepseek-v4.1-Flash is around 88% and 82% respectively, so our setup tests for the case where the selector model is more capable that the generator model. Our choice of the generator models allows us to evaluate how the gains with Turn-BoN sampling scale with model size and capability of the generator model.

For our experiments, we try two values of $N\in\{4,8\}$ — we found the results with $N=2$ to be very similar to the baseline (which corresponds to $N=1$ ). We use temperature $\tau=1.0$ and nucleus top- $p=0.95$ for generating $N$ candidate actions. As mentioned before, unlike Kang et al. (2026) we only experiment with listwise selection and leave thorough experimentation with pointwise and pairwise scoring approaches as future work. We use Deepseek-v4.1-Flash with “high” reasoning mode and Kimi-K3 with the default “max” reasoning mode. We prompt the selector model to select between candidate actions based which one is likely to make genuine progress toward completing the task, see Appendix 7 for the prompt we use.

### 4 How Turn-Level Selection Shapes Agent Behaviour

Results in Section 3 show improvements in pass@1, pass@k and consistency when using Turn-BoN sampling on Terminal-Bench v2.1 tasks, with larger gains in the setting when the gap between generator and selector model is large. These metrics alone, however, do not reveal which actions the selector model picks and how those choices shape the agent’s behaviour over a task trajectory. To dive deeper into how Turn-BoN sampling drives gains and improves agent behaviour, we analyze the rollouts along two different axis: (1) in Section 4.1 , we quantify what category of actions the selector model picks at each turn and trace how these picks change trajectory outcomes. (2) In Section 4.2 , we analyze generated trajectories against behavioural rubrics using an LLM judge. Taken together, these analysis show how BoN sampling changes distribution of actions and improves quality of the rollouts, even on trajectories where the agent was unable to solve the task correctly. As a sanity check, we verify that the accuracy gains do not come from cheating/hacking behaviour in Appendix 12 .


#### 4.1 What Actions Does the Selector Model Pick, and Why Does It Help?

> Figure 4 : Preference of selector models across eight behaviours on Terminal-Bench 2.1 — refer to Appendix 9 for the definition of each behaviour. Within each panel, x-axis groups by the generator model and number of candidates $N\in\{4,8\}$ . Solid lines ( ): denote the percentage of turns where the selector’s pick shows a particular behaviour. Dashed lines ( ): shows the expected percentage of turns with a behaviour under random selection from $N$ candidates. The gap between the two measures preference of the selector model for a behaviour. The gap for all behaviours is statistically significant by paired bootstrap over tasks (10,000 resamples, $p<0.01$ in every setting), except “ loops on a command ” behaviour with K2-Horizon-375B as the generator model.

We begin by analyzing all trajectories generated by Turn-BoN sampling as well as by the baseline method (no selector model) in terms of different action types and how the distribution over these actions types changes under Turn-BoN sampling as compared to the baseline. Recall that at every turn, the selector model chooses among one of $N$ proposed actions, where each action is a tool call with shell commands. For every turn in a trajectory, we extract the shell commands and classify each one by pattern matching on its program name and arguments into action types such as editing a file , running a test , installing a package , or reading without changing anything . Using these labels, together with the context of the tool call (i.e., prefix before it), we classify each tool call with one or more of eight behaviours, see Table 4 in Appendix 9 for details. We compare the distribution of each behaviour as exhibited by the actions that the selector model picks with a baseline that draws uniformly from $N$ candidates. The gap between the two isolates selector model’s preference over generator model’s action distribution.

As can be seen in Figure 4 , the selector model picks actions which make the agent do real work such as “ edit a file ”, “ test its last edit ” and “ runs a test or check ” much more than uniform selection. At the same time, commands which make the agent “ only read or inspect ” a file reduce considerably. The selector model also reduces rare bad behaviour from the generator model, such as malformed or empty tool calls or “ doom loops ”, from getting executed — thereby improving the consistency of the agent.

It is noteworthy that actions picked by the selector model also have a larger total character count across all shell commands in the response (see bottom row in Figure 5 ) — showing a preference for “combined action” where multiple commands are chained through. Moreover, with K2-Horizon-375B as the generator model, the selector models pick actions that are associated with more reasoning tokens as compared to the baseline; although with Qwen3.6-35B, the gap between reasoning tokens for the selected action and reasoning tokens for the baseline action is not statistically significant. Refer to the top row in Figure 5 .

#### 4.2 Does Turn-Level BoN Improve Trajectory Quality?

The analysis in Section 4.1 only shows a change in behaviour at turn level when using a selector model to choose actions among a candidate list. In this section, we aim to understand a shift in trajectory level behaviour — these can be understood to be at a more abstract level and are often associated with better generalization ability of the agent on out of distribution tasks. A trajectory where the agent is able to complete the task correctly might still have bad behaviours such as insufficient testing or improper use of tools and vice-a-versa, there can be instances where the agent was unable to complete the task correctly but made progress by understanding task requirements, sufficiently testing the changes, and not being stuck in loops.

To do a behaviour analysis at trajectory level, we use an LLM judge to annotate a trajectory against some behavioural rubrics. We use 13 bad behaviours that Wang et al. (2026b) identified from real-world agent traces for software engineering tasks (for example, repeating a failed action , skipping tests , ignoring instructions ) and added 15 additional bad behaviours which further check on how the agent diagnoses errors, tests its work, covers the requirements, handles state, and reports results (for example, retrying without diagnosing the error , writing tests that cannot fail ). Refer to Appendix 11 for more details.

We select a set of 36 tasks where the baseline run with K2-horizon-375B model fails to correctly solve a task in atleast one of its four attempts. We use the same set of tasks for analysis of runs with Qwen3.6-35B as the generator model to make the results comparable. For each generator model, we randomly select one trajectory from the baseline and one trajectory from each of the Turn-BoN configuration, obtaining a total of 360 trajectories to analyze.

We use DeepSeek-V4.1-Flash-1017 ( Xu et al., 2026 ) as the LLM judge. We reuse the prompt of Wang et al. (2026b) for judging all 28 behaviours, see Appendix 11.1 for the detailed prompt. For analysis, the LLM judge is only shown the task and the full trajectory — it is not given any information about correctness of the trajectory. For each behaviour, the LLM judge flags if the trajectory exhibits it — so it is possible for a trajectory to be flagged for multiple behaviours. We run the judge twice on each trajectory and report the average of the two annotations. For each behaviour, we report the share of trajectories the LLM judge flags for it, so lower is better. As a sanity check on the LLM judge annotations, we observe that a trajectory scored as correct by the verifier has fewer flagged behaviours on average than a incorrect trajectory, as expected.

As can be clearly seen, looping drops sharply (by 14% - 18%), consistent with the finding in Section 4.1 that the selector models does not pick candidate actions that rerun a failed command. Another consistent change is the reduction in actions where the agent retries an actions without diagnosing the failure. Some other behaviour improvements are more specific to the generator model — for K2-Horizon, the agent under BoN sampling improves on following task instructions, debugging and tool use. For Qwen3.6, the behaviour additionally improves on how the agent validates its work along with different aspects of testing such as not “writing tests that cannot fail”, testing for task requirements etc. For the baseline run with Qwen3.6, the agent checks what it built rather than what the task asks for, which matches its high share of incorrect submissions (44.9%, Table 2 ). Under BoN sampling, the selector rates each candidate action against the task requirements at every turn.

Even though the LLM judge is not given correctness of a trajectory as input, a correct trajectory may seem better to the LLM judge simply because it ends in the agent claiming to have solved the task. To avoid this bias, we compare all failure trajectories in baseline and Turn-BoN runs against the same 28 behaviour rubrics as described above. Failure trajectories under Turn-BoN sampling show fewer bad behaviours as compared to the baseline. For K2-Horizon, a failure BoN trajectory shows 2.7 (out of 28) bad behaviours on average, against 3.9 for the baseline run. Similarly, for Qwen3.6, a failure BoN trajectory on average shows 6.8 (out of 28) bad behaviours against 8.9 for a failed baseline trajectory. For K2-Horizon, the failure baseline trajectories often get stuck — for example, a third of these rerun a failed command (33%), against 10% of failing BoN attempts. Similarly, failure BoN attempts also ignore the task instructions less often (28% to 15%). For Qwen3.6, the change is mainly in how the agent checks its work — failing BoN attempts show reduced retries without diagnosis (50% to 26%) and less reliance on tests that cannot fail (65% to 47%).

Therefore, there is no bias in our analysis due to correctness of a trajectory. The improvement in agent behaviour carries over to failed (incorrect) trajectories as well — a failed attempt under Turn-BoN sampling is more often one where the agent works through the task properly and tests its solution but still submits a wrong answer, rather than one that stalls due to a bad behaviour — so it exposes fundamental gaps in agent’s ability to solve the task rather than the agent getting stuck due to a bad behavioural pattern. The analysis in Section 4 is complementary to the results presented in Section 3 ; metrics such as pass rates and consistency are based on correctness scores and obscure the change in agent behaviour which applies to all trajectories, including those where the agent was unable to solve the task correctly.


### 5 Conclusion and Future Work

In this work, we present some preliminary results on Turn-BoN sampling and show various advantages of guided search using an LLM-as-a-judge. Pass rates (both pass@1 and pass@k) improve significantly and the agent becomes more consistent in solving the tasks. Qualitatively, we also observe a radical change in agent behaviour. For example, the number of turns taken by the agent to solve a task reduces by almost half as the selector model rejects unproductive actions from the candidate list — guided search helps the model make more progress each turn. Other bad behaviours such as, looping over failed commands, ignoring task instructions, insufficient debugging and testing, also reduce substantially in all trajectories. Trajectory analysis in Section 4 highlights a fundamental advantage of the Turn-BoN framework — action selection from a candidate list gives an opportunity for the agent to follow good actions consistently throughout the trajectory, akin to the one step policy improvement operator which we used as motivation for this work (Section 2.2 ).

Even though our results validate the utility of Turn-BoN sampling using an off the shelf model as LLM-as-a-judge, this approach is computationally very expensive. In the concurrent work of Kang et al. (2026) , the authors also present results where a small model is trained (using supervised fine-tuning) on traces 9 9 It seems that the traces included reasoning tokens , scores and preference labels. We are not sure how they were able to access reasoning tokes of a closed source frontier model like GPT. obtained from GPT-5.6-Sol for pairwise verification and selection on some task set. They experiment with this small distilled model as the selector model and show accuracy gains. While training a small model to be good at scoring different candidate actions or at pairwise selection might improve compute costs, it is not clear how well such an approach generalizes.

We think an interesting open direction to explore is to do Turn-BoN sampling only at a few turns rather than at all turns. This can potentially reduce compute costs associated with both candidate generation and action selection. In addition, we believe that many of the benefits of the Turn-BoN approach we showed in our work might also apply to guided search using a trained critic ( Zainullina et al., 2025 ) , perhaps by co-training a critic model during post-training. As critic models are trained discriminatively to output numerical scores, using them for action selection can make Turn-BoN approach compute efficient — studying the work of Zainullina et al. (2025) at scale might be useful.

### 6 Related Work

We review some closely related works below. Recall that we study turn level best-of-N sampling for long-horizon agents, where a separate, off-the-shelf language model (selector model) is used to select among candidate actions generated by a base model (generator model), without explicitly learning an action-value function or simulating the downstream consequences of each action.

Inference-time scaling with repeated sampling. Scaling inference-time computation offers an effective alternative to improving language model performance without altering the model parameters: multiple candidate responses can be sampled from a fixed generator and later aggregated or ranked using a verifier. Repeated sampling can substantially increase the probability of generating at least one correct response ( Brown et al., 2024 ) , while the appropriate use of additional inference time compute depends on task difficulty and the form of verifier feedback available ( Snell et al., 2024 ) . Beirami et al. (2025) provides an analytical characterization of the win-rate and KL divergence of the induced best-of-N policy against the reference policy under ideal reward-based selection. In practice, however, the availability of a correct sample does not guarantee its selection. Imperfect reward models can be exploited ( Gao et al., 2023 ) , and recent work characterizes both coverage-dependent limits and failure modes of increasing the sampling budget ( Huang et al., 2025 ; Stroebl et al., 2026 ) . Hence, generation coverage and selection quality are an important consideration rather than simply treating a larger sample pool as an unconditional improvement.

Inference-time scaling for long horizon agents. For interactive agents, inference-time scaling must account for trajectories that alter an external environment. Existing line of works allocates additional compute across complete agent runs, CodeMonkeys ( Ehrlich et al., 2025 ) generates and tests multiple candidate software-repair trajectories before selecting a final edit, whereas SWE-Gym ( Pan et al., 2025 ) trains verifiers to re-rank complete software-agent trajectories. SWE-Replay ( Ding and Zhang, 2026 ) reduces repeated computation by branching from informative steps in prior attempts, although this requires the ability to rollback steps (which can be difficult in non-serializable environments), while Kim et al. (2026) represent completed trajectories compactly for parallel selection and sequential refinement. These approaches exploit information from full attempts but may require multiple environment executions. In contrast, action-level selection (this work) expends compute before committing to the next environment transition.

Per-turn action selection. Several recent methods allocate sampling and verification at intermediate decision points. Zainullina et al. (2025) investigate one-step lookahead guided by a learned action-value function in software-engineering environments where restoring earlier states is costly. Zhu et al. (2025) directly compare step step-wise best-of-N with trajectory based and other test-time-scaling strategies for language agents. Analogous mechanism appears for GUI agents: V-droid ( Dai et al., 2026 ) uses trained pairwise action verification, and GTA1 ( Yang et al., 2025 ) samples and judges candidate action proposals before visual grounding. For web agents, CATTS ( Lee et al., 2026b ) allocates sampling budget dynamically according to action-level uncertainty. Concurrent work on terminal agents is closely related: Mid-Harness ( Kang et al., 2026 ) samples candidate terminal actions at the model-harness boundary, investigates verification mechanism and distillation, and evaluates combinations of trajectory level scaling. LLM-as-a-Verifier likewise investigates general-purpose verification for agent tasks, including per-step agent verification ( Kwok et al., 2026 ) .

Process reward models and selection reliability. Process reward models are used as a tool to assess intermediate reasoning or actions, they have been extensively studied for mathematical reasoning ( Lightman et al., 2024 ) , where progress can be formalized through changes in the probability of eventual success ( Setlur et al., 2024 ) . Extending these ideas to agents, Web-Shepherd ( Chae et al., 2025 ) learns step-level preference signals for web-navigation, AgentPRM ( Xi et al., 2026 ) empahizies on both, future promise and realized progress, PRInTS ( Lee et al., 2026a ) combines multidimensional process evaluation with long-context summarization, and WebArbiter ( Zhang et al., 2026 ) trains a reasoning-based verifier for web-action selection. SWE-TRACE ( Han et al., 2026 ) incorporates rubric-guided process evaluation into both software-agent training and inference-time pruning. These approaches encompass methods trained for specialized evaluator in contrast to general purpose LLM judges. Importantly, the performance of a judge on aggregate scoring metrics need not imply that it can reliably rank candidates originating from the same state ( Landesberg, 2026 ) ; moreover, off-the-shelf verification is not always sufficient, as observed in embodied action selection ( Singhi et al., 2026 ) . This makes the quality and behavioural traits of the selector an important aspect to be taken into consideration.

Lookahead and sampled policy improvement. Per-turn action selection is closely related to policy improvement via one-step lookahead and rollout in classifical reinforcement learning. Early work studied improving a base policy by evaluating candidate actions through Monte Carlo simulations of their long-term returns ( Tesauro and Galperin, 1996 ; Bertsekas and Castañón, 1999 ) . More recent methods have investigated policy improvement over sampled action subsets when exhaustive action maximization is impractical. Batch-constrained Q-Learning ( Fujimoto et al., 2019 ) samples actions from a learned behavior distribution and selects among them using a learned Q-function, while EMaQ ( Ghasemipour et al., 2021 ) studies the expected maximum Q-value over a fixed number of sampled actions and characterizes the effects of sample count and proposal distribution. Sampled MuZero ( Hubert et al., 2021 ) and Gumbel MuZero ( Danihelka et al., 2022 ) further investigate policy improvement over restricted action sets within model-based planning. Unlike these approaches, our method uses a separate, general-purpose language model to select among candidate actions without explicitly learning an action-value function or simulation their downstream consequences.

##### 8.1.1 Conditions for policy improvement under Turn-BoN

Let $g^{\pi}_{N}(s)$ be the expected sampling gain under an oracle selector at state $s$ , defined with respect to the critic function $Q^{\pi}(\cdot)$ as,

[Tableau] $\displaystyle g^{\pi}_{N}(s)=\mathbb{E}_{\mathcal{A}^{\pi}_{C}(s)}\left[\max_{a\in\mathcal{A}^{\pi}_{C}(s)}Q^{\pi}(s,a)\right]-V^{\pi}(s),$ (6)

where the expectation is taken with respect to the candidate list sampled under policy $\pi$ . Define the expected selection error as,

[Tableau] $\displaystyle\epsilon^{\pi}_{N}(s)=\mathbb{E}_{\mathcal{A}^{\pi}_{C}(s),\,a\sim\pi_{N}(\cdot|s)}\left[\left(\max_{a^{\prime}\in\mathcal{A}^{\pi}_{C}(s)}Q^{\pi}(s,a^{\prime})\right)-Q^{\pi}(s,a)\right].$ (7)

Here, $g^{\pi}_{N}(s)$ measures the expected gain under one-step policy improvement at state $s$ and a sample of the candidate list $\mathcal{A}^{\pi}_{C}(s)$ , i.e., it measures the benefit of sampling multiple candidate actions and acting greedily for a single step. Similarly, $\epsilon^{\pi}_{N}(s)$ can be understood as the selection error or the gap in one step policy improvement at state $s$ and candidate list $\mathcal{A}^{\pi}_{C}(s)$ due to an “imperfect selector”, which does not necessarily choose the best action from the candidate list. By construction, both quantities are non-negative, i.e., $g_{N}\succeq 0,\,\,\epsilon_{N}\succeq 0$ .

Proposition 3 below shows that the selector model need not identify the best action perfectly. Policy improvement is guaranteed as long as the expected selection error is smaller than the expected gain possible from sampling multiple actions under an oracle selector. Equivalently, policy improvement is guaranteed if the expected advantage of policy $\pi_{N}$ relative to policy $\pi$ is non-negative. Importantly, this result does not assume that the selector explicitly estimates $Q^{\pi}$ or assigns numerical scores to candidate actions.

A natural concern with Turn-BoN sampling is that a selector model which picks actions based on apparent progress could favour shortcuts that make the verifier pass without actually solving the task, for example editing the tests or reading the reference solution. We also observe that the selector model picks installs a package more often than uniform selection (Figure 4 ), which raises the question of whether some of the gains come from answers retrieved from outside the environment. In this section, we check whether the pass rate gains come from such shortcuts.

We judge all 2,300 passing attempts in Table 7 , since failed attempts earn no reward. We follow the reward hacking setup of Artificial Analysis 12 12 https://artificialanalysis.ai/methodology/coding-agents-benchmarking (AA setup), which extends the reward hacking check of Harbor’s analyze command 13 13 https://github.com/harbor-framework/harbor . Harbor counts edits to the tests, writes to the reward file, and copies from the reference solution as reward hacking. AA additionally counts answers fetched from outside the environment, such as the benchmark’s public solutions. Note that normal network use, such as installing packages or reading documentation, does not count as reward hacking. We use DeepSeek-V4.1-Flash-1017 as the judge and run it as an agent with the Codex CLI. The judge works in a separate sandbox that holds the task files (including the tests and the reference solution), the full trajectory, and the verifier output, and it can search these files and run shell commands before giving its verdict. This is useful since trajectories are long and a shortcut is often a single command among many turns. See Appendix 12.1 for the judge prompt.

As can be seen from Table 7 , the judge labels only 17 of the 2,300 passing attempts as reward hacking, with at most three in any setting. Baseline attempts are flagged at a similar rate (0.9%) to BoN attempts (0.7%). The number of cases does not grow with $N$ (9 at $N{=}4$ and 4 at $N{=}8$ ), and is similar for the two selector models (7 with Kimi-K3 and 6 with Deepseek-v4.1-Flash). No BoN setting differs significantly from its baseline ( $p>0.2$ in every setting).

Most flagged cases (13 of 17) exploit the environment or the verifier rather than fetching answers from outside. On fix-code-vulnerability , the agent restores the fixed file from git with git checkout (three cases). On custom-memory-heap-crash , the agent exits early with _exit(0) or _Exit(0) to skip the crashing destructors, which the verifier’s memory check does not catch (three cases). On path-tracing , the agent disassembles a compiled reference renderer left in the sandbox to recover the exact scene (two cases). Only four cases fetch answers from outside the environment. On fix-ocaml-gc , the agent downloads the upstream OCaml source and copies its one-line fix (three cases, two of them at baseline), and the fourth case is on mteb-retrieve , described below.

On mteb-retrieve , the shortcut is chosen by the selector model. At turn 21, the selector model picks a candidate that tries to reach the benchmark’s GitHub repository, reasoning that the task’s source code likely defines the expected answer. In the following turns, it keeps picking candidates that download the repository and read the reference solution. This suggests that when a task is ambiguous, a selector model that rates actions by progress alone can favour such shortcuts, although we see the benchmark’s own solution retrieved only once in the 1,870 passing attempts under BoN.
