## What Does the Model See? Representation Validity in Multimodal LLM-Based Video Analysis

Multimodal large language models (MLLMs) allow social scientists to analyze video at scale, but researchers must decide which parts of a video to provide as input. We use the term representation validity to examine how text, audio, video, and combined inputs affect measurement and subsequent analysis. We compare input representations across six open-weight MLLMs and three human-annotated video datasets. No representation consistently performs best. On seven news-related constructs, native-video performance varies little across models (macro-F1 = .70–.77), while extracted-text performance ranges from .52 to .80. Three models perform better with text and three with video; combining inputs rarely improves performance. Higher classification accuracy also does not reliably produce estimates closer to those based on human codes. The highest-F1 representation best reproduces human-coded regression coefficients in 17 of 42 comparisons. Even when each model uses its highest-F1 deployable representation, 45% of sample-prevalence estimates differ from the human-coded benchmark by more than ten percentage points. Input representation therefore requires validation for both the construct being measured and the quantity estimated from the resulting labels.


#### 1 Introduction

Before a large language model can code a video, researchers must decide how to present it. They can supply a speech transcript, add optical character recognition (OCR) of on-screen text, sample frames and attach audio, use the model’s video pathway, upload the original file, or ask the model to describe the clip and then code that description. These choices determine which information the model can use to measure the construct of interest.

So far, input representation has received less attention than model and prompt selection. LLM annotation is now common in computational social science. Zero-shot models can match crowd workers and, on some tasks, trained experts ( Gilardi et al., 2023 ; Törnberg, 2023 ; Heseltine and Clemm von Hohenberg, 2024 ) . They work across languages and constructs ( Rathje et al., 2024 ) , and open-weight models allow researchers to run versioned annotation pipelines locally ( Alizadeh et al., 2025 ) . Their labels support claims about political communication, engagement, and elite behavior ( Marks et al., 2025 ; Solovev et al., 2026 ; Törnberg and Chueri, 2025 ) . Validation studies to date have focused on which models, prompts, and decoding settings produce agreement with human coders ( Ziems et al., 2024 ; Abraham et al., 2025 ) . For text annotation, the input often closely resembles the document researchers want to classify. Video requires additional decisions about which channels to retain and how to encode them.

A thirty-second TikTok news video may convey meaning through speech, on-screen headlines, footage, editing, music, or delivery. A transcript retains the words but discards the picture and most properties of delivery. OCR recovers written content but not music or visual context. A sparse frame sample may capture the setting while missing a brief end card. A model’s native video pathway can preserve temporal structure, although frame sampling and audio alignment vary by architecture. The value of each input depends on whether it preserves information relevant to the construct.

Let $X$ denote the original video, $R$ the procedure used to represent it, and $X_{R}=R(X)$ the model input. A model $f_{\theta}$ produces

[Tableau] $$\hat{Y}=f_{\theta}\big(R(X)\big).$$ (1)

Varying $R$ while holding the model and prompt constant isolates the effect of representation on measurement. Researchers using the same model and codebook can obtain different variables from the same videos if they supply different inputs.

We use representation validity to describe this part of the measurement process within established approaches to construct validity. We examine whether the representation retains the information a construct requires, whether the model uses that information, whether it combines complementary signals, and whether the resulting variable preserves the quantity researchers want to estimate.

We examine these questions using six open-weight audio-visual LLMs and three datasets with human reference labels. We use 603 German-language TikTok news videos with codes for news values, platform features, and audiovisual properties ( Mayer et al., 2025 ) ; 400 English-language videos with codes for hate and for whether they target Black or Jewish people ( Das et al., 2023 ) ; and 650 English sitcom clips with sarcasm labels ( Castro et al., 2019 ) . We give each model the same codebook instructions while varying the input representation. Across the datasets, we compare nine input routes: metadata only, an automatic transcript, extracted speech and on-screen text, a human transcript where available, sampled frames with audio, native video, full video, combined text and video, and a model-written description. We remove audio to test whether models use sound, and we compare errors across routes to test whether models combine complementary text and video signals. We then re-estimate engagement regressions and sample prevalences to assess how coding accuracy relates to downstream estimates. Finally, we repeat runs to check computational stability.

On the seven verbally defined news constructs, native-video macro-F1 ranges from .70 to .77 across models, compared with .52 to .80 for extracted text. Three models perform better with extracted text and three with native video. The wider comparison also shows that representation effects vary by model and construct. Comparing constructs on the same videos helps separate these effects from differences between datasets: audiovisual input improves coding of visual setup more consistently than coding of verbal news constructs, and its advantage differs between the two HateMM target-group variables.

The audio ablations show that models use sound differently across tasks. Removing audio can substantially reduce performance on hate or sarcasm while barely affecting another task. Both Gemma models can transcribe English speech with an appropriate prompt, yet rarely identify music. Text and audiovisual routes also make complementary errors, but providing both in one call usually yields little improvement over the better individual route.

Higher macro-F1 does not reliably identify the representation that best recovers a downstream estimate. In the news application, the highest-F1 route produces the smallest regression-coefficient error in 17 of 42 model–construct comparisons. Across all three datasets, 45% of sample-prevalence estimates remain more than ten percentage points from the human-coded reference even after selecting the highest-F1 deployable route. These results support validating model–representation combinations for the intended construct and for the estimates calculated from their labels.


#### 2 Related work


##### 2.1 LLM annotation in computational social science

Automated content analysis is a measurement problem: an instrument should agree with a trusted reference and support valid substantive inference ( Grimmer and Stewart, 2013 ; Song et al., 2020 ; Baden et al., 2022 ) . Generative LLMs have made this work less costly. Zero-shot annotation with ChatGPT outperformed crowd workers on several political-text tasks ( Gilardi et al., 2023 ) , matched or exceeded experts on political tweets ( Törnberg, 2023 ) , and approached expert coders across political-science annotation tasks ( Heseltine and Clemm von Hohenberg, 2024 ) . Similar results hold for sentiment, discrete emotions, and offensiveness across twelve languages ( Rathje et al., 2024 ) , although performance varies across computational social science tasks and constructs ( Ziems et al., 2024 ) .

Subsequent work has examined how to produce and validate these annotations. Open-weight models permit local processing and reproduction from archived weights, but researchers must report model settings and fine-tuning choices that affect performance ( Alizadeh et al., 2025 ; Ollion et al., 2024 ) . Small changes in prompt wording can also shift accuracy ( Abraham et al., 2025 ) . Validation must extend beyond classification: even accurate labels can bias downstream regressions, and methods such as design-based supervised learning use human-coded subsamples to correct that bias ( TeBlunthuis et al., 2024 ; Egami et al., 2023 ) . Operational choices affect costs as well; annotating multiple items and variables per call can reduce costs with little loss of accuracy ( Pipal et al., 2026 ) .

Substantive studies increasingly use LLM-generated codes as measures. GPT-4o codes of ingroup solidarity and outgroup hostility in Facebook posts show how engagement shifted after the political crises of the 2024 US campaign ( Marks et al., 2025 ) ; LLM measures of incivility and character attacks link hostile campaign rhetoric to electoral outcomes ( Banks and Stone, 2026 ) ; LLM-coded tweets of parliamentarians in 26 countries trace a rise in elite incivility ( Törnberg and Chueri, 2025 ) ; and language-model estimates track outgroup animosity among politicians, journalists, and partisan users over a decade ( Fulay and Roy, 2026 ) . Similar designs measure framing in news articles ( Tohidi et al., 2025 ) and mobilization in protest communication ( Eckardt et al., 2025 ) . Increasingly, the material is audiovisual. A study of 25,292 TikTok videos by German politicians uses GPT-4-turbo to code automatic video transcripts for outgroup animosity, identity language, and relatability ( Solovev et al., 2026 ) . Multimodal models now also code who appears in candidates’ Instagram stories ( Achmann-Denkler et al., 2026 ) . These studies depend on the representation supplied to the model, although they rarely compare alternative representations.

Model and prompt selection thus have established roles in annotation validation. For multimodal data, researchers must also decide how to represent the material before the model processes it.


##### 2.2 From text annotation to multimodal social data

Research that codes audiovisual political material has historically combined speech recognition for what is said, computer vision for faces, objects, and settings, and human coding or supervised classifiers on top ( Joo and Steinert-Threlkeld, 2022 ; Boussalis et al., 2021 ) . A validation of automated coding for campaign advertisements shows that such component pipelines reach human-level reliability for many but not all variables ( Tarr et al., 2023 ) . Which channel carries a construct matters. When human coders rate parliamentary speeches from transcripts and from video, the valence of a speech carries over to the transcript, whereas its emotional arousal does not ( Cochrane et al., 2022 ) .

Multimodal LLMs can process several channels in one call, but their performance varies across settings. Open and proprietary multimodal models approach human reliability when rating emotional arousal in laboratory recordings but fall well short on real parliamentary debates ( Licht, 2026 ) . Benchmarks for video LLMs show that models can answer many items without the visual channel and that accuracy does not necessarily reflect use of that channel ( Lee, 2026 ) . Video LLMs also read on-screen text poorly ( Shi et al., 2025 ) , which matters for platforms on which much of a video’s verbal content appears as overlaid text. Converting video into text first can sometimes improve performance. For example, describing clips and reasoning over the descriptions outperforms end-to-end video models on long-video question answering ( Zhang et al., 2024 ) .

This work shows that constructs rely on different channels, models vary in their ability to extract them, and intermediate text representations can perform well. It leaves open how alternative representations compare when researchers hold the videos, social-science constructs, model, and prompt constant.


##### 2.3 Representation as a measurement decision

Equation ( 1 ) distinguishes the original object $X$ , its representation $X_{R}$ , and the model $f_{\theta}$ . Holding the model, prompt, and decoding settings constant allows us to compare representations using four checks.

Representation sufficiency concerns $R$ . A representation is sufficient for a construct if it retains the information that the construct definition requires. A transcript cannot be sufficient for music detection, and sixteen sampled frames may miss a brief on-screen prompt. Researchers can assess sufficiency from each construct’s codebook definition before running a model (Table 2 ).

Representation utilization concerns $f_{\theta}$ given $X_{R}$ . A model may receive information it does not use. We test this by removing a channel from an otherwise identical input and checking whether the model’s codes change.

Representation integration concerns $f_{\theta}$ given several representations at once. When two representations make different errors, a model that receives both could in principle do better than either. Whether it does is an empirical question.

Inferential validity concerns estimates calculated from $\hat{Y}$ . Automated labels can agree closely with human codes yet yield different regression coefficients, because the effect of a coding error depends on where it occurs in the data ( TeBlunthuis et al., 2024 ) .

We use these four checks to define our research questions. RQ1 asks how much annotation validity changes when we present the same videos through different representations. RQ2 asks whether representation effects depend on the information requirements of the target construct. RQ3 asks whether multimodal models use the modalities we provide and whether they can integrate complementary signals. RQ4 asks whether representation-induced measurement differences alter downstream substantive conclusions.


#### 3 Data and research design

In our experiments, we hold the model, codebook prompt, decoding settings, and evaluation target constant while varying how we represent each item (Figure 1 ). In addition, we provide the same item metadata with every route.

##### 3.1 Validation datasets

We use three datasets with human reference labels (Table 1 ). They differ in language, domain, and the channels relevant to their constructs.

We use News on TikTok as our primary dataset. It contains videos that German-language news outlets in Germany, Austria, and Switzerland posted on TikTok in 2023. Trained coders annotated the videos using a published codebook ( Mayer et al., 2025 ) . We draw a class-quota sample of 603 test videos from the 7,978 videos that the published release classifies as news. We sample until each class of four verbally defined constructs (geographic scope, negative news, conflict, and scope) contains about 200 videos. Within each class, we weight candidates by their country’s share of the corpus and count each selected video toward every class it matches. We exclude 132 development videos that we drew earlier using the same procedure and used only for format checks. The test draw yields 612 videos, but we could not download nine of them and did not replace them (Appendix 6 ).

This procedure over-represents minority classes of the four quota constructs. For example, the human coders identify conflict in 33% of test videos, compared with 14% of the corpus. The other constructs remain close to their corpus shares. We use the sample to evaluate classification and to compare automated and human-coded sample prevalences; we do not estimate prevalence in the corpus or on the platform. Professional news videos often repeat information across voice-over, on-screen headlines, and footage, making them a useful setting for testing how much video adds beyond extracted text.

We use 400 videos from HateMM , a dataset of BitChute videos with human hate-speech annotations ( Das et al., 2023 ) : 200 hateful and 200 non-hateful videos. We include hateful videos only if the annotated hateful segment starts within the first 120 seconds, so that every route includes material from the relevant segment. These user-generated videos can convey hate through speech, symbols, imagery, or a combination of channels. The original annotators also recorded which community each video targets or concerns, for hateful and non-hateful videos alike. We analyze two of these target-group labels as separate constructs: whether a video targets Black people (207 of 400 videos) and whether it targets Jewish people (47 of 400). Comparing three constructs on the same videos lets us test whether representation effects differ by construct while holding the material constant.

We use 650 clips from MUStARD , a dataset of English-language sitcom utterances with audio and human sarcasm labels ( Castro et al., 2019 ) . We reserve 40 of the original 690 clips for development (20 per class), leaving 650 test clips, of which 325 are sarcastic. We include the preceding dialogue that the dataset provides as context. Sarcasm may depend on delivery as well as on words and context. We also use MUStARD’s human transcripts to distinguish automatic speech-recognition errors from differences between representations.

##### 3.2 Constructs and their information requirements

We use the coding definitions to classify channels as required, potentially informative, or unnecessary for each construct (Table 2 ). This table is a descriptive classification assembled during interpretation of the results; it is not an independently validated measure of channel requirements. We then check whether representation effects match those information requirements.

The seven news constructs that we call verbally defined are those whose definitions refer to what a story is about or to prompts that can be spoken or written. We include geographic scope, negative news, conflict, scope, two kinds of calls to interact, and other people’s voice. We select these constructs because they occur often enough in the sample and their definitions refer mainly to verbal content. We examine purely visual and auditory constructs separately. Two of the seven verbally defined constructs also involve nonverbal information. A call to interact on TikTok can be “purely visual or via an animation,” and whether “the voice of people other than the journalist” is heard depends on who speaks, which a transcript does not record. The two audiovisual anchors , visual set-up and music, require visual or auditory evidence and serve as manipulation checks: providing the relevant channel should improve performance.

##### 3.3 Models

We use six open-weight LLMs that accept both images and audio and return text. They are Gemma 4 12B and Gemma 4 E4B ( Google DeepMind, 2026 ) , Qwen3-Omni 30B-A3B ( Xu et al., 2025b ) , Qwen2.5-Omni 7B ( Xu et al., 2025a ) , Nemotron-3 Nano Omni 30B-A3B ( NVIDIA, 2026 ) , and MiniCPM-o 4.5 ( Yao et al., 2024 ) . The set includes dense and mixture-of-experts architectures with different approaches to audio processing. We require audio input so that every model can receive speech audio in the frames + audio route. We exclude models without audio input (for example Gemma 4 26B and 31B) because they cannot run that route as defined. We list exact checkpoints and revisions in Appendix 7 .

We use the six models to assess whether representation effects recur across architectures, sizes, and developers. Our focus is on these effects and their variation across models, rather than on a model ranking.

We run all models on one NVIDIA A100 (80 GB) with vLLM 0.30 ( Kwon et al., 2023 ) , using bfloat16 precision and greedy decoding. We disable reasoning (“thinking”) modes and use a JSON-schema grammar to restrict outputs to each construct’s legal codes. Completed coding calls return parseable, in-scale answers; this does not prevent input-processing failures. We code the nine news constructs together and the two HateMM target variables together. Hate and sarcasm each use a separate single-construct call. We disable prefix caching and the multimodal preprocessing cache, except that the capped full-video runs use the preprocessing cache (Appendix 7 ).


##### 3.4 Representation routes

We compare the nine routes in Table 3 , using each model to code every item through every route that its dataset supports. We provide at most the first 120 seconds of each video, except in the full-video route, where we supply the original file. We also provide the same metadata across routes: outlet and nationality, caption, and hashtags for news; show, speaker, and preceding dialogue as a human transcript for sarcasm. HateMM provides no metadata. We use the same prompt across routes within each corpus, changing only one sentence to describe the input material (Appendix 18 ). The news and hate prompts use definitions from the source coding guidelines; for sarcasm and the HateMM target variables, we supply operational definitions consistent with the source annotations. We fix each prompt before running its corresponding comparison and retain it across models and routes. The original news, hate, and sarcasm prompts were frozen before the first test-set calls; the target-group prompts and additional video routes were introduced later. We use the development sets for format and input-processing checks, not accuracy tuning.

##### 3.5 Evaluation

We evaluate each construct against the human reference labels using macro-F1, the unweighted mean of F1 across the codebook’s categories. We exclude missing or unclear ( $-99$ ) human labels separately for each construct. Among the remaining items, we count missing or invalid model outputs as incorrect, including failures caused by inputs that exceed a model’s limits. To summarize a group of constructs, we average their macro-F1 scores rather than pooling their items. We also report nominal Krippendorff’s $\alpha$ against the human labels ( Hayes and Krippendorff, 2007 ) .

We report macro-F1 for every route, construct, and model, with 95% confidence intervals from an item bootstrap (1,000 resamples). We compare routes within each model and construct, using the same items. For each model and construct we identify the observed best route and compare every other route with it through the paired bootstrap distribution of the difference in macro-F1. Using a margin of $\pm.05$ macro-F1, we call a route practically equivalent to the best if the 90% interval of the difference lies within $\pm.05$ , worse if the interval lies entirely below $-.05$ , and inconclusive otherwise. Because we select the comparator for having the highest observed score, the comparison favors it. We therefore treat this as a descriptive diagnostic rather than a confirmatory equivalence test. We also report margins of .03 and .10 as sensitivity checks.

We summarize the loss from choosing a route as its shortfall , the distance in macro-F1 between that route and the best route of the same row. We decompose the variation of construct-level macro-F1 across models, routes, and constructs into main effects and interactions; with one value per cell, this is an exact descriptive decomposition, not a test. Where we compare two specific routes, we report the paired bootstrap difference (2,000 resamples, same items for both routes) with its 95% interval. We do not test differences across the six models, which are not independent observations.

We test audio use by coding the same visual input with and without its audio track. We run this audio ablation on a random subsample of 150 news videos, where we also vary the number of frames, on all 400 HateMM videos, and on all 650 sarcasm clips. We run additional diagnostic tests for the two Gemma models because their initial news results show little response to audio. We test an audio-only route, the media placement recommended in the Gemma 4 documentation (images before the instruction, audio after it), a direct question about music, and transcription with the developer’s recommended prompt. We also repeat the tests with a second inference backend, Hugging Face transformers.

To assess integration , we classify each model’s item $\times$ construct decisions into four cases: both routes are correct, only extracted text is correct, only frames + audio is correct, or both are wrong. We then calculate an oracle score by selecting the correct label whenever either route provides it and the extracted-text label when both routes are wrong. This diagnostic uses the human reference labels to show the benefit of resolving disagreements correctly; we cannot use it to code unlabeled data.

To assess inferential validity , we re-estimate an engagement regression on the news data, replacing the human codes with each route’s codes (Section 4.5 ). For each coefficient, we examine whether pipelines with higher macro-F1 produce estimates closer to the human-code estimate. We also check whether selecting the highest-F1 route selects the route with the smallest coefficient error. For every binary construct across the three datasets, we compare automated and human-coded sample prevalences, both across all routes and after selecting each model’s highest-F1 route.

We assess reproducibility by re-running 50 news videos on six routes with identical settings.

An initial analysis plan, the original codebook prompts, and the inference code were frozen on 10 September 2026, with their SHA-256 hashes recorded locally; the plan was not deposited in a public registry. After interim results, we moved from laptop inference to the A100 and reran the study, expanded the model set, and added the native- and full-video routes and HateMM target-group comparisons. The broader grid, integration, prevalence, and downstream route-selection analyses developed during this extension. We therefore report these comparisons as descriptive and exploratory, while retaining the initial plan’s $\pm.05$ equivalence margin. Appendix 7 gives further details. We used generative AI in preparing replication material and supplementary information, as specified in the declarations.

##### 4.1 Representation sensitivity

For news, we compare representations on the same videos and constructs with constant prompts and models. On the seven verbally defined constructs, native-video macro-F1 falls in a narrow range from .70 to .77 across all six models. Extracted-text performance spans .52 to .80. The direction of the difference therefore reverses across models. Gemma 4 12B, Gemma 4 E4B, and Qwen3-Omni perform better from extracted text, whereas Qwen2.5-Omni, Nemotron, and MiniCPM-o perform better from native video. The paired native-video minus extracted-text differences range from $-.06$ to $+.18$ , with all intervals excluding zero (Appendix 9 ).

This variation also appears across the full grid. Across the 78 model–construct combinations, no route dominates (Figure 2 ). Extracted text is the observed best route in 16 combinations, native video in 15, frames + audio in 14, text + video and describe first in 10 each, full video in 7, metadata only in 4, and the transcript in 2. Relative to the observed best route, 24% of the 510 pairwise comparisons are practically equivalent within the pre-specified $\pm.05$ margin, 37% are worse by more than .05, and 38% remain inconclusive (Figure 3 a; Appendix Table 8 ). The typical shortfall is small for several routes. The median is .02 for text + video and .03–.04 for the main text and video routes. Every route nevertheless has combinations on which its shortfall is substantial. The size of the best-or-equivalent set changes with the margin; many comparisons remain inconclusive.

The variance decomposition shows that representation effects depend on the model and construct (Figure 3 b). Differences between constructs account for 51% of the observed variation in macro-F1. The route main effect accounts for 4% and the model main effect for 5%, while route $\times$ construct accounts for 10%, model $\times$ route for 5%, model $\times$ construct for 16%, and the three-way interaction for another 10%. Most variation associated with representation occurs through its interactions with the construct and model.

The ordering of routes also varies in HateMM and MUStARD. For hate, extracted text (.76 to .83) or text + video (.76 to .85) is the observed best route for four of six models, and no video route improves on extracted text by more than .02. For sarcasm, the preferred route changes sharply across models. The Gemma models do best from the transcript or text + video, Qwen3-Omni from the full clip, Qwen2.5-Omni from text + video, and Nemotron and MiniCPM-o from a model-written description. When models can process the untouched file, its pooled performance stays within .04 of native video. Providing the original file offers no consistent advantage over the reduced representations.


##### 4.2 Construct dependence

We compare constructs on the same items to hold language, genre, sample, and annotation source constant. On the 603 news videos, frames + audio improves on extracted text by .36 macro-F1 on average for visual setup, with the interval above zero in all six models. For other people’s voice, the mean gain is .12 and five of six intervals lie above zero. By contrast, the six remaining verbal constructs range from a mean difference of $-.02$ to $+.08$ , with models disagreeing in sign (Appendix 9 ). For music, the audiovisual advantage varies with the model’s use of audio. Relative to the verbal-construct mean, the additional gain for music ranges from $-.02$ to $+.45$ with frames + audio and is positive with a confidence interval above zero for five of six models under native video.

We make a second same-item comparison using HateMM. On the same 400 videos, all six models code the Black-target variable best from extracted text or text + video, while five of six code the Jewish-target variable best from a video route (Figure 2 ). Frames + audio gains more over extracted text for the Jewish-target variable than for the Black-target variable in every model; the difference is .04 to .12 in five models, with the paired interval above zero in four. Thus, the preferred representation can change with the target construct even when we hold the videos and models constant.

The wider comparison follows a similar pattern. Video performs best for visual setup in every model and for music in the four models that use its audio signal. Results for the verbal news constructs vary by model. We interpret cross-dataset contrasts cautiously because language, genre, construct, and annotation source vary together. The same-item comparisons provide clearer evidence that representation effects depend on both the information a construct requires and the model’s ability to use it.


##### 4.3 Modality utilization

We test models’ use of audio by removing it from the frames + audio route while keeping the visual input constant (Figure 4 ).

The effect of removing audio varies by task. For hate, removing the soundtrack lowers macro-F1 in every model by .10 to .21. For sarcasm, it costs Gemma 4 12B .08, Gemma 4 E4B .16, and Qwen2.5-Omni .07. Music detection drops by .17 to .46 in the four non-Gemma models. Yet on the seven verbal news constructs, removing audio changes the two Gemma models by .01 or less, while it costs Nemotron .07 and MiniCPM-o .05. These differences show why researchers need to assess audio use for each task.

Further tests distinguish speech transcription from music detection in the Gemma models (Table 4 ). Both Gemma models transcribe English speech well when we use the developer-recommended transcription instruction. Their median word error rate is .11 on the sitcom clips. The models can process speech, but this ability does not extend reliably to music detection in these tests.

##### 4.4 Multimodal integration

Extracted text and audiovisual input make complementary errors. Across every model and construct group, some decisions are correct only from extracted text and others only from frames + audio (Appendix Table 12 ). Depending on the model and dataset, 1–24% of decisions are correct only from text and 3–47% only from video. A diagnostic oracle that takes the correct answer whenever either route has it would improve on the better single route by .01 to .16 macro-F1, with a median gain of .07 (Figure 5 ). The two sets of predictions thus contain correct labels that neither route consistently recovers alone.

> Figure 5: Integration across datasets: macro-F1 of extracted text (sarcasm: transcript), frames + audio, both in one call (text + video), and an oracle that selects the correct single-route prediction whenever one is available. Providing both representations in one call rarely improves on the better individual route. Across the 36 model–group combinations, text + video ranges from .08 below to .03 above the better single route, with a median difference of $-.003$ ; it exceeds the better route by .02 or more in only 14% of cells. Its performance often closely follows one of the component routes. On the news constructs it tracks the video route even for the three models whose extracted-text route is better. Gemma 4 12B, for example, scores .80 from extracted text, .75 from frames + audio, and .75 from both. For the Black-target variable in HateMM, the combined route tracks the text route in five of six models. The combined-input results fall short of the gains suggested by the complementary predictions.

##### 4.6 Robustness and reproducibility

Four of the six models could process the untouched original files across all three datasets (Nemotron failed on 4.5% of HateMM videos, mostly because the audio exceeded a size or duration limit). For both Qwen models, most news and HateMM files crashed the vision encoder (Qwen3-Omni) or exceeded the context window (Qwen2.5-Omni, 32k tokens). Capping the visual input at 32 frames did not produce a usable fallback: Qwen2.5-Omni processed 12 of 20 attempted news videos and 147 of 400 HateMM videos; Qwen3-Omni processed none of the 20 news videos and only one HateMM video. The news pilots do not establish completion rates for all 603 videos (Appendix Table 10 ). Uploading the original file is therefore infeasible for some models and datasets. Where full video ran, it performed like native video (within .04 pooled).

The standardized frames + audio input and the model’s own video pathway give the same pooled result on the news constructs (differences within $\pm.012$ ), although individual constructs can move by up to $\pm.15$ ; frames at 896 instead of 448 pixels change pooled macro-F1 by at most .02 (Appendix 10 ).

The agreement results give a less favorable assessment than the macro-F1 values, which reach .94. In Krippendorff’s $\alpha$ , only 12% of the 252 results from six models, six routes (metadata only, transcript, extracted text, frames + audio, text + video, describe first), and seven news constructs reach .667, and only for one construct does the best route reach the agreement of the two trained coders in the published pretest. When we treat the six models as six coders, their agreement ranges from $\alpha=.27$ to .70 (Appendix 14 ).

We re-run 50 news videos on six routes with identical settings on the same GPU. Models reproduce 97.3% to 99.8% of individual codes and all nine codes for 81% to 98% of item–route pairs (Appendix 15 ). Batched GPU inference is not fully deterministic. The least stable here were the two mixture-of-experts models (97.3% and 97.9%), with one dense model close behind (98.3%); six models do not support a conclusion about architectures, and no route was consistently less stable than the others.

Coding from extracted text required 0.09 to 0.26 A100 GPU-seconds per news video, frames + audio 0.36 to 1.11 seconds (Appendix 16 ). At the University of Zurich computing rate of CHF 0.081 per A100-hour, coding 1,000 news videos therefore costs CHF 0.002 to 0.006 from extracted text and CHF 0.008 to 0.025 from frames + audio. At on-demand prices of commercial cloud providers, US$3.43 (Amazon Web Services) to US$3.67 (Microsoft Azure) per A100-hour ( Amazon Web Services, 2026 ; Microsoft Azure, 2026 ) , the same jobs cost US$0.09 to 0.27 and US$0.34 to 1.13. For these inference runs, the absolute cost differences between representations are small.


#### 5 Discussion

Our study shows that input representation belongs in the specification of a video annotation instrument. Transcripts, sampled frames with audio, native video, and original files expose different information to the model. Switching between them can change the resulting variables while the model, prompt, decoding settings, and source videos remain fixed.

For the seven verbal news constructs, native-video performance is similar across models (.70–.77 macro-F1), while extracted-text performance ranges from .52 to .80 and changes their ordering. Across the full comparison, the main effect of representation is small relative to its interactions with model and construct. A representation that works well in one model–construct combination may perform poorly in another. Reporting the model name and prompt is therefore insufficient for reproducing a multimodal measure. Researchers should also document speech and OCR extraction, frame counts and resolution, audio alignment, truncation, and media placement within the prompt. Each affects the evidence the model receives.

Our findings do not establish a general preference for text or video. Extracted text can outperform audiovisual input on verbal news constructs, whereas visual setup requires pictures. On the same HateMM videos, audiovisual input has different advantages for the Black-target and Jewish-target variables. The codebook helps identify relevant channels, but performance also depends on whether the model uses them. Full video adds a feasibility constraint. Where models can process the original file, performance is close to that of the controlled video routes. Two models, however, fail to process most original news and HateMM files, and the capped trials do not establish a reliable fallback. Researchers need to test whether their model can process a candidate representation reliably before scaling up annotation.

An audio-capable model may use sound for one task and largely ignore it for another. The ablations show large effects for hate, smaller effects for some sarcasm models, and little effect for several models on verbal news content. Both Gemma models transcribe English speech with the recommended prompt but rarely detect music. Changing media placement mainly affects the audio-only task, and the music failure recurs with a second inference backend. These findings support testing modality use for the specific construct and input configuration. Integration also requires a separate check. The oracle gains a median .07 macro-F1 by selecting correct predictions from the two routes using the reference labels. The combined-input route exceeds the better component by at least .02 in only 14% of model–group combinations. Receiving several modalities therefore does not establish that a model combines their useful signals.

The downstream analyses show why annotation validation should include the intended estimate. Automated codes substantially attenuate the negative-news and conflict coefficients, and higher macro-F1 does not consistently correspond to smaller coefficient error. Among the three main routes, selecting the highest-F1 route also selects the closest coefficient estimate in 17 of 42 model–construct comparisons. The prevalence analysis yields a similar result. Even after selecting the highest-F1 deployable route for each model and construct, 45% of estimates differ from the human-coded sample prevalence by more than ten percentage points. This is consistent with prior work on misclassification bias ( TeBlunthuis et al., 2024 ) : the effect of coding errors depends on their distribution across the data. F1 and agreement statistics remain useful assessments of a classifier, but neither alone establishes whether its labels support the intended estimate. A human-coded subset can support both forms of validation. Researchers can use it to compare representations before scaling up and to assess or correct error in downstream estimates ( Egami et al., 2023 ) . Similar checks may be useful beyond video wherever preprocessing changes the evidence available to a computational measure.

Based on our findings, we recommend five checks for multimodal LLM annotation.

- 1. Validate more than one plausible representation. Use a human-coded subset to compare model–representation combinations that researchers could reasonably deploy, and use a substantively defined equivalence margin rather than treating non-significance as interchangeability.

- 2. Match the candidate representations to the construct, then test utilization. The codebook indicates which channels could matter; a simple modality ablation shows whether the model actually uses them on the task.

- 3. Do not assume that additional modalities are integrated. Compare a combined route with its components. Check whether the combined input improves on the better component when the individual routes make different errors.

- 4. Validate the downstream quantity when automated labels feed substantive inference. Classification accuracy and estimand recovery need not select the same pipeline. Where possible, use the human-coded subset to quantify or correct the resulting measurement error.

- 5. Archive the representation as part of the instrument. Record extraction tools, frame and audio handling, prompt placement, model checkpoints, outputs, and a re-run check. The representation and the realized model outputs are part of what must be reproducible.

These checks should include model-specific input conventions and processing limits. For the inference runs measured here, GPU cost differences are small enough to give priority to validation among feasible routes.

The evidence comes from three datasets and six open-weight models that fit on one A100 GPU. The primary application is German news, while HateMM and MUStARD are English; larger proprietary systems or future checkpoints may use modalities differently. The regression test is available only for the news data, although the prevalence analysis spans all three datasets. “Native video” is also not one perfectly standardized representation because each architecture implements its video pathway differently, and Qwen3-Omni required audio to be supplied separately. The main frame-based routes see at most the first 120 seconds and sixteen frames; more frames add little here, but faster-cut or much longer material may behave differently.

The validation samples also set boundaries on the claims. The news sample deliberately over-represents minority classes of four quota constructs, while HateMM and MUStARD are balanced samples. The prevalence analysis therefore concerns recovery of the human-coded prevalence in those samples, not population prevalence. Human labels are references rather than error-free ground truth. The news release is single-coded outside its published reliability pretest, and the hate and sarcasm datasets report imperfect inter-annotator agreement. Finally, comparisons across datasets confound the construct with language, genre, and annotation; we therefore treat the same-item contrasts as the strongest evidence for construct dependence.

Overall, across six open-weight models and three datasets, the choice of input representation changes video annotation quality, with effects that depend on the model and construct. Audio availability does not ensure that a model uses sound for the task, and combined text and video inputs rarely improve on the better individual route. Higher annotation accuracy does not reliably yield regression coefficients or sample prevalences closer to the human-coded estimates. Researchers using multimodal LLMs should validate the representation alongside the model and prompt, and assess the estimates they intend to derive from the labels.

#### 6 News sample

We draw the news test sample from the published release (version 2.0.0; 8,623 coded videos, of which the original coders classify 7,978 as news), using a class-quota sampler with seed 42. We target 200 videos per class of geographic scope (three classes), negative news, conflict, and scope. For each variable, we exclude videos with unclear codes from its sampling pools. At each step, the sampler selects the class furthest below its target, draws a candidate with probability proportional to its country’s share of the news corpus, and counts that video toward every matching class still below target. We exclude 132 development videos that we drew earlier with the same sampler and smaller targets.

The sampler selects 612 test videos. We could not download nine because of age restrictions, blocked access, or failed writes, and we did not replace them, leaving 603. We reproduce the 612 selected videos exactly when we re-run the sampler with the archived settings. Because each video counts toward every matching class, the quotas over-represent minority classes rather than producing exact balance (Table 6 ). The sample’s country mix (Switzerland 58%, Austria 34%, Germany 8%) also differs from the news corpus (47%, 38%, 16%). We use 599 videos in the regression analysis, excluding three without view counts and one with an unclear human code for geographic scope.

##### Inference and preprocessing

We use greedy decoding (temperature 0) for coding calls, with at most 120 output tokens and a JSON-schema grammar that lists each construct’s legal integer codes. We disable reasoning modes through the chat template. For description calls in the describe-first route, we use greedy decoding with at most 450 tokens. We process requests in batches of 256 and disable prefix caching. We also disable the multimodal preprocessing cache except for capped full-video runs. We run Nemotron-3 Nano Omni with one image tile per frame.

We divide audio longer than 30 seconds into consecutive 30-second clips (at most four), matching the per-clip limit of the Gemma 4 audio encoder ( Google DeepMind, 2026 ) . We transcribe speech with Whisper large-v3-turbo ( Radford et al., 2023 ) and automatic language detection. We extract on-screen text with Apple’s Vision framework at one frame per second and remove near-duplicate lines. In the text prompts, we retain at most 6,000 characters of the automatic transcript, 3,000 characters of OCR text, and 6,000 characters of a generated description. For frames + audio, we sample the midpoints of sixteen equal segments of the first 120 seconds and scale the images to 448 pixels on the longest side.

For native video, we prepare a file containing the first 120 seconds at the same resolution and let each model’s video loader sample sixteen frames. We supply audio as separate clips to Gemma 4, Qwen3-Omni, and MiniCPM-o; a vLLM error prevents Qwen3-Omni from using time-aligned audio. For Qwen2.5-Omni and Nemotron, we supply audio aligned with the video. For full video, we pass the original file and use each model’s default sampling. We provide its audio as separate clips from the first 120 seconds for Gemma 4, Qwen3-Omni, and MiniCPM-o, and as time-aligned audio for Qwen2.5-Omni and Nemotron. We count processing failures as incorrect and omit full-video cells where failures exceed 5%. All retained full-video cells use the original file. For capped runs, we use the same file, limit the video loader to 32 frames, and supply audio clips from the first 120 seconds. Capped-news tests cover 20 videos per Qwen model; capped HateMM tests cover all 400 videos for every model (Table 10 ).

In the Gemma diagnostic tests, we add an audio-only route, follow the recommended media placement (frames before the instruction, audio after it), ask directly about music, and test transcription with the developer’s prompt. We also repeat the tests with the Hugging Face transformers version installed in the vLLM image. We summarize the runtime configuration in Table 7 . We did not log the PyTorch and transformers versions separately; we used the versions shipped with the public image vllm/vllm-openai:v0.30.0 .
